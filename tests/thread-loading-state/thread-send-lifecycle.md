# 会话发送的账号与停止生命周期

## 前提

使用隔离测试运行时及合成会话，保留标准测试卷；不要操作生产状态。通过测试代理或领域API fixture延迟resume、thread/start、投递确认、历史读取与问题详情。账号切换测试使用前端生命周期fixture；正常账号切换仍遵循服务端空闲门禁，不绕过门禁。明亮和深色主题各执行一轮。

## 操作与预期

1. 在已有会话发送，挂起resume，然后停止/重启订阅或切换测试账号，再释放旧resume。不得继续启动旧回合、改写当前模型或供应方。
2. 在投递已开始后停止/重启，分别释放旧成功、失败与steer的onPrepared/onResult。不得追加旧显示消息、改写投递显示ID、清当前回合、覆盖当前错误或新增3000ms延迟同步；已经持久接受的请求仍按原协议完成。
3. 挂起新会话创建，在新生命周期再次发送。新发送可进入创建；旧创建返回不选中旧会话、不发送旧首条消息，旧finally不清新busy。对模型不支持的fallback重复此检查。
4. 新会话已创建、首条投递挂起时切换生命周期，释放旧成功/失败。不得请求旧标题或导航；当前失败仍保留createdThreadId和输入草稿，空threadId结果释放busy。
5. 挂起问题详情或历史回合读取，再停止/重启并释放旧成功/失败。不得合并旧详情或继续发送回答；当前问题确认仍按原ordinal与去重规则工作。
6. 挂起现有会话保存或队列编辑，切换账号/会话后释放。原提交回调收到未保存以结束等待；新草稿、编辑关联与错误保留。当前保存成功只确认一次。
7. 挂起首页worktree/无项目目录准备或首条发送，切换上下文后释放。旧准备不更新当前目录、不启动会话；旧成功/失败不导航、不展示旧错误。

## 投递前置等待与已保存意图

在配置/共享模型目录读取、delivery-context请求或响应JSON解析阶段挂起已有/新会话的immediate/steer发送，切换测试生命周期后再释放。预期旧步骤不能开始后续账号快照读取，不能将旧意图保存到当前账号快照或POST；已有未确认记录保持原内容。若在outbox已经保存后才切换，原请求仍使用保存的expectedContextId完成，一次确认后清记录；显示observer失败或失效不能阻止持久提交。排队mutation的已接受写序列保持原合同，本条不将其视为已完成同样的前置审计。

## 恢复等待期间切换显示会话（0.2.22 R1）

准备两个 Web 会话 A/B，分别保存 high/priority 与 low/普通速度；A 尚未在当前页面发送，使用合成 gateway 延迟 A 的 resume。点击 A 发送，等待恢复时切到 B，再释放 A 的恢复响应。核对投递仍属于 A，模型、推理强度及速度都使用点击发送时 A 的快照；B 的设置保持，且仅有一次 resume 与投递。另在等待时切测试账号或停止 owner，旧发送仍须取消。正式组合回归包含真实 send/model owner，执行 `pnpm exec vitest run src/composables/threadSendController.test.ts`。清理延迟 fixture 和合成消息，保留测试偏好；回退该修复会恢复设置串用风险。

## 清理与回滚

撤销所有延迟/错误fixture，恢复正常网络及订阅，保留已有测试数据。回滚需同时恢复desktop发送逻辑和App续接边界；回滚会重新引入已复现的迟到显示缺口。此检查不证明真实供应方成功、长期内存、真实组件十次挂载或NFS冷读取。

## dev.8 审核补充：新会话超时与重试所有权

前提：仅使用独立合成运行时/内存RPC和任务临时目录，能够延迟thread/start或worktree/create响应。明亮、深色及刷新复验须另在授权浏览器场景进行；离线脚本不能代替界面验收。

1. 从首页提交唯一首条消息，挂起thread/start，触发120秒watchdog（离线可手动推进timer）；记录complete回调、错误、发送锁和投递次数。
2. 超时后重试，再释放旧创建响应。预期保持明确的未确认/失败状态，重试不能无提示地被旧锁挡住；此前complete(false)的尚未投递工作不得在无确认时继续提交首条消息。
3. 分别不重试、超时后离开首页、超时后变更测试账号代次，再释放旧响应。核对提交与导航边界；账号测试只推进前端夹具代次，不绕过实际服务空闲门禁。
4. 在worktree已创建但响应未返回时超时，再重试。预期复用或明确处理已创建资源，不遗留两套已注册worktree；释放旧响应不得重复提交。
5. 正常新会话作对照：创建一次、首条投递一次、complete(true)、释放发送锁。
