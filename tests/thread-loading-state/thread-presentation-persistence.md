# 会话用量、终端偏好与快照恢复

前提：隔离测试 home，两个会话 a/b；可在开发 fixture 中延迟历史响应并发送完整 `thread/tokenUsage/updated`。分别检查亮色和暗色。组合回归：`pnpm exec vitest run src/composables/threadPresentationComposition.test.ts src/composables/threadPresentationState.test.ts`。

1. a 收到用量更新后刷新，确认当前上下文、剩余量与比例正确；重复同一事件不重复写 localStorage。切到 b，不显示 a 的用量。
2. 打开 a 和 b 的终端，再关闭 a，刷新后仅 b 保持打开。停止/恢复通知订阅不清终端偏好。
3. 暂时过滤 a，使它不在侧栏列表中，通过原路由读取 a；正文及会话元数据仍来自当前历史快照。延迟历史响应后停止，释放旧响应，不恢复旧快照。
4. 停止后执行显式历史读取，确认仍可恢复快照；停止时用量仅从内存清除，浏览器存储保留，重新加载页面后可恢复。
5. 在隔离浏览器配置中把两个持久化键分别设置为损坏 JSON、数组或 null，再加载页面：不会崩溃或显示非法用量/开关；结束后恢复原测试值。

清理：解除延迟/通知 fixture，恢复两个 localStorage 测试键，关闭合成会话终端。保留标准测试卷，不读取或复制生产状态。

## 消息投影与实际挂载

前提：上述隔离环境，正常会话及活动回合，准备图片/技能/文件附件和全局/会话审批请求；保留原 renderer 与消息身份协议。

1. 在同一活动回合连续引导两条相同文字，确认不同 intent ID 的消息各自保留；服务端历史回显同一身份后仅显示一条。新回合开始后序号重新计算，旧回合的已接受投递不占新序号。
2. 带图片/技能/文件发送消息，切换到另一会话再返回：乐观消息仍属于原会话，附件正确；持久历史、plan/command/file/agent live 消息与回合摘要顺序保持，投递显示在合并后处理。
3. 同时出现全局和所选会话请求，确认按收到时间排序；切换会话后只显示新会话及全局请求。加载/旧页/账号恢复提示跟随当前选择。
4. 亮暗主题各从首页进入会话再返回10次，确认正文实际挂载/卸载，监听器和定时器回到暖首页基线；组件订阅可重建，但退出后必须关闭。检查临时测试进程与连接，不以累计创建数量等同活动残留。

清理：取消合成待确认意图及审批，关闭合成附件测试会话，解除 fixture。短时堆增长需单独记录，不能用节点/监听器稳定代替长期内存验证。
