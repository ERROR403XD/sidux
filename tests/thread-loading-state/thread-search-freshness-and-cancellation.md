# 会话搜索：标题、正文、更新与取消（0.2.15）

## 前提与设置

使用独立 4173/59001 和虚构线程，打开侧栏搜索与网络记录。同一项目准备多个无关标题、一个精确标题、前缀/包含匹配和打散的多关键词匹配；另准备仅正文命中、仅命令输出命中、已改名但摘要仍保留旧标题、初始侧栏页之外的会话。保持一个不匹配的置顶会话。范围测试使用至少 120 个线程，其中一个超过 50 回合。分别使用浅色和深色主题。

自动检查：`pnpm exec vitest run src/server/threadSearch.test.ts src/threadSearchMatch.test.ts src/api/codexGateway.test.ts`。界面脚本：`node output/0215-search/ui.cjs`，使用请求拦截，不发送模型任务。

## 操作与预期

1. 打开左上角搜索，默认提示“搜索标题”、范围“标题”。输入一个精确标题，只显示匹配会话，不带出同项目其他会话。多个词用空格分隔时要求同时匹配；大小写、全角/半角和连续空格不影响结果。排序为精确标题、标题前缀、连续短语、分散关键词，同级按最近活动。保留置顶/项目分组，时间视图也遵守搜索相关度。
2. 默认标题模式不读取正文，也不匹配隐藏摘要；没有名称时，显示在侧栏的摘要本身就是标题，仍可被搜索。输入仅正文出现的标记应为 0 个结果，切换“正文”后可命中。正文覆盖用户文本和最终回复，不匹配命令、命令输出、助手过程说明；标题命中仍优先。
3. 验证较早会话尚未出现在初始侧栏页时可以搜到并打开。查询返回必要元数据，不为每个命中额外请求历史。结果列表不能改变不匹配会话的置顶状态。清空搜索恢复普通列表和原排序；收起的区段在搜索时显示匹配结果，清空后保持原折叠偏好。
4. 向虚构命中线程添加消息或模拟完成事件。当前查询自动刷新且只增加一次搜索请求；搜索不新增 WebSocket。重命名后新名生效，隐藏旧摘要不应造成旧名命中。归档后消失，取消归档或导入后重新可搜索。结束后恢复测试线程名称与归档状态。
5. 其他进程追加历史时，即使元数据时间戳未变，文件大小/纳秒修改时间改变也使正文缓存失效；没有可用文件签名时缓存最多复用 5 秒。缓存容量内未变更的正文重复查询不重读。
6. 快速输入 slow→latest、切换范围或清空查询。旧 fetch 被取消，晚到响应不能覆盖新结果。服务端等待在途最多 4 个正文读取结束后停止后续批次；多个客户端并发不叠加。搜索进行中不显示“未找到匹配线程”。
7. 搜索过程中修改正被读取的线程并让旧请求最后返回。新结果不得发布旧正文缓存；重试次数有上限，持续更新时可重试而不无限扫描。
8. 普通状态仅显示“N 个结果”，覆盖不完整时追加“部分范围”；悬停可查看覆盖说明。标题最多最近 1000 个非归档线程；正文最多最近 100 个，每个最近 50 回合、末尾 20 万字符。第 101 个会话仅正文出现的标记不代表已被覆盖，仍可命中标题。
9. 模拟一个正文读取失败与一次接口失败。前者保留可用结果并标记部分范围，悬停可见失败数量；后者显示简短失败和“重试”，不保留旧结果或显示原始长错误。点击重试恢复。重复/无效列表游标不可悄悄变成完整空结果。
10. 在 1440×900、768×1024、375×812 浅深主题检查真实搜索框、范围菜单、结果、清空和重试；控件文字清晰，手机抽屉无横向溢出。打开结果后内容路由正确，再次展开抽屉可继续搜索。

## 性能与清理

记录冷/热标题查询、冷/热正文查询、更新和取消的请求数、响应字节与耗时。标题模式的正文读取必须为 0。正文并发最多 4，缓存最多 100 项且 UTF-8 合计不超过 32 MB；标题最多 10 页。超过缓存容量后允许重新读取被逐出的正文。接口仅返回匹配 ID 与必要的轻量元数据，不返回完整历史或长摘要；搜索不发起模型任务。

截图放在 output/playwright，报告注明 URL、视口、主题、范围/取消/刷新断言和绝对路径。删除或归档虚构线程时按创建清单操作，不清空用户历史、认证或候选卷。
