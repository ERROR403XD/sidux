# 0.2.2 搜索更新、范围与取消

## 前提与设置

使用独立 4173/59001 和虚构线程，打开侧栏搜索与网络记录。准备至少 120 个线程，其中一个超过 50 turn；标题、摘要与正文放入不同唯一标记，避免无法分辨命中来源。分别使用浅色和深色主题。

自动检查：`pnpm exec vitest run src/server/threadSearch.test.ts`；UI fixture 为 `node output/0202/search-ui.cjs`；真实 HTTP 示例 `node output/0202/search-http.cjs` 只操作其指定的虚构线程。

## 操作与预期

1. 搜索正文唯一标记，立即换一个查询。首轮建立最近正文缓存，未变更线程不反复请求历史；查询大小写不影响匹配。结果顺序按最近活动线程排列。
2. 向命中线程添加新消息，再搜索新标记。新消息可命中，旧消息更新后的结果不使用旧索引。保持同一查询时收到完成通知也会刷新结果；不新增第二条 WebSocket。
3. 重命名线程，再搜索新名/旧名。新名生效；归档后结果消失，取消归档后重新可见。导入线程与存储的标题也纳入下一次查询。测试完成恢复虚构线程名称与归档状态。
4. 其他进程追加历史时，即使元数据时间戳未改变，文件大小/纳秒修改时间变更也使正文缓存失效。没有可用文件签名时，缓存最多复用 5 秒。
5. 快速输入 slow→latest，或清空查询。旧 fetch 被取消，晚到响应不能覆盖新结果；清空后恢复普通侧栏。服务端完成已经在途的最多 4 个正文读取后停止后续批次，多个客户端总并发不叠加。
6. 在搜索过程中修改被读取线程，模拟旧请求最后才返回。新结果不得发布旧正文缓存；重试次数有上限，持续变化时显示重试提示，不无限扫描。
7. 核对范围提示：标题/摘要最多最近 1000 个非归档线程；正文最多最近 100 个线程，每个最近 50 turn，最多末尾 20 万字符。范围截取和单个正文读取失败不能被描述成全量成功；完整范围可从提示的 title 查看。第 101 个线程的独有正文不应被当作完整正文覆盖，仍可命中其标题/摘要。
8. 模拟一个正文读取失败和一次查询接口失败。前者保留可用结果并显示失败数量；后者显示原因，重新输入后可恢复。无效/重复列表游标不能悄悄变成完整空结果。

## 性能与清理

分别记录冷查询、连续热查询、新消息后查询和取消查询的请求数、响应字节与耗时。正文读取并发最多 4；正文缓存最多 100 项、UTF-8 文本合计 32 MB；标题列表最多 10 页。取消不会自动重放或启动模型任务。

截图放在 output/playwright，报告注明 URL、视口、浅深主题、范围/取消/刷新断言和绝对路径。删除或归档本次虚构线程时按创建清单操作，不清空实际用户历史、认证或候选卷。
