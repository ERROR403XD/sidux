# 0.2.22：账号与刷新协调

前提：隔离测试 home 中准备账号 A/B 及两个会话。自动化仅替换 API 边界，真实 desktop 与队列、列表、历史、metadata owner 运行；手工验收使用已通过候选门禁的 59001。

1. 延迟账号 A 的队列快照读取，发起刷新，然后切换到 B；B 准备当前队列。完成 A 的读取，确认它不追加列表/历史读取。
2. 延迟列表读取，停止 desktop 后再完成旧列表；确认不追加历史请求，也不恢复已失效的视图。
3. 延迟 A 的历史读取，切换账号并让当前页产生可识别错误；完成 A 的错误响应，确认当前错误未被替换。
4. 延迟队列准备期间从会话 a 改选 b，再完成准备；确认本次刷新按当前选择读取 b。
5. 切换 provider，确认只使目录与额度缓存失效；切换账号则依次隔离各领域读取、reset 列表与完成确认、resume/catalog/quota 缓存及历史错误。
6. 分别调用等待辅助刷新与默认延迟刷新路径，确认前者等待配置/技能/额度，后者不阻塞正文加载。
7. 停止后执行明确的历史/刷新读取，确认仍可按原接口工作；停止只隔离先前读取，不机械取消已接受全局保存或队列意图。

预期：旧代次不追加IO、覆盖新状态或错误；各domain owner保持原请求缓存与生命周期，协调器不另建传输、timer或请求槽。

回滚/清理：取消延迟注入、回到原账号，停止本轮测试状态。只清理独立测试 home，不读写5900持久状态，不清空标准候选卷。
