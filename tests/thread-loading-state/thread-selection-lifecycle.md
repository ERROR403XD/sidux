# 会话选择、偏好恢复与停止生命周期

## 前置条件

- 使用独立开发环境或空闲且已更新的 59001 候选；准备两条会话 A、B。不得使用生产 5900 的认证、会话或状态。
- 打开网络面板。需要迟到场景时，对历史读取或模型配置/目录读取设置延迟；无需修改真实服务器数据。

## 操作与预期

1. 选择 A，等待历史及模型偏好恢复。正常选择返回成功，技能读取遵循既有缓存，消息、选中态和模型来源一致。
2. 延迟 A 的历史读取，切到 B；再释放旧读取。旧选择返回 `error`，不追加模型配置/目录或技能读取，不覆盖当前页面错误。历史 owner 可以保留仍有效的 A 历史缓存。
3. 延迟 A 的模型配置/目录读取，执行 A→B→A，再释放旧读取。旧选择及旧模型提交失效，当前选择保留自己的偏好。不能仅比较最终 ID 判断读取有效。
4. 分别在历史、模型等待期间切换账号或停止并重新启动订阅，再释放旧读取。旧操作不返回成功、不开始后续读取；新生命周期立即可选择会话。
5. 同时触发两次选择 A。历史仍可合并为一次读取，仅最新选择启动模型恢复；旧结果为 `error`、新结果为 `ok`。
6. 停止后调用选择命令：不改变选中 ID，也不发起历史/模型/技能 IO；显式 priming 仍可恢复同步选中投影。当前不存在的会话仍返回 `not-found` 并显示错误。
7. 为 A 设置计划模式、B 设置默认模式，切换并刷新页面。每会话模式与存储一致；首页新会话恢复默认模式，旧全局模式不继承。检查浅色/深色下实际会话内容与选择状态。

## 清理与验证范围

- 撤销延迟并恢复原账号；测试创建的会话按需删除，不清空标准测试卷。
- 自动化证明来自真实 desktop 装配与控制器测试，浏览器逐步操作需独立验收。停止仅隔离本地 continuation，不取消已开始的服务端请求。
