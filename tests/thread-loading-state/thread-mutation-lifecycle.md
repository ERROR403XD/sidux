# 重命名、归档与分叉的异步续接

## 前提

使用隔离运行时、合成账号及会话；准备source/other两条会话和可分叉的已完成回合。为rename/archive/fork、标题persist、列表/历史读取配置延迟fixture。账号切换通过前端生命周期注入，服务端正常空闲门禁保持。明亮/深色各一轮，不清标准测试卷。

## 操作与预期

1. 挂起重命名RPC，停止/重启或切换测试账号，再释放成功/失败。旧结果不写标题、不追加persist或search revision、不覆盖当前错误。标题persist已开始时切换账号，再完成等待，也不提交当前search/error；已接受的请求不撤回。
2. 挂起后台会话归档，切换生命周期再释放。当前列表不删同ID行、不追加列表/历史读取。正常归档当前会话仍立即选择相邻会话，当前后台归档仍可完成。
3. 挂起整会话/历史回合分叉，切换账号、停止/重启或进入另一会话，再释放。旧结果不插入optimistic行、不rename、不拉回选择、不发起跟进历史或路由导航。
4. 分叉后的列表、历史或rename等待期间切换生命周期/会话，再释放。未开始的后续请求不执行；App不显示旧失败/成功、不清当前错误、不收起当前侧栏。
5. App的router.push等待期间进入另一页面，再完成原router等待。原回调不重新select旧分叉、不报告成功。当前正常两种分叉仍导航并提示一次。
6. 对source发起重命名后打开other，再完成重命名。仍更新source标题，other保持选中；会话选择变化不取消同账号后台rename/archive。
7. 停止轮询后触发上述四种操作，不发送写请求。模拟空history-fork结果，不插入空ID或重命名。

## 回滚生命周期

1. 挂起文件撤销，切换账号或停止/重启后释放。已接受的文件请求不撤回，但不再发起历史rollback；当前错误不被旧文件错误覆盖。
2. 挂起历史rollback，切换生命周期并加载当前账号历史后释放。旧消息不写入当前history/live/turn状态，不追加sync，也不报告成功。
3. 挂起旧rollback文件请求，切换账号后加载当前目录与回合并发起新rollback。当前操作可以开始；旧finally结束后当前busy仍保留，直到当前自己的请求完成。
4. 正常rollback的同步等待期间切换账号，再完成旧同步。App不显示旧失败、不将旧用户文本补回新账号同ID的草稿。当前正常rollback仍只补草稿一次。
5. 当前rollback重复提交只有一次文件请求；当前文件撤销失败时不写历史，保留已有会话历史，显示当前错误并释放busy。

文件撤销和历史rollback仍是既有两个服务操作。本批隔离未开始的后续步骤及前端提交，不新增跨服务事务或自动补偿；已经接受的文件修改可能先于生命周期变化完成。

## 清理与回滚

移除延迟/失败fixture，恢复网络和轮询，只删除合成数据。回滚本修复会恢复已复现的迟到提交。这里只覆盖四种写操作、rollback及对应App续接，不是interrupt、跨服务事务、账号预备/协议边界或真实浏览器时延的证明。

## 资源边界

四种完整写操作、回滚、action lifecycle与rollback busy/token由 `threadMutationController` 持有。列表/历史/模型/标题及turn/live/sync通过窄getter/命令协作，owner不获得可写Ref或整个desktop对象；busy只读投影不复制消息。结构迁移保留正常请求/提交顺序；十次owner停止/重启不等同于真实组件十次挂载。

回滚结构迁移补测：在文件撤销等待期间选择other，再完成请求。操作仍绑定原source的文件/历史，不改变other选择，App不向other补草稿；无目录会话仍直接回滚历史，不追加文件请求。测试后恢复选择与延迟fixture；仅撤销结构迁移提交可以恢复父层所有权，保留前一批生命周期修复。
