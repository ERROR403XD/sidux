# 会话metadata的账号、停止与请求槽生命周期

## 前提

使用隔离运行时和合成会话；为额度、技能、模式、模型配置与标题读取配置延迟fixture。账号测试使用前端生命周期注入，不绕过正常服务端空闲门禁。明亮/深色主题各一轮，保留标准测试卷和真实用户数据。

## 操作与预期

1. 挂起额度/技能读取，停止并重新启动或切换测试账号，再刷新当前数据。当前请求立即开始，旧结果不提交；旧finally结束后加入当前请求仍合并，暖技能读取不增加请求。
2. 挂起全局技能读取，加载另一个目录的会话并刷新技能，再释放旧结果。当前目录单独读取，旧目录结果不覆盖当前技能。
3. 挂起模式读取或模型配置失败，切换生命周期后释放；设置当前会话为Plan。旧模式不改当前模式偏好，旧CLI错误不显示，不注册旧重试。
4. 生成标题或加载标题缓存期间停止/重启，再释放。旧生成不请求persist、不更新标题；旧缓存不影响新列表。正常当前生成和附件标题恢复仍工作。
5. 标题缓存挂起期间确认重命名，再释放缓存。已确认标题保留，其他缓存标题正常恢复；较旧并发缓存读取不覆盖较新读取。
6. 测试scheduler保留被clear的ancillary、额度或回合同步callback，停止/重启后显式触发旧callback。没有新API请求，也不清新timer槽。正常当前0ms/500ms/3000ms调度仍保留。
7. 当前额度读取挂起时收到实时额度，再释放读取响应。保留较新的实时额度；同context并发读取一次，2秒暖读取不增加请求。额度失效后再次读取一次。
8. 让技能读取失败，正常加载列表/历史并操作会话。保留已知技能，附属失败不阻塞主流程；强制技能刷新可以重试，空技能结果也遵守暖复用。

## 资源边界

`threadMetadataController` 私有持有额度、技能、模式、标题缓存、请求槽和0/500/3000ms定时器；父层通过只读投影和窄命令装配。模型偏好、其他会话写操作与通知订阅仍按各自实施批次验证。本批单测包含十次owner停止/重启，不等同于十次真实组件挂载。

## 清理与回滚

移除延迟/失败与callback注入，恢复网络及轮询；只删除合成fixture，不清标准卷。回滚会恢复已记录的迟到提交和缓存覆盖缺口。单测资源合同不替代真实UI时延、长期堆、真实组件十次挂载或NFS冷读取。
