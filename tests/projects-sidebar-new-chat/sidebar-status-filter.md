# 0.2.18：侧边栏状态筛选

## 前置条件

- 在隔离开发环境准备至少三个项目；包含活跃、带蓝点未读、最后回合额度失败、曾额度失败但后来成功，以及手动停止/普通网络失败的会话。
- 固定一个会话，折叠一个项目，记录项目顺序和展开状态。不要用生产账号制造额度耗尽；可运行 `node scripts/audit/0.2.18-sidebar-native.cjs` 验证实际 CLI 配合本地模拟响应的失败→恢复数据。

## 操作与预期

1. 项目/会话区上方仅有“活跃、未读、中断”三个标签，没有常驻说明文字。点击任一项，只有该项的边框、文字白色高亮；点击另一项切换，点击已选项取消。键盘 Tab 聚焦，空格/Enter 可操作。
2. 活跃仅显示原有运行标志对应的会话；保留所属项目。取消筛选后恢复原排序、分组与展开状态。折叠的项目不会因筛选自动展开，固定区、普通会话区和按时间排列模式均沿用原结构。
3. 未读直接使用蓝点：点击未读 A 后蓝点消失，但 A 继续显示；点击未读 B 后 A 隐藏，B 保留；切到已读 C 后 B 也隐藏。不能把未读暂留状态写回未读持久化数据。
4. 手机端选择 A 自动关闭侧栏，再打开侧栏时 A 仍保留；切到 B 再打开，A 消失。取消筛选并再次选择未读，不把已读会话重新纳入。
5. 中断只显示**最后回合**确认为额度失败/中断的会话。历史中间曾报额度错误但最终成功、已开始新回合、普通手动停止、401 或普通网络失败均不匹配。是否启用“额度恢复后继续”不影响这一条件。
6. 一项读取失败时，其他已确认结果仍可展示，失败状态提供重试；不能把未知状态当成已确认额度中断。新建但尚未发送第一条消息的会话不匹配。
7. 筛选期间固定会话可以被隐藏，但取消筛选后仍固定；不发送删减后的 pins 数据。搜索与状态条件取交集，不调整原项目顺序。
8. 验证中英文与 1440×1000、768×1024、375×812 浅深主题，标签不越界；选中项始终白字、白边框，浅色主题有深底确保可读。

## 性能与安全边界

- 全部/活跃/未读切换只做前端掩码，不增加 RPC。
- 中断按需调用 `/codex-api/sidebar-thread-status`，每批至多 100 个 ID；服务端最多 4 个真实未结束 RPC，只读取 `thread/turns/list` 的最后 1 回合，`itemsView=notLoaded`，不拉历史正文。
- 触发新回合、完成、取消、状态改变时使缓存失效；目录更新时间也参与缓存校验；迟到结果不得覆盖更新后的状态。
- 超时后保留底层 RPC 占位直到真正结束，不能因重试不断扩大实际并发。此读取不加入自动化任务准入锁，不改账号出口或额度续跑状态。

## 清理与回退

取消筛选即可恢复列表；刷新页面默认不筛选。清理本次虚构会话/浏览器上下文。原生模拟脚本自动停止自己的子进程与本地 HTTP 服务，并删除自己的临时 home，不操作生产数据。撤回代码前确认 59001 空闲；只重启独立开发服务，不重启 5900。

## 活跃标签与额度错误忽略

前提：隔离开发服务；准备最终回合因额度不足失败的会话，以及普通错误会话。

1. 中文侧栏标签显示“活跃”，英文仍为 Active。
2. 打开额度失败会话并选择“中断”；在错误下方点击“忽略”。预期按钮变为“已忽略”，会话及没有其他匹配项的项目从结果中消失，当前正文保留。
3. 刷新或重新打开页面，预期“已忽略”仍在，筛选仍排除该回合。
4. 点击“已忽略”取消标记，预期立即重新入选；另一个会话的同名回合不受影响。
5. 已忽略会话出现新一轮额度错误，预期新回合仍会入选，旧标记不屏蔽未来错误。普通错误不显示忽略控件。
6. 明暗主题、1440×1000、768×1024、375×812 检查控件不重叠、不横向溢出，键盘可操作。保存失败时不显示成功标记。
