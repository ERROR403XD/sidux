# 0.2.18 / 0.2.19：侧边栏状态筛选

## 前置条件

- 在隔离开发环境准备至少三个项目；包含活跃、带蓝点未读、最后回合额度失败、曾额度失败但后来成功，以及手动停止/普通网络失败的会话。
- 固定一个会话，折叠一个项目，记录项目顺序和展开状态。不要用生产账号制造额度耗尽；可运行 `node scripts/audit/0.2.18-sidebar-native.cjs` 验证实际 CLI 配合本地模拟响应的失败→恢复数据。

## 操作与预期

1. 项目/会话区上方仅有“活跃、未读、中断”三个标签，没有常驻说明文字。点击任一项，只有该项的边框、文字白色高亮；点击另一项切换，点击已选项取消。键盘 Tab 聚焦，空格/Enter 可操作。
2. 活跃开启时仅显示原有运行标志对应的会话；0.2.19 还暂留本次筛选开启期间结束的会话，直到查看并切走。保留所属项目。取消筛选后恢复原排序、分组与展开状态。折叠的项目不会因筛选自动展开，固定区、普通会话区和按时间排列模式均沿用原结构。
3. 未读直接使用蓝点：点击未读 A 后蓝点消失，但 A 继续显示；点击未读 B 后 A 隐藏，B 保留；切到已读 C 后 B 也隐藏。不能把未读暂留状态写回未读持久化数据。
4. 手机端选择 A 自动关闭侧栏，再打开侧栏时 A 仍保留；切到 B 再打开，A 消失。取消筛选并再次选择未读，不把已读会话重新纳入。
5. 0.2.19 中断显示存在尚未忽略问题、且当前未运行的会话，包括额度、401、网络等最终失败。普通手动停止和成功恢复的中途重试不记录问题。已记录的最终失败不会因阅读或后续回合成功消失；是否启用“额度恢复后继续”不影响问题标记。
6. 一项读取失败时，其他已确认结果仍可展示，失败状态提供重试；不能把未知状态当成已确认中断。新建但尚未发送第一条消息的会话不匹配。
7. 筛选期间固定会话可以被隐藏，但取消筛选后仍固定；不发送删减后的 pins 数据。搜索与状态条件取交集，不调整原项目顺序。
8. 验证中英文与 1440×1000、768×1024、375×812 浅深主题，标签不越界；选中项始终白字、白边框，浅色主题有深底确保可读。

## 性能与安全边界

- 全部/活跃/未读切换只做前端掩码，不增加 RPC。问题摘要在通知连接 ready 后读取一次，重连补读；复用既有通知订阅，事件增量更新，GET 不访问原生会话。
- 中断按需调用 `/codex-api/sidebar-thread-status`，跳过已知尚未忽略问题的会话，每批至多 100 个 ID；服务端最多 4 个真实未结束 RPC，只读取 `thread/turns/list` 的最后 1 回合，`itemsView=notLoaded`，不拉历史正文。
- 触发新回合、完成、取消、状态改变时使缓存失效；目录更新时间也参与缓存校验；迟到结果不得覆盖更新后的状态。
- 超时后保留底层 RPC 占位直到真正结束，不能因重试不断扩大实际并发。此读取不加入自动化任务准入锁，不改账号出口或额度续跑状态。

## 清理与回退

取消筛选即可恢复列表；刷新页面默认不筛选。清理本次虚构会话/浏览器上下文。原生模拟脚本自动停止自己的子进程与本地 HTTP 服务，并删除自己的临时 home，不操作生产数据。撤回代码前确认 59001 空闲；只重启独立开发服务，不重启 5900。

## 活跃标签与额度错误忽略

前提：隔离开发服务；准备最终回合因额度不足失败的会话，以及普通错误会话。

1. 中文侧栏标签显示“活跃”，英文仍为 Active。
2. 打开额度失败会话并选择“中断”；在错误下方点击“忽略”。预期按钮变为“已忽略”，黄点消失，当前选中行保留到切走；没有其他匹配项的项目随之从结果中消失，当前正文保留。
3. 刷新或重新打开页面，预期“已忽略”仍在，筛选仍排除该回合。
4. 点击“已忽略”取消标记，预期立即重新入选；另一个会话的同名回合不受影响。
5. 已忽略会话出现新一轮额度错误，预期新回合仍会入选，旧标记不屏蔽未来错误。0.2.19 普通最终错误也显示相同忽略控件。
6. 明暗主题、1440×1000、768×1024、375×812 检查控件不重叠、不横向溢出，键盘可操作。保存失败时不显示成功标记。

清理：取消测试回合的忽略标记，保留历史原文；不改变账号额度、API、自动化与额度恢复续跑配置。标记按 threadId + turnId 保存在开发 CODEX_HOME 的 ignored-quota-errors.json。

## 当前会话的统一保留规则（0.2.18）

前提：分别准备两个活跃会话、两个未读会话、两个最终因额度不足中断的会话，开启对应筛选。

1. 打开其中一个活跃会话，等待其回合完成：该行和项目仍可见，对话区保持当前会话；点击另一个会话后，已完成会话从活跃结果消失。
2. 打开未读会话，蓝点清除后当前行仍可见；点击另一个会话后，前一个会话从未读结果消失。
3. 打开中断会话并忽略其额度错误，刷新状态完成后当前行仍可见；点击另一个会话后，该行从中断结果消失。
4. 切换筛选项重新按新条件匹配；没有匹配过当前筛选的会话不应凭选中状态被强行加入。清除筛选后原项目层级、排序和折叠状态不变。
5. 不因临时保留而伪造活跃/未读/中断标志，不改变额度忽略的服务器记录；未读与中断沿用一个当前行的保留规则；活跃还保留本次观察到但尚未查看并离开的结束会话，活跃/未读切换不产生状态请求，中断筛选沿用既有批量请求。

清理：仅移除 fixture；无需重置真实账号、会话或自动化。

## 0.2.19：活跃筛选周期与未处理问题圆点

前提：4173 当前工作区服务；运行 `node scripts/test-sidebar-active-retention-ui.cjs` 使用隔离浏览器及模拟接口，或在 59001 准备正常完成、网络失败、额度失败、手动停止和历史未读会话。禁止消耗生产额度制造失败。

1. 先有一个蓝点旧会话，再开启活跃。旧会话不出现；开启后让后台会话分别成功、失败和手动停止，均继续显示。完成事件与蓝点事件顺序颠倒时也不提前隐藏。
2. 逐个打开停止的会话，再切到另一个会话，前一个从活跃消失。正在运行时切走不移除；正在查看的会话手动停止，保留到切走。手机侧栏关闭/重开和视口切换不能重置本次活跃名单。
3. 关闭再开启活跃，或切到另一种筛选再回来，仅显示仍运行的会话。整页刷新也不恢复旧的活跃名单；不把暂留状态写进真实运行/未读标志。
4. 正常未读完成为蓝点，普通最终异常为红点，额度最终异常为黄点，直径均约 6.67px。红黄点在阅读、切换、重连、刷新以及后来成功后仍保留。运行/审批指示沿用原优先级，不丢弃未处理问题。存在多项问题时，有未忽略额度问题则显示黄点。
5. 最终错误正文里的“忽略”按当前 threadId + turnId 生效，“已忽略”可以撤销。另可从会话菜单“忽略全部问题”处理当前已显示的问题；操作开始后新增的问题不能被这次操作误清除。失败时保留标记及可重试错误。
6. 中断筛选纳入红点、黄点对应的未处理问题；手动停止不纳入。忽略清除问题标记，选中行仍保留到切走；撤销忽略重新纳入。查看/忽略问题不影响活跃名单的独立清理规则。
7. 两个窗口同时打开，窗口一忽略/撤销时窗口二随通知更新；迟到初始快照不能覆盖更新。蓝点已读同步不能清除红黄点。
8. 暂时断网但回合尚未最终失败时，不编造中断结果；普通 willRetry 重试后成功或手动停止不标红。额度错误在现有自动 interrupt 前发出、最终回合 error 为空时仍保持黄点。
9. 浅深主题、1440×1000、768×1024、375×812 验证真实行及菜单，菜单不越界。检查固定区、项目分组、无项目会话、时间排序及搜索与状态条件的交集。

持久化：`codexapp-thread-interruptions-v1.json` 只保存会话/回合 ID 和错误种类；忽略沿用 `ignored-quota-errors.json`，兼容已有额度忽略标记。不保存错误正文，不把 UI 状态用于账号、额度、调度、投递或重试。新结束问题通过通知记录；旧历史沿用中断筛选的最终回合按需读取补充，不在启动时扫描全部历史。格式损坏必须报读取失败并保留原文件，不自动清空。

清理：脚本只关闭自己的浏览器上下文；HTTP 单测仅清理自己的临时 home、监听端口与原生 fixture。撤回 UI 代码可保留上述元数据供恢复，不删除真实会话、认证、额度和自动化记录。

## REV-04：问题摘要挂起不阻塞忽略

前提：独立 4173，运行 `UI_LABEL=revision UI_REPORT_PATH=output/0219-revision/sidebar-ui.json node scripts/test-sidebar-active-retention-ui.cjs`；复用受控 SSE 并故意挂起摘要 GET。

操作：在摘要仍挂起时依次忽略两个会话的问题；只在 POST 成功后检查对应圆点消失和下一次忽略按钮可用。放行迟到快照，确认旧问题没有复活。单元测试补 10 秒读取/保存期限、SSE ready 合并后恢复、POST 超时不重发、卸载清理和读取错误不能覆盖较新的保存错误。
