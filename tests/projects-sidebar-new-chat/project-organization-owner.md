# 0.2.22：项目组织与工作区恢复

前提：使用隔离测试 home，准备两个物理项目、一个远程项目和一个仅名称项目，保存不同的展示名称。自动化回归仅替换 API 边界，实际运行 desktop 与领域控制器；浏览器人工验收使用 59001 已通过门禁的候选。

## 首次读取失败后的恢复

1. 在独立测试环境让首次 `/codex-api/workspace-roots-state` 读取失败，加载侧栏。
2. 确认本地展示名称仍可用，列表没有因工作区读取失败而整体报错。
3. 恢复该接口，强制刷新列表。
4. 确认物理项目使用服务器保存名称，远程项目恢复名称和主机后缀；恢复本身不发 PUT。
5. 本次恢复成功后修改本地项目名称，再刷新列表；旧快照不得覆盖新名称。

预期：失败不耗尽首次恢复机会；成功后沿用一次性恢复合同，虚拟项目名称仍随最新快照更新。

## 项目操作与清理

1. 连续修改同一项目名称，等待 500ms；服务器仅保存最后一次名称，去除首尾空白。
2. 在 500ms 内停止 desktop；待执行的保存取消。已经开始的 CODEX_HOME 全局保存可以完成，切换账号不将其私有化或撤销。
3. 移动项目、置顶项目，确认侧栏立即调整；每次有效排序沿用一次工作区读取和一次写入。
4. 移除当前物理项目，确认剩余项目及会话保留、选择切到剩余会话；保存 active 的有效回退。
5. 移除仅名称项目，确认调用项目 DELETE 后刷新列表，所属会话保持原始 ID/cwd。
6. 在亮暗主题重复操作，检查项目名称和选中、运行、未读及审批状态显示。

回滚/清理：还原测试项目名称与顺序，重新添加移除的项目根。只清理本轮独立测试数据，不清空标准候选卷；移除项目不等于删除源码或会话历史。
