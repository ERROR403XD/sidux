# 仅名称项目与项目功能专项回归

前提：独立 CODEX_HOME、59001 候选；准备普通目录项目、两个同名组织项目、至少两个无项目会话、一个普通目录会话。真实账号故障只用隔离 fixture 注入，不破坏生产凭据。

| 功能 | 操作 | 预期 |
| --- | --- | --- |
| 创建 | 创建项目只填名称，目录留空；点击创建及 Enter 各一次；再创建同名项目 | 均创建成功，独立身份；仅 CodexApp 元数据改变，未建立项目文件夹；不增加说明文字 |
| 图标/名称 | 切换展开、收起，鼠标悬停；明暗主题 | 使用两种组织层级图标，不显示文件夹图标、内部 ID 或额外类型标签 |
| 空项目折叠 | 空组织与空目录项目分别鼠标、Enter、空格收起，再刷新；展开后将会话移入，重复操作 | 收起只占标题行高度，不显示“没有会话”；刷新保持收起；展开空项目显示空行，有成员项目显示原会话，工作目录不变 |
| 编辑 | 改名，包含中文、空格、斜杠、尖括号；刷新浏览器及重启进程 | 名称原样保留，身份/成员不变；目录仍空，不改 AGENTS.md |
| 归组 | 从已有无项目会话菜单“移动到项目”选择组织，再移到另一组织和无项目 | 只改变界面归属；cwd、原生会话文件、账号、活动状态和审批身份不变；刷新后保持 |
| 新会话 | 项目行新建、已打开成员会话的工具栏新建；切换新会话选择器 | 保留当前组织，实际发送仍使用普通无项目分配的独立 cwd；不把组织 ID 交给 RPC/终端/Git |
| 当前任务 | 成员会话处于运行/待输入/额度保护时改名、排序、移入/移出 | 执行及阻塞规则不变，不自动停止、放行、重发或切账号；待处理入口仍可找到 |
| 排序/收起 | 键盘 Alt+上下、鼠标拖动、手机移动模式；收起/展开、刷新 | 普通/组织项目共同排序，空项目不丢失，不把成员 cwd 写入真实工作区根 |
| 会话操作 | 选中、搜索、更多、置顶、改名、分支、归档、复制会话、复制路径 | 保持普通会话操作；分支沿用原 cwd 与归属，路径复制仍是真实 cwd |
| 文件 | 成员写入测试文件，再浏览项目/成员目录 | 列出已有成员文件位置，链接能打开，不创建共享工作根或搬动文件 |
| 导入导出 | 空/非空组织导出 ZIP，再导入；另做旧目录 ZIP 往返 | 成员及文件正确，显式导入产生独立副本并恢复组织；旧格式可读，原始文件不变 |
| 自动化 | 普通与组织项目各新建/编辑/多时间/暂停/启用/手动/重试/删除；默认与固定账号组合 | 原调度、幂等、保护、出口语义相同；组织新会话的 RPC cwd 为实际目录 |
| 普通目录项目 | 已有目录、新建目录、重名显示、附加目录、Git 状态、worktree、GitHub clone、ZIP、移除 | 既有功能通过，不因组织支持改变原目录规则 |
| 移除 | 移除有成员的组织，刷新、重启 | 组织消失，会话回到无项目列表，文件/账号/实际目录不变；不能归档或删除成员 |
| 故障 | 写权限失败、损坏元数据、并发保存、排序同时读取、重启 | 原文件保留；失败不显示成功；不把过期缓存重新写回，不清空成员或扩大到账号故障 |

自动化证据入口：`scripts/test-project-organization.cjs`（先构建）、`scripts/test-project-root-api.cjs`、`scripts/test-project-organization-ui.cjs`；Vitest 中的 `virtualProjects`、`projectOrganization`、`projectState`、`projectSetup`、`useDesktopState`、`projectDirectories`、`automationDispatchIntegration` 等。浏览器脚本使用受控 API 状态；真实文件和 IPC 行为由独立脚本/测试证明。

清理：移除明确由本测试建立的项目元数据及 fixture 目录，确认监听进程退出；不得删除用户工作目录或生产状态。回退代码保留 `codexapp-projects.json`；旧版本仍可按真实 cwd 读取原会话，但不显示新组织关系。

## REV-02：组织移除与自动化执行组合

前提：先构建当前版本；执行 `node scripts/test-removed-project-automation.cjs`，使用独立 CODEX_HOME、合成账号和原生 IPC fixture。

操作：仅填名称创建项目，创建任务并手动运行成功；记录定义和认证文件后移除项目，再手动运行、重复同一请求。检查会话真实 cwd、组织成员、执行账号及原任务定义。显式重试并重复相同重试请求；再用同一任务固定原执行账号，启用分钟规则，等待自然到点完成，重新暂停并核对 nextRunAtMs 为空。脚本最多等待 80 秒，不修改系统时间或调度状态。同时运行 virtualProjects 的并发移除/归组测试、automationDispatchIntegration 的默认/固定账号和定时触发矩阵。

预期：移除只取消表现归属，任务继续使用普通无项目的独立 cwd；不复活项目、不改定义/账号/出口、不重复执行。移除恰好发生在创建目录与归组之间也不使任务失败。普通用户编辑不存在项目仍报错；损坏元数据不能被当成项目已移除而吞掉。自动化页面的失效组织 ID 不作为标签展示。

性能：新增目录复用原分配方式，组织归组在既有 mutation 队列内判断存在性；不添加 RPC、账号检查、全量会话扫描或永久删除记录。

清理/回退：脚本确认自有进程退出，按临时 home 和唯一标记清理生成目录。回退代码不迁移定义、认证或历史；仍使用原 requestId 防止手动重放。

## 新会话立即显示在所属项目（0.2.19 补充）

- 准备：隔离实例有仅名称项目及普通项目，浅/深主题可切换；使用可控制投递响应的合成会话。
- 操作：从仅名称项目的新建会话按钮发送首条消息，将投递响应暂缓。
- 预期：目录接口确认创建及归属后，新会话首次出现就在对应项目内，不先出现在无项目区；投递等待、成功或失败后仍在对应项目，刷新后依据服务端已保存的归属恢复。实际 cwd 仍是普通无项目目录，原生 thread/start 与投递请求不包含 virtual ID；不重复创建或重发。
- 操作：令目录创建接口失败。预期：不创建原生会话、不发起投递、不显示虚假的已创建会话。普通项目和无项目新建仍沿用原流程。
- 清理：释放合成请求、关闭隔离浏览器；删除测试数据。回退仅撤销前端即时显示归属参数，不修改服务端项目映射、账号或调度数据。
