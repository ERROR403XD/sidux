# 0.2.14 原版插件、技能与 MCP

前提：启动独立候选 59001；页面测试使用当前源码 4173。准备含技能和 MCP 的原版插件市场。用请求桩为 `app/list` 返回 403，其他原版插件接口返回可核对的状态。

1. 打开设置 → 插件 / 技能 / MCP。仅出现插件、技能/MCP 两个入口，无 Composio、应用目录、GitHub 同步面板；网络面板中没有 `app/list`、`/composio/`、`/skills-sync/` 请求。
2. 安装插件，查看服务连接的授权链接；停用插件，刷新页面，再启用、卸载。每步应与原版 `plugin/list/read/install/uninstall` 和 `config/batchWrite` 状态一致。依赖服务需要授权不等于套餐不支持，不能因未读取全量应用目录禁用安装。
3. 某个市场报错、另一个本地市场正常时，保留可用插件并提示部分市场读取失败。
4. 切换项目范围，查看技能与 MCP；展开 MCP 时才读取工具详情。发送 200 条重复启动通知，一个合并窗口最多新增一次 MCP 请求。请求中途切换范围后，旧结果不得覆盖新范围。
5. 在 1440×900、768×1024、375×812 各检查浅色、深色；真实卡片和插件详情无主题混色、横向溢出。
6. 安装原版验收插件并从新会话实际调用其中的技能/MCP。只有原生接口成功、实际返回指定输出才算运行验收，页面桩不替代此项。

清理：卸载验收插件并移除验收市场；删除临时自动化，归档其会话。现有用户插件与技能保留。

历史说明：本目录内 GitHub 同步、Composio 相关案例适用于 0.2.13 及更早版本，0.2.14 已移除此功能。

已完成页面证据：`output/0214/ui.json` 与 `output/playwright/0214-{plugin,skills}-*.png`；6 组布局检查通过，安装/停用/卸载和刷新持久化通过，退役请求为零。实际原版调用证据见本版本开发验收文档。

大目录验收：候选原生目录超过60项时，检查每页最多60张卡片，下一页改变内容，搜索跨完整目录且返回第一页；浅/深主题均无横向溢出。分页不重复请求原生目录。清理搜索条件并回到第一页。

前置：4173 当前源码、121 项原版目录桩及 MCP/本地技能桩；实际候选 59001 只读复核。
