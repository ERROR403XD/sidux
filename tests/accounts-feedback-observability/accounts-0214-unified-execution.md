# 0.2.14 统一账号执行与移除

前提：59001隔离候选，测试账号A/B，跟随默认出口和固定B的测试Key。记录使用真实上游或协议fixture，真实生成会消耗额度。

| 操作 | 预期 |
|---|---|
| A会话未完成/无额度/掉登录时，用B的Key调用models、Responses、Chat Completions、compact和WebSocket | B返回实际输出；A状态不阻塞B；上下文不跨Key |
| A等待额度时执行绑定B的自动化，完成后再执行同一任务 | 两次均产生结果并结束；不覆盖主auth |
| A准备账号连接时执行B任务 | B可独立准备和启动；同一任务目标不重叠 |
| 两个自动化产生相同原生审批ID，分别处理 | 只回复对应任务 |
| 默认出口A与固定B各开流，默认出口改B | 保存成功，仅跟随默认的连接中断；固定B继续 |
| 主回合已失败，存在失败/排队记录和后台终端，切换账号 | 保留历史和终端，后续走新账号；仍在提交/结果未知的投递需要核对 |
| 主账号失效，打开重新认证 | 不被独立自动化、失败记录或终端禁用；额度服务临时失败不等同认证失败 |
| A掉登录/刷新中/执行中，更多→移除→确认移除并中断 | 不必先切换或等待；A凭据删除、连接关闭，B继续；迟到刷新不能恢复A |
| 再添加A，刷新页面 | 可重新登录；旧连接不复活，绑定不漂移到其他身份；同一身份重新添加后新请求使用新凭据；历史保留 |

浅/深主题各检查上述入口。部署空闲门禁仍需检查全部活动执行；账号切换使用独立边界。

清理：取消测试排程，撤销测试Key，停止测试容器；真实移除只能重新登录恢复，不向5900复制候选凭据。

自动回归：accountExecution、accountRuntimeIntegration、accountTaskRouting、accountAuthCoordinator、apiProxy/gateway、automation。IPC测试有实际子进程和输出，上游由fixture模拟。

认证与会话写入权补充回归：

| 操作 | 预期 |
|---|---|
| 已过期的access token被标记需认证，但refresh token仍有效；从API或账号探针访问 | 使用同一协调器刷新后恢复；原生探针不自行覆盖令牌 |
| 多个入口同时遇到失效refresh token | 合并请求，明确失效按凭据版本阻止重复刷新；临时故障退避30秒 |
| 令牌刷新未返回时移除账号，随后重新登录同一身份，再让旧刷新返回 | 保留新凭据，旧刷新不能覆盖或恢复旧连接 |
| 自动化完成后继续聊天，再对同一会话执行两轮心跳自动化，每次随后聊天，最后归档 | 同一会话保持原生进程，切换当前执行账号；输出正确，归档成功 |
| 已完成会话还有后台终端或待审批 | 保留其所属进程，清楚提示同一会话待处理项；其他会话与账号继续运行 |

原生 unsubscribe 保留写入权30分钟，因此会话与原生进程绑定；普通聊天和心跳复用同一会话进程，在会话边界更换凭据。共享会话资源池最多16个进程，自动化最多4个并发运行；仅回收空闲资源，等待被回收进程退出后再使用。移除不等待额度或回合结束，关闭关联进程并等待本地退出（1.5秒后强制终止）。部署仍须通过全局空闲检查。真实验收与模拟场景的区分见开发验收文档。

运行中跟随默认账号的自动化已取得B时，把主账号改为A后移除A：B的运行保持执行，运行记录保留取得的账号标识。账号切换只检查活跃会话归属与未知投递，不扫描全部历史。
