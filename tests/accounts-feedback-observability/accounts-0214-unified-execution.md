# 0.2.14 统一账号执行与移除

前提：59001隔离候选，测试账号A/B，跟随默认出口和固定B的测试Key。记录使用真实上游或协议fixture，真实生成会消耗额度。

| 操作 | 预期 |
|---|---|
| A会话未完成/无额度/掉登录时，用B的Key调用models、Responses、Chat Completions、compact和WebSocket | B返回实际输出；A状态不阻塞B；上下文不跨Key |
| A等待额度时执行绑定B的自动化，完成后再执行同一任务 | 两次均产生结果并结束；不覆盖主auth |
| A准备账号连接时执行B任务 | B可独立准备和启动；同一任务目标不重叠 |
| 两个自动化产生相同原生审批ID，分别处理 | 只回复对应任务 |
| 默认出口A与固定B各开流，默认出口改B | 保存成功，仅跟随默认的连接中断；固定B继续 |
| 主回合已失败，存在失败/排队记录和后台终端，切换账号 | 保留历史和终端，后续走新账号；仍在提交/结果未知的投递需要核对 |
| 主账号失效，打开重新认证 | 不被独立自动化、失败记录或终端禁用；额度服务临时失败不等同认证失败 |
| A掉登录/刷新中/执行中，更多→移除→确认移除并中断 | 不必先切换或等待；A凭据删除、连接关闭，B继续；迟到刷新不能恢复A |
| 再添加A，刷新页面 | 可重新登录；旧绑定A的Key/任务不自动改绑，需重新选择；历史保留 |

浅/深主题各检查上述入口。部署空闲门禁仍需检查全部活动执行；账号切换使用独立边界。

清理：取消测试排程，撤销测试Key，停止测试容器；真实移除只能重新登录恢复，不向5900复制候选凭据。
