# 账号预留额度、重置机会与通知

前提：使用59001隔离开发实例或受控RPC fixture；真实账号的重置操作必须另行确认。分别验证1440×900、375×812、768×1024的浅色和深色。全局时区设为Asia/Shanghai，并额外检查America/New_York夏令时换日。

1. 账号周限额分别设置为今天、明天、后天和三天后重置，确认显示今天/明天/后天/周几加时间，不显示月日；5h行保持日期对齐。
2. 注入5次可用重置机会，乱序到期时间；账号卡显示3图标和“+2次重置”，悬停到期从左到右递增。打开确认后取消，消费请求为0；再次确认，仅发送一次所选creditId和稳定幂等ID。刷新列表更新次数。未知明细不可消费；过期机会不显示为可用。
3. 在账号设置填周保护1%，应提示5h保护2%。保存并刷新页面验证保留。API Key选择固定账号或全局账号，两种情况均可勾选受保护；更换账号不自动移除保护。
4. 普通Key及主会话在周剩余1%或5h剩余2%时均拒绝新请求；受保护Key仍可使用，多个Key共享账号预留，不累加。WS连接建立后降低额度，下一个帧也拒绝；运行中非保护HTTP/WS连接和原生会话应被终止，保护任务保留。额度未知时普通流量不可使用预留。
5. 开启POST通知，配置本地模拟URL、JSON多行请求体和{{message}}；账号分别启用5h/周通知及自定义模板。首次基线不发送，resetAt推进且用量下降才排队。跨午夜免打扰期间不发送，结束后发送一次。重启不重复发送，失败/未知HTTP结果不自动重试。消息引号/换行不可修改外围JSON字段。
6. 手动刷新确认等级、额度和重置机会同步；当前账号及有运行活动的账号按最大已用额度分档刷新：<75%为60秒、≥75%为30秒、≥90%为15秒、≥99%为5秒；其他账号5分钟刷新，单飞串行；隐藏页面不轮询账号列表。后台调度检查每5秒，网络请求耗时可能使实际间隔延长。

7. 推送 account/rateLimits/updated 仅包含5h窗口，账号卡应立即更新且保留周窗口与重置机会，不追加账号列表GET；在全量读取未返回时推送新值，旧响应不得覆盖新通知。浅深主题各检查一次。
8. 启动、重新登录、恢复WebSocket连接后立即读取；并发读取合并为一个上游请求。429附Retry-After时按指定时间退避，无提示时指数退避；退避中多次刷新不得发出新上游请求。没有浏览器打开时后台刷新仍有效，不调用内部wham usage接口。

清理：关闭通知、保护值恢复0、撤销fixture Key并删除测试自动化/标记；不得清理真实账号凭据。回滚采用交接文档记录的旧镜像和原卷，禁止同时启动共享卷的两个实例。
