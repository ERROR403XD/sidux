# 账号预留额度、重置机会与通知

前提：使用59001隔离开发实例或受控RPC fixture；真实账号的重置操作必须另行确认。分别验证1440×900、375×812、768×1024的浅色和深色。全局时区设为Asia/Shanghai，并额外检查America/New_York夏令时换日。

1. 账号主额度分别设置为今天、明天、后天和三天后重置，确认显示今天/明天/后天/周几加时间，不显示月日；5h行保持日期对齐。
2. 注入5次可用重置机会，乱序到期时间；账号卡显示3图标和“+2次重置”，悬停到期从左到右递增。打开确认后取消，消费请求为0；再次确认，仅发送一次所选creditId和稳定幂等ID。刷新列表更新次数。未知明细不可消费；过期机会不显示为可用。
3. 在账号设置填主额度保护1%，应提示5h保护2%。保存并刷新页面验证保留。API Key选择固定账号或全局账号，两种情况均可勾选受保护；更换账号不自动移除保护。
4. 普通Key及主会话在主额度剩余1%或5h剩余2%时均拒绝新请求；受保护Key仍可使用，多个Key共享账号预留，不累加。WS连接建立后降低额度，下一个帧也拒绝；运行中非保护HTTP/WS连接和原生会话应被终止，保护任务保留。额度未知时普通流量不可使用预留。
5. 开启POST通知，配置本地模拟URL、JSON多行请求体和{{message}}；账号分别启用5h/主额度通知及自定义模板。首次基线不发送，剩余额度增加至少45个百分点且最近10分钟未使用重置才排队，resetAt无需推进。跨午夜免打扰期间不发送，结束后发送一次。重启不重复发送，失败/未知HTTP结果不自动重试。消息引号/换行不可修改外围JSON字段。
6. 手动刷新确认等级、额度和重置机会同步；当前账号及有运行活动的账号按最大已用额度分档刷新：<75%为60秒、≥75%为30秒、≥90%为15秒、≥99%为5秒；其他账号5分钟刷新，单飞串行；隐藏页面不轮询账号列表。后台调度检查每5秒，网络请求耗时可能使实际间隔延长。

7. 推送 account/rateLimits/updated 仅包含5h窗口，账号卡应立即更新且保留主额度窗口与重置机会，不追加账号列表GET；在全量读取未返回时推送新值，旧响应不得覆盖新通知。浅深主题各检查一次。
8. 启动、重新登录、恢复WebSocket连接后立即读取；并发读取合并为一个上游请求。429附Retry-After时按指定时间退避，无提示时指数退避；退避中多次刷新不得发出新上游请求。没有浏览器打开时后台刷新仍有效，不调用内部wham usage接口。

清理：关闭通知、保护值恢复0、撤销fixture Key并删除测试自动化/标记；不得清理真实账号凭据。回滚采用交接文档记录的旧镜像和原卷，禁止同时启动共享卷的两个实例。

## 0.2.12 恢复判定与通知测试

前置：隔离账号快照、可控时间、通知接收桩。真实发送仅在用户明确授权后使用本机已有配置。

1. 剩余额度20%→30%（相对增长50%，但只增加10个百分点）不得通知；20%→64.9%不得通知；20%→65%应通知，重置时间无需推进；65%→100%只有35个百分点，不通知。相同快照不得重复通知。
2. 真正进入重置RPC前持久化使用时间；最近10分钟内用过重置，则剩余额度20%→80%不通知。重置机会过期造成数量减少不算使用。10分钟以后再次发生剩余额度增加至少45个百分点应通知。
3. 账号刷新/凭据轮换后，重置使用时间必须保留。Free仅有30天窗口时，普通任务不得消耗账号的保护值，受保护任务可使用预留部分。
4. 设置中保存通知配置并“发送测试通知”：显示结果，不伪造额度重置事件；测试不受免打扰时段限制。接口成功与收件端确认分别记录。
5. 主激活账号和固定账号读取模型，缓存只能在相同账号与凭据版本内共享；读取不得改变激活账号、导入API代理目录。

清理：恢复模拟时间，删除隔离目录；保留用户明确要求启用的真实通知配置，不把URL、请求体凭据放入测试证据。

## 重置机会到期提醒

前置：隔离账号与可控available重置机会，配置POST测试接收器，不向真实接收人发送fixture通知。
操作：账号设置开启到期提醒。默认应为`7d, 3d, 12h`；输入`7d，3d 12h`保存后重开，应规范成英文逗号加空格。`3d12h`是84小时，`3d 12h`是72小时和12小时两个档位。分别模拟跨过7天、3天、12小时阈值、服务重启、静默时段、机会已用或到期。
预期：每个机会/到期时间/档位最多通知一次；离线跨过多个档位仅补最近档位，机会消失、已用或到期不再发待发提醒。支持account、account_id、credit_id、expires_at、remaining、lead_time占位符。0h与小数输入报错。通知开关默认关闭。
清理：移除隔离状态与接收器；恢复修改前配置。

## 0.2.14 追加：Banked reset 次数增加提醒

前置：使用隔离账号数据、可用次数快照和本地 HTTP 接收器。不得使用真实重置机会或外部通知接收人测试。

操作：打开账号设置，启用“重置次数增加提醒（Banked reset）”，编辑通知模板并保存；刷新页面后重新打开，检查开关和模板保留。先观察 1 次，再观察 3 次并重复观察相同快照；进入免打扰后重启通知服务，再离开免打扰。预期：第一次只建基准，增加 2 次只投递一次，免打扰延后并跨重启保留；POST 模板可以使用 account、account_id、increase、previous、remaining。次数减少、未知快照、错误快照、旧时间快照均不误报增加。禁用规则清除未发送通知，禁用期间观察的增长不在重新启用时补发。检查另一账号的基准不受影响。

验证：accountNotificationService.test.ts 包括真实 loopback HTTP 投递和并发去重；UI 在三个视口的浅/深主题测试保存与刷新。清理：停本地接收器并删除临时数据；不修改真实通知渠道或 reset credits。
