# Codex API 出口（0.2.0）

## 前置条件

- 使用隔离 59001 候选及其账号池，不复制生产认证。至少一名已登录的 Codex 账号；双账号用例需要两名测试账号。
- 构建阶段执行 `node scripts/install-api-proxy.cjs output/api-proxy-component`，使用固定校验的 CLIProxyAPI 7.2.152；支持本机 Linux x64。
- 客户端使用独立 CODEX_HOME、临时测试工程和 Codex CLI 0.153.4。测试 key 不写入版本库或报告。

## 操作与预期结果

1. 打开侧栏“自动化”下方“API 出口”，分别检查 1440×900、375×812、768×1024 浅深主题。账号选择使用自定义菜单；卡片、输入框、弹窗无浅色残留或横向溢出。
2. 启用出口并保存；默认跟随 WebUI，也可固定选择另一账号。页面分别显示 WebUI 账号、API 选择及实际使用账号。刷新页面后设置保持。API 固定账号切换不修改 WebUI active；WebUI 切换其他账号不打断固定 API 账号的连接。
3. 创建、重命名、停用/启用 key，检查仅创建时显示完整值。轮换创建新 key，旧 key 24 小时后失效；撤销不可重新启用。已过期/撤销 key 的 HTTP、WS 握手以及原 WS 内新请求均被拒绝。
4. 按页面配置设置 base URL 与 `SIDUX_API_KEY`；独立客户端没有 OpenAI 认证也能工作。HTTP 与 WS 配置分别执行读文件、改代码、`node --test`、根据工具结果继续；测试工程只出现在客户端。
5. 普通 `/v1/models` 与 `?client_version=0.153.4` 目录分别验收；固定组件不支持的 ultra 不得公布，手动请求需明确报错而不降级。`/v1/responses` 非流式与 SSE、基础 `/v1/chat/completions` 可用。无 key 返回 JSON 401；未知 `/v1/*` 返回 JSON 404，不返回网页。
6. `/v1/responses/compact` 使用 Codex 原生 Responses V2 `compaction_trigger`，返回真实 opaque compaction；压缩后引用先前虚构事实。旧上游 compact URL 的 404 不能伪装成成功。HTTP previous_response_id 明确拒绝；WS 续接必须属于本 key 与当前路由，未知上下文报错。
7. 建立长 SSE、执行中的 WS 与空闲 WS，再保存账号或停用服务。正常操作停止新请求，等待已接收响应；超时保留原路由和活动请求。空闲 WS 正常关闭。单独确认强制操作后才中断活动连接。
8. 两把 key 并发，撤销其中一把不影响另一把。达到并发上限返回 429，不排无限队列。客户端断开后上游关闭，活动计数回到 0；无重复计数释放。
9. 同账号 API/WebUI 同时刷新时验证单一受协调的刷新、revision 检查、active 物化更新；固定非 active 账号刷新不能改 active。组件投影不含 refresh token；原版二进制/目录固定，没有浮动 latest 更新。
10. 执行只读 `CODEXAPP_IDLE_CHECK_URL=http://127.0.0.1:59001 node scripts/check-codexapp-idle.cjs`。活动 HTTP/SSE/WS 阻止替换；活动接口故障不能视为空闲。只有核实旧产物不含 API 出口时才允许 legacy 例外。

## 工程验证

- `pnpm run test:unit`、`pnpm run build`；构建后 `node -e "process.argv=['node','codexapp','--help'];require('./dist-cli/index.js')"`。
- `CPA_BINARY=$PWD/output/api-proxy-component/cli-proxy-api node scripts/probe-api-proxy.cjs` 为假账号/假上游探针，不需要真实凭据。
- Provider/Auth Docker 四场景：无认证 Zen、失效认证错误刷新持久化、畸形认证回退、Zen→OpenRouter；保存浅深主题错误界面及重复 live overlay 数量。
- 性能比较直连固定组件与经接入层的并发 1/4/8：延迟、请求次数、内存与取消；首页不为 API 出口增加轮询，页面隐藏/离开后停止刷新。

## 回滚与清理

撤销验收 key，等待活动归零，恢复验收前出口设置。先核对共同空闲，再回退候选镜像；不回滚已合法轮换的账号凭据、用户会话或 key 撤销状态。清理本次临时客户端目录与专用测试容器，保留候选账号卷。5900 不在本次部署范围内。


## 0.2.1 API 入口与 key 持续时间

前置：在独立 59001 候选打开 API 出口；用临时 key 验证，浅/深主题各测 1440×900、375×812、768×1024。

1. 检查侧栏 API 出口图标为蓝色，与技能和自动化区分。
2. 打开创建 key，名称和持续时间分行，弹窗/输入框不横向溢出。持续时间默认空白、提示“无限”；创建后 API 保存 expiresAt=null。
3. 再创建临时 key，持续时间填 7，确认 expiresAt 为提交后 7 天；刷新页面仍显示正确到期时间。
4. 输入 0、-1、1.5 或超出日期范围的数字，点创建应显示错误且不发送创建请求。清空后恢复可创建。
5. 轮换使用相同持续时间规则，原 key 仍按 24 小时过渡，到期时间不被错误覆盖为新 key 的持续时间。

清理：撤销临时 key，恢复原出口开关。回退仅恢复候选代码，保留已撤销 key 状态。
## 0.2.10 错误后恢复与用量

准备：使用隔离候选与临时 key、可控制错误的假上游；不要对生产故障注入。

1. 先成功请求，再返回一次 400，改回合法请求；应正常成功且出口保持启用。
2. 返回 500，再恢复上游；在接入层退避窗口后发送新请求，应成功，原生成请求不得被自动重放。429 带 Retry-After 时应等待对应窗口。
3. 取消慢 SSE、断开 WS 或停止组件，检查活动计数回到零，后续请求仍可恢复。
4. 检查 key 请求/Token 汇总、错误和用量缺失计数；两把 key 分别调用，刷新和正常重启后不串账。
5. 分别使用 JSON、SSE、compact、WS 多轮；将上游 usage 的 input/output/total 与对应 key 对账，缓存和推理明细不重复计入总量。取消没有 usage 的慢流，显示用量缺失而非伪造零消耗；模型目录次数单列。
6. 切换今日/近 7 天/累计及全局显示时区，用跨日 fixture 确认自然日归属；重命名不改账目，轮换新 key 独立计账，撤销后仍可查看旧统计。
7. 在独立测试目录制造坏 usage 文件或写失败，检查提示可见、出口仍可服务、坏文件保留；正常重启保留已落盘统计。记录异常退出可能丢失约 2 秒加写入耗时的未落盘量。

清理：撤销临时 key、结束测试连接，出口设置恢复测试前状态；保留已有账号与用户统计。

### 0.2.20-dev.3 key 高级选项与路由

3. 已撤销的 key 行内不显示端点标签、启用开关、高级选项、重命名、轮换、撤销，也不显示到期时间。
4. 聚合路由：打开后每行“账号在左、模型名在右”，新增项默认账号为“全局账号”，账号选项包含“全局账号”；行数不限、允许同一账号重复、不需要排序。主界面账号下拉框此时显示“聚合账号”；改选其他账号会关闭聚合模式但保留清单，之后可再选回“聚合账号”。开启聚合路由的 key 请求 `/v1/models` 返回清单模型并集且不请求上游，并按模型路由到清单内对应账号；清单外模型透传到该 key 自己的账号。
5. 强制路由：只改写请求模型，不影响账号选择，与聚合路由和普通账号都不互斥；两者同时开启时先按强制模型定位账号。未开启强制路由时按调用方传入的模型名直传，不因本地模型目录否决。
6. 校验：确认高级选项时，空模型、重复模型（区分大小写）、空账号、账号已删除或停用、强制路由模型不在聚合清单内都会以红色通知阻止确认；强制路由不在清单时提示包含 key 名与“路由配置错误”。确认只写入本地待保存状态，仍需整体“保存配置”才落盘。
7. 保存后刷新页面，路由与清单保持一致；浅深主题、1440×900 / 375×812 / 768×1024 均无横向溢出。

### 0.2.20-dev.3 聚合路由处理顺序与连接生命周期

前置：使用隔离 59001 或 `127.0.0.1:4173`（独立 `CODEX_HOME`），准备两个可观测的虚构账号和一把开启聚合、关闭强制路由的临时 key；为慢上传、延迟 prepare、SSE/compact/WS 准备可控 fixture。不得向生产网关注入慢请求，也不要把真实 key 写入日志或截图。

1. 原始 HTTP 客户端只发送部分 JSON。活动快照应立即出现该 key 的 `http` 活动，`phase=reading`，`connections` 和 `activeRequests` 各增加 1；此时不应触发账号 prepare 或上游请求。补全请求体后才解析 `model`、绑定清单账号并进入 `preparing/running`。
2. 在部分请求体保持未完成时执行该 key 的强制停用/排空。管理请求成功后活动最终归零、上游请求数不增加，客户端收到关闭或 408/499 类终止；刷新后不能继续向上游发送旧请求。
3. 动态聚合 WebSocket 完成握手但不发送首帧。活动快照应显示 `phase=waiting-first-frame`、`connections` 增加 1 而 `activeRequests` 不增加；执行排空后连接和活动归零。
4. 将 WS prepare 延迟，在连接尚未建立时快速发送两帧。最多只能有一次 prepare、上游连接、账号 lease 和 generation hold；第二帧应得到明确的进行中错误或随连接关闭，不得产生第二条上游请求。
5. 分别在慢请求体、prepare、SSE、compact 和 WS 发送/接收阶段断开客户端。确认活动、账号 lease、generation hold、定时器和上游连接最终归零，单次请求只计一次成功、失败或中断。
6. 让默认 key（跟随主账号）和固定到账号 B 的 key 并行保持活动，然后切换或删除账号 A。只有实际依赖 A 的活动被中断；固定 B 的请求继续，聚合清单中明确绑定 B 的模型不因主账号切换而中断；全局账号项按新的主账号重新请求。
7. 依次验证普通 key、强制路由 key、聚合且开启强制路由 key、聚合但关闭强制路由 key。只有最后一种需要先读请求体取得 `model` 再选账号，其余路径应在既有时点完成账号解析。
8. 覆盖清单内模型、清单外模型、缺少 `model`、`model=null`、清单中的全局账号项、固定账号项以及 `/v1/models`。聚合 `/v1/models` 返回本地并集且零上游请求；清单外模型按既有默认链路透传，全局项跟随当前主账号，固定项只访问对应账号。

## 0.2.22-dev.2：Magpie / Sub2API 兼容周期额度查询

准备：使用源码构建后的隔离实例，两个绑定不同 OpenAI 测试账号的有效 Key，账号已有 Sidux 成功额度快照。使用 Magpie 临时配置，不改线上供应商或真实账号；API 代理需已启用。

1. 配置自定义供应商的 Balance URL 为 `https://服务域名/v1/usage`，Balance field、Balance token 留空，沿用供应商 API Key；隔离本地验证可用 `http://127.0.0.1:4173/v1/usage`。
2. 发起 `GET /v1/usage`，只有 `Authorization: Bearer <API_KEY>`，无需页面登录。JSON 顶层 `rate_limits` 为数组；只含缓存中实际存在且有效的 300/1440/10080 分钟窗口，分别命名 `5h`/`1d`/`7d`。
3. 按用户确认使用百分比归一化：`unit: "percent"`、`limit: 100`、`used: 真实已用百分比`、`remaining: 100 - used`。不声明 USD、不创建美元计费、不把多个窗口相加为顶层 remaining。`reset_at` 直接沿用真实缓存的 Unix 秒并转换为 RFC 3339 UTC（Z）；零用量、尚未开始的窗口可省略 reset_at。
4. 两个 Key 对应不同缓存百分比和重置时间，确认 Magpie 周期进度与重置时间一致；绑定同一账号的 Key 共享该账号额度，此接口不是每 Key 的独立消费账本。强制路由可用，聚合路由、未明确绑定、自定义连接无账号周期，返回空数组。
5. 无、错误、停用、撤销或过期 Key 返回 401；只支持 GET，其他方法返回 405。并发变更绑定时返回 409，不混合旧账号与新路由数据。
6. 超过五分钟或当前刷新失败/进行中时，仍可使用最近一次成功缓存，附 `updated_at` 和 `stale: true`；已过重置点、未知长度、异常百分比、有用量但缺重置时间的窗口省略。缺缓存或未成功更新过时返回空数组，不伪造可用额度。
7. 连续查询不触发账号刷新、模型目录读取、组件 prepare、账号执行 lease、活动配额或模型请求统计；外部额度查询次数必须为零，仅每个绑定账号查询读取一次本地状态。

Magpie 0.1.1233 的 Sub2API 解析器把窗口单位固定标作 USD，并忽略 Sidux 的 unit 字段；比例和重置时间正确，单位文字由 Magpie 侧决定。该客户端限制不能用伪造美元数据规避。

### Magpie 纯百分比显示（推荐）

把 Balance URL 改为 `https://服务域名/v1/usage/percent`，Balance token 留空，并填写 Balance field：

```text
5h 已用: periods.five_hour.used_percent / 100 %; 5h 重置: periods.five_hour.reset_at; 7d 已用: periods.weekly.used_percent / 100 %; 7d 重置: periods.weekly.reset_at
```

该路径复用同一鉴权、绑定规则与本地快照，响应保留 rate_limits，并增加按实际窗口存在的 periods.five_hour / periods.daily / periods.weekly。每项包含 used_percent、remaining_percent 和可选 reset_at，不增加外部查询。需要显示实际 1d 窗口时可增加 `1d 已用: periods.daily.used_percent / 100 %; 1d 重置: periods.daily.reset_at`。没有该周期或尚无重置时间的字段由 Magpie 显示为“—”，不伪造数值。

验收：Magpie 卡片数据的 balanceParts 应含真实百分比及 percent 数值（客户端据此绘制进度条），重置行等于缓存的 RFC 3339 时间；windows 为空且无 USD。两个 Key 的百分比必须分别对应绑定账号，无效 Key 返回 401。用户切换到该路径后需要同时填写 Balance field；留空无法自动识别通用字段。
