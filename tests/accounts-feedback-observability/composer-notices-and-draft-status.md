### 功能提示关闭与轻量草稿保存状态（0.2.18）

#### 前置条件
当前 4173 工作树，隔离测试浏览器；明暗主题，1440×1000、375×812、768×1024。所有草稿均为合成文本，不发送模型请求。

#### 操作
1. 新会话输入文本，检查“已保存”，刷新确认文本恢复；清空后状态消失。
2. 分别在两个会话编辑不同草稿，切换再刷新，检查内容和保存状态各自对应。队列编辑草稿沿用独立 draftKey。
3. 仅在测试页面令 Storage.prototype.setItem 对 thread-draft 键抛出 QuotaExceededError，继续编辑。
4. 检查“保存失败 / 复制草稿”；复制失败时输入文本应被选中，便于手工复制。恢复存储再编辑后检查“已保存”。
5. 在新会话输入 `/copy` 并确认命令，出现“请先进入一个会话”；点击 ×，检查提示消失、草稿不变。再次执行，提示应重新出现。
6. 对会话历史操作、队列操作、命令弹窗中的功能错误重复关闭检查。切换会话后不应带入旧会话被关闭的状态。
7. 重复明暗主题和窄屏检查，按钮可点、可键盘聚焦，无横向溢出。

#### 预期
- 常规状态只写“已保存”，样式轻；现有同步存储成功后才显示，不承诺跨设备同步。
- 保存失败不清空输入，不自动发送；已有附件仍沿用原草稿引用语义，复制按钮复制文字，不承诺备份附件文件。
- × 只收起功能提示，不中断执行、不回答审批、不修改失败回合的持久记录。新的错误仍可出现。
- 不新增 API 请求、轮询或存储写入；继续复用原有草稿 watcher。

#### 清理
恢复 Storage.prototype.setItem，删除测试浏览器的合成草稿或关闭测试上下文；不修改真实浏览器数据。

### 0.2.22-dev.2：输入框草稿归属与旧标签页覆盖

前置：4173 独立合成后端和全新浏览器上下文，两个会话 A/B；两个标签页共享该上下文的 localStorage。使用浅深主题，所有文本与附件为合成数据，不发送模型请求。

1. A 输入不同于 B 的草稿，带一个文件附件和技能；切换 A/B，再刷新，确认文字、附件和技能分别归属原会话。
2. 两个标签页同时打开 A。第二页更新草稿并显示已保存，第一页保持原文本不编辑，切换 B 再回 A。A 应恢复第二页的最新草稿，第一页切换时 localStorage 草稿写入次数为零；刷新后仍保持最新草稿。
3. 在输入事件同一任务内触发 pagehide，再刷新。最后一次输入应已写入原会话键。输入后立即卸载、切换会话也应保存到原会话，不写进目标会话。
4. 进入队列编辑草稿，切换另一会话再返回；队列草稿与普通未发送草稿独立。退出队列编辑后普通草稿保持原样。
5. 同一批次修改文字、附件、技能，正常保存只写一次；仅恢复草稿、切换未编辑会话或卸载未编辑输入框不回写。主动清空仍应保存清空操作。
6. 模拟 localStorage 写入失败，确认输入和“保存失败 / 复制草稿”保留；恢复写入后继续编辑或离开可重试。此修复不恢复此前已经被覆盖的文本；多个标签页同时主动编辑仍采用最后保存者的内容。

验证：`pnpm exec vitest run src/composables/useComposerDraftPersistence.test.ts src/composables/threadSendComposition.test.ts src/composables/threadMutationComposition.test.ts --maxWorkers=4`，以及项目 `docs/plans/evidence/022-drafts-20261015/verify-ui.cjs`。

清理：关闭合成浏览器上下文；不清空用户 localStorage 或 59001 标准卷。回退相关修复提交即可，继续使用既有 v1 草稿键，无存储迁移。

### 0.2.22-dev.4：路由切换期间的草稿隔离

前置：隔离 4173 和两个独立浏览器上下文模拟设备，各有 A/B 会话；使用合成草稿，不发消息。脚本：`node scripts/verify-022-dev4-model-drafts.cjs`。

1. B 输入独有草稿，再切 A，延迟 A 的 thread/read 响应并输入 A 独有草稿。
2. 响应未结束时切回 B：地址和输入框立即对应 B，暂时禁用输入/提交；不能显示或保存 A 内容到 B。
3. 释放响应：B 恢复可编辑，刷新后仍保留 B 草稿，返回 A 仍是 A 内容。
4. 两个独立上下文分别输入不同文本，重复切换及刷新；各浏览器只恢复本地草稿，不承诺跨设备同步。
5. 队列编辑模式切换会话时，旧会话的 draftKey 不得绑定给新会话。浅/深主题均执行。

预期：草稿归属取可见路由，不等待历史请求串行完成；不增加 API、轮询或存储写入。
清理：关闭合成上下文及请求拦截，保留 4173；不清理真实 localStorage。回滚该修复提交即可。
