# 账号操作控制器与生命周期

前置条件：隔离开发环境有两个合成账号 A/B；使用 4173 的请求拦截，或在 59001 自己的测试账号中操作。不得读取、复制生产认证或删除真实账号。亮暗主题分别执行。

1. 读取 A 为当前账号，延迟一次账号列表 GET；切换 B 完成后再释放旧 GET。B 仍为当前账号，会话按当前账号刷新；旧列表不覆盖 B。
2. 延迟切换 POST，关闭并卸载应用，再释放响应。不显示迟到提示、不重新启动轮询、不发起后续 custom connection/会话/账号请求。
3. 点击刷新列表，延迟第一个额度响应；卸载后释放响应。不会继续刷新下一个账号。
4. 同时触发两次列表读取；只产生一次 GET。静默调用失败不提示，非静默调用失败保留错误。
5. 点击 A 的移除，第一次只显示确认，第二次才发请求；请求期间点击切换 B 或移除另一个账号，不发第二个身份变更请求。成功后列表与当前账号一致。
6. 移除后通过登录重新加入同一 storageId，登录完成关闭对话框并清空目标，账号重新显示；刷新页面后从服务端恢复。
7. 从设置页及左下角账号面板重复上述可见操作；按钮、错误、额度时间及登录对话框在亮暗主题可读，切换失败后可重试。

预期：账号状态与当前身份一致，停止后的结果不改变状态或新增资源；串行额度刷新最多同时一个请求。新增控制器只接收窄身份刷新接口，App 不持有账号列表写入、API 操作或计时器。
