# 0.2.11 账号定时激活

前置：隔离候选 59001；至少两个 GPT 账号，其中目标账号未绑定当前主运行时且访问令牌有效；独立反代组件已安装。使用测试账号，不拷贝生产认证。计划默认关闭。

1. 在设置→账号与连接选择目标账号和多个每日小时和分钟文本框（如 9 与 7），使用全局时区，保存；刷新保留，开启/保存不立即发送，后端关闭网页仍调度。
2. 到点分别模拟或准备：5h 原始 usedPercent=0、非零但 UI 四舍五入仍显示100%、未知额度、周窗口100%但5h非零、无效凭据。只有第一种可进入发送，其他记录跳过，不刷新认证或补发。
3. 目标账号有请求或空闲 WS 时跳过。准备过程中插入前台连接、账号切换、凭据版本变化、关闭计划，检查最后准入不发送。另一个账号提供的 API 服务不中断，当前激活账号不变。
4. 同一个时刻重复 tick、服务重启、时间回拨、夏令时重叠均不能重复发送；服务停机错过时刻不补发。发送响应丢失记录结果未知，不自动重发。
5. 每个账号执行后清理临时探针和反代进程，最多一个临时反代实例。失败路径不能留下常驻进程、全局账号锁或 credential refresh。
6. 真实窗口验收：记录目标账号、发送前后的5h原始用量和 resetsAt；消息成功与窗口启动分开确认。使用固定标准速度 gpt-5.6-luna、固定短消息，不带项目/历史/工具。若账号不满足准入条件，不绕过筛选以追求通过。
7. 浅深主题及 375×812/768×1024 检查账号复选、多时间输入、保存/错误/最近结果。保存后刷新截图显示同一计划。

回滚/清理：先关闭计划，确认临时进程退出，再撤回代码；保留 `CODEX_HOME/account-activation/state.json` 的已执行标识，避免重新发送。只清理本次 fixture 数据。API 出口不需要重新配置或重启。

性能：关闭时无账号轮询；启用后单个10秒定时器，仅到点逐个读取目标账号。每次一组新鲜额度读取、一个有界临时反代启动及一次消息，不自动重试/补发。下一时刻计算只在初始化/保存/计划推进执行；执行日志最多200条、去重记录保留3天。最后准入和网络开始之间没有异步等待。真实其他账号 API 延迟及窗口结果需候选实测。

## 59001 时分输入与全局时区

前置：隔离 fixture，计划关闭。输入 9/7，保存并刷新应恢复 09/07；25小时、60分钟、空小时或分钟必须报错，不能提交。无独立计划时区控件。全局时区切换为 UTC 后，后端计划 timezone=UTC，刷新仍一致，原时分不变。重复选择同一时区不发送保存请求，保存期间禁用时区选择；旧计划时区在首次打开设置时对齐当前浏览器全局时区。

清理：恢复原全局时区及关闭计划；不触发真实激活测试。该偏好仍沿用浏览器本地存储，计划时区是服务器持久状态，多浏览器以最后一次设置页面对齐/保存为准。


## 0.2.17 替代路径

前提：隔离 59001，以样本凭据与模拟 app-server 验证，不读取生产认证文件。

操作：选择两个账号与每日时刻，打开开关；修改时间后离开设置并返回、刷新。模拟到时、凭据短暂变更、首个回合耗时超过一分钟、服务重启及前台主账号切换。

预期：修改即时保存；空账号/空时刻允许编辑但无下次计划；多账号串行、每个时刻最多一次。每个激活会话使用自己的 CODEX_HOME 和空目录、指定外部凭据，仅发送 hi；完成后约两分钟关闭进程并删除整份临时会话目录。不会调用主账号切换、写 auth.json/accounts.json 或刷新 token；前台账号选择不会改变固定激活凭据。重启清理本调度器残留会话，不重复未知请求。

清理：关闭计划，恢复测试前设置，检查 account-activation/sessions 为空、测试进程退出，主认证及选择状态与基线一致。若无法证明身份隔离，退回固定账号的 API 代理激活。
