# 跨版本 HTTP 缓存与白屏恢复

状态：2026-09-06 已修复；发布时必须复验真实打包版本的旧缓存迁移。

前提：两份真实打包版本，一处固定的临时 localhost 地址可只读切换它们的静态资源；API 使用隔离 59001，只允许读取。保留响应头和浏览器 HTTP 缓存；不要使用 Playwright route，因为它会改变缓存行为。Chromium 1024×768 浅/深色，先禁用 SW 隔离 HTTP 缓存，再另验 SW 场景。

1. 旧版加载并显示输入框，记录首页 ETag、Last-Modified、脚本名。
2. 同一地址切换到新版本，普通刷新，记录首页条件请求与脚本响应。
3. 修复前：不同首页碰撞出同一 ETag，返回 304；旧 JS 路径返回 HTML，出现 MIME 错误和空 #app。忽略缓存刷新可恢复。
4. 修复后预期：使用已经保存旧 ETag 的客户端普通刷新仍取得当前 HTML，不错误 304，不出现 MIME 错误/白屏；缺失 assets 返回真实 404，页面导航 fallback 仍可用。
5. 保留已带恢复入口的修复版标签页后切换版本，再触发未加载的分块；应有明确恢复提示。冷启动模块加载失败也应显示可操作提示，不能依赖已经失败的主模块代码。
6. 另验 SW 开启、正常网络、503/断连恢复；旧的有效页面缓存恢复仍生效，不缓存 HTML 为脚本。
7. 主模块被阻断时，在浅/深主题、375×812、768×1024 检查独立恢复卡片：可读、不越界、不自动刷新；恢复网络后点击“重新加载”，页面恢复且保留原路由，临时刷新参数被移除。
8. 当前打包版已经打开的线程中输入未发送草稿，阻断未加载的 ReviewPane 分块并打开审查面板。应出现恢复提示；点击“稍后”仅关闭提示，再从 Git 菜单退出审查面板回到会话，确认草稿仍保留且没有发送任务。Vite 开发模式没有生产 preload 事件，此项以打包版为验收对象。

性能：记录同一次普通刷新中 HTML 与 JS/CSS 的请求数、200/304、字节数和耗时；不要为修首页校验而禁止所有哈希资源缓存。

清理：关闭自己创建的代理、测试浏览器与缓存；不修改真实端口的上游，不发送任务，不清空用户浏览器缓存，不操作生产服务。
