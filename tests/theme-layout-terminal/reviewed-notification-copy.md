# 0.2.19 审核通知文案

前提：使用独立 CODEX_HOME 的候选与本轮已审核 CSV；不得通过破坏生产账号或历史制造报错。

操作：核对审核意见非空的 60 行及其模板变量；切换中文/英文，检查提交核对、预算、压缩、账号用量退避、自动化失败、统计写入失败等界面。用隔离 fixture 触发失败，分别检查错误码、保护状态及发送次数。

预期：正文遵从审核意见，空白意见保持原样；模型名、秒数、技能名、多行执行状态完整保留。简化提示不解除预算/额度/运行保护，不导致未知提交重发，统计同步失败仍不影响已完成请求。

自动化：translateSource、threadGoal、threadCompaction、accountAuthCoordinator、accountActivationRuntime、automationError 测试覆盖变量及行为边界，最终结合全量回归。

清理/回退：关闭测试页面，保留原独立测试数据作为证据；可独立撤回文案提交，不能回写用户会话内容。

## 四类操作通知（0.2.19 UI 补充）

准备：隔离实例，使用请求拦截模拟结果；1440×1000、768×1024、375×812，浅深主题与中英文。

操作与预期：
1. 触发成功、失败、注意、信息通知：绿勾、红色感叹号、黄色三角、灰色信息图标；文字同主题正文色，边线/图标/倒计时同语义色。辅助技术可读出类型，不只依赖颜色。
2. 成功和普通信息 3 秒消失，注意和失败 6 秒；悬停/聚焦暂停，离开继续剩余时间，关闭按钮和 Enter 可移除。最多 3 条，同文案/类型/作用域去重，不同类型或会话不误合并。
3. 删除/启停回执成功后刷新失败：只有一条对应黄色结果通知，保留行内刷新错误；删除失败仍为红色且确认框保留。
4. 自动化编辑器已有入队提示改为灰色“自动化已加入队列”；详情运行入口原本无成功 toast，保持安静，不能显示任务已完成；每次仍只有一个原接口请求，参数、requestId、防重与调度规则不变。
5. 合成额度重置结果 reset 为成功，alreadyRedeemed/nothingToReset 为信息，noCredit/未知结果为注意；未知结果保留原确认框，错误请求仍失败，不改额度、重试和确认流程。MCP 仅打开授权页是信息，配置重载成功仍为成功。

清理：关闭隔离浏览器，释放拦截；不使用真实账号消费额度，不改账号/API/出口/调度或业务状态。自动化与额度请求次数、ID、确认字段应与原路径一致。


## 0.2.22-dev.7 POST 通知来源前缀

前置：使用隔离测试实例，启用 POST 通知并把 URL 指向本地记录请求体的测试接收器。

1. 发送测试通知，触发会话完成、GOAL 阶段（先启用阶段通知）和额度恢复通知。
2. 使用嵌套请求体 `{"source":"custom","nested":{"text":"{{message}}"}}` 重试。
3. 将账号通知文本手动配置为 `【Sidux】{{account}} 已恢复`，再次触发。

预期：所有 POST 的 `{{message}}` 内容以 `【Sidux】` 开头，已有前缀不会重复；自定义字段、转义、免打扰和去重保持有效。浏览器通知和 Telegram 桥接沿用各自文案。旧版延迟通知在本版发送时也带前缀。

清理：恢复测试实例原通知配置，停止本地接收器；不要向真实通知渠道发送测试消息。
