# 全局显示时区、复制与输入恢复（0.2.8）

## 前置条件

使用当前候选或本项目 4173，准备带代码块、文件链接的 TestChat、一个有执行历史的自动化，以及存在到期时间的测试 API key。记录浏览器系统时区、原显示偏好和自动化执行时区。浏览器自动化使用隔离虚构数据；真实账号 key 不写入截图或日志。

## 操作与预期

1. 打开侧栏设置中的“显示时区”，搜索并选择 `America/New_York`、`UTC`、`Asia/Shanghai` 和“跟随系统”。现有页面日期立即变化，刷新后保持，同源另一标签页同步。下拉框使用共用样式，搜索、键盘和窄屏定位正常。
2. 用固定瞬间 `2026-09-06T17:00:00Z` 核对 API key、自动化下次/历史、额度重置和 Hooks：上海为 9 月 7 日 01:00，纽约为 9 月 6 日 13:00，UTC 为 9 月 6 日 17:00。各处不重复附加显示时区。导出的独立 Markdown 时间元数据保留时区标识。
3. 打开自动化编辑窗口，确认已保存的执行时区及 RRULE 未因显示偏好修改，关闭不保存。调度器与任务执行时区仍单独明确显示。
4. 只对显示偏好存储项模拟写入失败，选择新时区时应看到错误，已生效时区保持。移除故障后重试成功；非法历史值或清空偏好后安全回到系统时区。
5. 点击代码块“复制代码”，粘贴得到原始代码，不含围栏或高亮 HTML；完整回复复制保留 Markdown。模拟 Clipboard API 拒绝时只降级一次，恢复之前输入焦点和选区，隐藏 textarea 被移除；完全失败显示“复制失败”，重试可恢复。
6. 输入中文草稿并模拟 composition/Enter，不得误发送。切换会话保留各自草稿，刷新后恢复。发送唯一 TestChat 标记及 Markdown 文件/浏览链接，检查真实消息行的 `hrefOk`、`titleOk`、`textOk`；截图保存到 `output/playwright/testchat-0208-*-cjs.png`。
7. 在 1440×900、768×1024、375×812 下分别检查浅深主题，设置下拉和复制按钮可见、不越界。物理手机需额外用真实输入法和软键盘检查输入框可见、滚动与焦点；浏览器模拟不能代替真机。
8. 按 [跨版本缓存恢复](release-cache-refresh.md) 验证旧资源请求为 404、入口不缓存、刷新取得新版本且草稿未误发送。

## 清理与回退

恢复原显示偏好（本浏览器同站点全部页面统一生效），删除仅用于测试的草稿和 key，关闭虚构测试浏览器。自动化执行规则不应改变。候选回退前检查空闲与后台终端，保留独立状态卷；不要清空账号或生产浏览器数据。
