# Hooks 观察与 Codex 后台终端（0.2.7）

前提：CLI 支持 hooks/list 与 thread/backgroundTerminals/list/terminate；使用隔离 CODEX_HOME 和内部测试会话。真实 Hooks 使用预先审阅的无害测试配置。停止验收只允许操作此会话专门创建、有超时上限的测试进程。

1. 打开会话，保持 Hooks/后台终端关闭。期望无 process-activity 请求。打开 Hooks 后应显示当前 cwd 的只读来源、启用和信任状态，待审阅不当作可执行；没有信任、编辑、执行按钮。
2. 接收成功、失败、阻止、异步运行和停止通知。期望摘要、耗时、简短纯文本输出正确；点击展开才请求详细输出，HTML 不执行；秒级原生时间不能落到 1970 年。相同原生 Hook ID 的不同回合保留为独立记录。结束后迟到的开始不得回退状态。
3. 刷新页面、重启隔离 CLI/服务。已结束记录恢复；未结束记录显示“状态待确认”，不伪装成功或失败。故意损坏独立测试记录文件，应有读取错误且保留原文件，不覆盖为正常空历史。观察范围和截断可见。
4. 打开后台终端，区分应用自带交互终端与 Codex 进程。列表显示原生 processId、命令、cwd 及存在时的 PID/CPU/内存。没有值不能显示为测得的零。未打开输出时不读历史；输出 delta 不触发 HTTP。选中后无本地观察输出时仅查最近 10 回合；代码模式未发输出通知时，在已观察的回合、原生 processId 和开始时间可核对的前提下，只读会话文件尾部 1 MB 中的结构化 exec 返回值，标为“工具返回片段”。无法关联时明确说明，不无限扫描或从助手文字猜测输出。
5. 在同一测试会话创建两个有唯一标记的限时进程。对 A 点停止后先取消，确认没有 terminate 请求；重新确认后核对 processId 与 itemId，只有 A 被停止，B 保留。不调用 clean 或应用自带终端 close，不使用 OS PID 替代原生 processId。输出保留已观察的退出码，列表消失不能伪造退出码。
6. 注入列表失败、详情失败、停止响应丢失、重复点击及旧列表进程 ID 复用。失败可刷新/重试；列表过期时停止按钮禁用；停止结果不明先重读，不自动重复终止。返回“未停止”不能显示为停止成功。不同命令项的旧确认被拒绝。
7. 快速关闭/换会话/换账号、延迟响应和重连。旧响应不得覆盖新会话，关闭后不再查询。打开面板的相关事件合并刷新；Hooks 通知不重复读取配置；终端输出只更新选中的本线程命令。手动刷新可重新读取配置与状态。
8. 在 1440×900、375×812、768×1024 浅深主题检查实际弹窗、长命令/路径/输出、确认区和按钮。没有横向越界、深色浅底或重复 live overlay。关闭窗口后草稿与焦点保持。

清理/回退：仅停止本轮的限时测试进程、移除独立测试容器；保留认证/历史卷。候选回退先验证空闲，再使用已验收 0.2.6 镜像和原独立状态卷。生产 5900 和 5173 不在范围内。记录文件为独立 CODEX_HOME/codexapp-hook-observations.json，只保存已收到的有界摘要/输出；缺失的原生历史不能由本测试补造。
