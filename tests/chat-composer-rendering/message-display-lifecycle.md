# 会话消息展示、复制和命令结果生命周期

适用：0.2.22 的 `ThreadConversation` 装配、消息展示 owner、命令/Worked 结果与富文本正文。原有文件操作、Markdown 和分页用例继续保留。

## 前提与环境

- 使用当前 Linux 构建和隔离的合成 `CODEX_HOME`，入口 `http://127.0.0.1:4173/`；先核对监听 cwd。不要接入 5900、59001、59002 的状态。
- 通过 `scripts/seed-022-baseline.cjs` 建立 201 条合成会话，使用 `src/server/fixtures/022-baseline-app-server.cjs`；浏览器脚本另建自有的 80 回合会话。
- 桌面 1440×1000、平板 768×1024、手机 375×812，分别检查浅色中文、深色英文。
- 复制故障和迟到回执使用可控 Clipboard Promise；Worked 使用真实会话组件消费合成 WS `turn/completed`。这不是云端模型或用户账号验收。

## 操作与预期

1. 展开两个连续命令的分组，再展开第一个命令输出。分组、命令状态和原输出正确；每个结果只展开自己的目标；没有新增 API 请求，旁边的回复 DOM 保持连接。
2. 展开同回合的 Worked 摘要。显示该回合的两条命令；关闭并重开保持原有交互。切到另一会话再返回，分组和 Worked 恢复默认收起。
3. 复制回复与代码。回复按回合合并到最后一个可复制锚点，包含文件和图片信息；代码仅复制原代码内容。成功反馈约 1.8 秒后重置；拒绝 Clipboard 与选择复制时显示失败，随后成功尝试能够恢复。
4. 让 Clipboard 保持未完成，切换 A→B→A 后再完成或失败。旧回执不能显示到新一代 A；工作目录或账号 revision 变化也必须同步失效。开始新复制时取消旧反馈和 timer，旧失败不能覆盖新成功。
5. 让 Clipboard 未完成，再转到设置使会话组件卸载，然后完成或失败。没有页面异常，没有新反馈或 reset timer；停止后不能重新复制、展开、打开图片或发出分叉/回滚/实施计划命令。
6. 右击消息文件链接，分别尝试 Esc、外部点击、窗口失焦和会话切换。菜单关闭并清除旧 URL；菜单打开时增加三类监听，关闭后释放。停止后旧链接动作不能再打开或复制。
7. 暂时进入 loading，替换消息列表并删除命令和 Worked，然后只将 loading 设为 false。旧展开记录应被剪枝；之后重新出现相同 ID 时不恢复旧展开。仍存在的合法目标保留状态。
8. 检查标题、表格、嵌套列表、高亮/未知代码、文件链接和图片。浅深主题和三个视口保持原样式；`v-html` 内部元素保留原 scoped 边界，不因拆分获得新的通用布局样式。
9. 向上分页并注入流式回复。原消息节点仍连接；锚点不跳动，手动阅读位置保持。跳到最新后回复增长继续跟随，缓存重开仍只显示最近 50 行。
10. 在真实输入框发送唯一 `TestChat` marker，包含加粗、带空格及括号的文件路径、行列号、反引号 HTTP 和 Markdown 链接。验证真实用户行的 `hrefOk/titleOk/textOk`，刷新后仍正确，保留亮暗截图。
