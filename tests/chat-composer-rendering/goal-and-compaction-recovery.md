# 0.2.4 持续目标与上下文压缩

前置：固定 CLI 0.153.4，启用原生 Goal；只在 59001 独立测试会话或拦截 fixture 操作。使用浅/深主题及 1440×900、375×812、768×1024；浏览器故障通过 Playwright 注入，不改变生产认证。

1. 从输入框“＋ → 持续目标”创建目标，确认模型与强度，保存后检查常驻卡片和侧栏标记。暂停只停止后续 Goal 推进；当前回合需另按停止。
2. 为 paused、blocked、budgetLimited、usageLimited、complete 状态分别调整预算或留空。保存只改预算，不恢复任务、不重写 objective、不清零用量。提高已用完的预算后仍需明确点击继续。预算超额时剩余显示 0，并保留超额数量。
3. 修改目标文本并保存：原 active 目标继续运行；其他状态保存成 paused 的新目标，重新累计用量。未保存的目标/预算修改不能被“继续”静默忽略。
4. 两个页面打开同一目标，第一页面保存新目标或预算；第二页面保留自己的草稿并提示已变更，先重新读取再编辑。读取失败保留旧卡片并提供重试；断开通知连接后恢复，当前目标重新从原生读取。
5. 目标完成后刷新及重启候选，状态与统计保持；清除目标保留会话消息。总量只采用原生计数，不累加子线程历史 token；协议不提供的分项不显示成已测数据。运行耗时非零但原生计数为 0 时，不显示推算的预算余量。
6. 空闲会话选择 `/compact`，等待开始、完成和耗时。重复点击只触发一次原生压缩。可关闭窗口在会话中查看进度；输入草稿不被后台压缩状态覆盖。
7. 在独立无效认证容器触发压缩失败；重试中的错误不提前将压缩标为失败，最终失败展示原生原因。刷新后仍可辨认压缩失败；相同回合只显示一条压缩失败反馈。
8. 手动中断本次压缩后刷新，当前浏览器保留关联 turnId 并显示中断。原生旧历史没有压缩条目且浏览器无关联记录时，不猜测空回合的用途。
9. 丢弃压缩请求响应后刷新：从历史确认已完成的压缩，不再发起；未找到结果则显示待确认。“检查结果”只读，明确点击“再次压缩”才启动新请求。后台账号操作、未清空队列及原生活动回合不能绕过服务端空闲检查。
10. TestChat 发送唯一标记和本地 Markdown 链接，确认真实消息行的 href、title、文字均正确。检查小屏横向溢出、错误信息换行和浅深主题表面。快速结束或在历史读取期间结束的回合必须触发新快照，不能被近期缓存挡住。

清理：只清除本轮内部 Goal/测试容器，不删除用户会话或认证卷。候选回退前检查共同空闲；保留状态数据，使用已验收 0.2.3 镜像，不操作 5900。

## 清除目标二次确认（0.2.19 补充）

准备隔离会话及持续目标；从 /goal 点击“清除目标”，确认框显示目标正文，默认焦点为取消。取消/Esc/关闭不调用 thread/goal/clear。确认后检查当前目标再按原接口清除，忙碌期间只允许一次请求；成功后显示“目标已清除”，失败保留目标与错误反馈。确认期间目标正文或预算被其他位置修改时拒绝清除，要求重新读取；不得误清新的目标。浅深主题及窄屏验证按钮、层级与焦点。完成后关闭隔离浏览器并释放受控 RPC；不操作生产目标。

## dev.8 压缩请求、导航与刷新组合（2026-10-20 审核）

前置：本轮独立合成 `CODEX_HOME` 和已核对归属的 `http://127.0.0.1:4173/`，两个空闲合成会话 A/B。使用浅/深主题及 1440×1000、768×1024、375×812。浏览器拦截 `thread/compact/start`，返回成功信封但不发送到原生运行时；意外普通 delivery 必须拒绝。输入 `/compact` 后点击命令选项，或先按方向键选择再按 Enter；未选中时 Enter 按普通消息处理。

1. 依次进入 B、A，在 A 打开压缩窗口；按浏览器后退进入 B，再点击“开始压缩”。预期窗口关闭或重新绑定到 B，不能对 A 提交。当前 dev.8 六组均发送 A 的 ID，记录为 R56；关闭后在 B 重新打开的对照正确。
2. 对 B 提交一次，检查按钮禁用且只有一个被拦截请求。真正刷新页面后重新打开：显示“结果未确认”，不自动发送。点击“检查结果”仅读最近 20 回合，合成历史没有本次结果时继续未知；明确点“再次压缩”才增加一条带 `repeatUnknown: true` 的请求。
3. 检查窗口表面随主题变化、三种尺寸没有水平溢出、Tab/Shift+Tab 焦点留在窗口。每阶段等待 2–3 秒再截图，记录完整 URL、viewport、请求的 threadId 和按钮状态。
4. 运行 `node docs/baseline/022/dev8-review-20261020/compaction-offline.cjs`，核对同页/双页去重、保存失败/读回不符拒绝发送、队列与账号操作双检查、响应丢失不自动重发、失败/中断/迟到历史、20/100 条容量边界。当前 32 条中 31 通过，1 条同为 R56，预期 exit 1；内存传输不代表原生压缩执行验收。

清理：关闭本轮 browser/context、释放所有挂起内存请求；前后核对两份合成会话 SHA 不变，保留本轮 4173。证据等所有浏览器关闭后再写入 `docs/`，避免 Vite 文件监听触发下一组页面重载。不得重启其它服务或修改真实会话。若出现测试夹具误发送，只恢复已核实的自有会话字节并核对历史 SHA，单独记录其清理过程。
