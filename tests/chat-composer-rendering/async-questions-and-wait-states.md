# 0.2.1 异步提问与等待状态

前置：59001 独立候选、CLI 0.153.4；内部虚构线程。六组 UI 检查为 1440×900、375×812、768×1024 的浅/深主题，失败路径用 fixture，原生问题另用真实模型验证。

1. 发出带 `isBlocking=false` 的 requestUserInput，输入框仍可用；普通输入或显式引导不调用 server-request respond。缺省/true 保持旧阻塞卡片。
2. 多问题卡片选择选项并填写无 options 的自由答案，默认选中不提交。自填答案覆盖预选项；留空无选项问题拒绝发送。isSecret 使用密码输入框。
3. 多个异步请求逐个回答；审批到达后优先展示，取消审批再恢复待答问题。MCP 表单/URL、权限允许和拒绝继续可用，不扩大默认权限；新版 fileSystem.entries 的路径/通配符可见，拒绝返回空权限、保留说明，不发送通用 RPC 错误。
4. 结构化 `agentMessage.questions/delivery` 实时出现；默认选项、自填、暂不回答、再展开都不触发提交。发送明确绑定线程、turn、问题；逐问题答案保持次序。
5. 刷新未答卡片仍在；回答后从输入框上方的待答区域移除，历史回答仍保留；刷新后不再展示待答卡片或再次发送。原生运行中 item-N 临时 ID 变为 call ID 后，同一 turn 内问题序号仍关联正确；同一 turn 的相同标题问题保持不同序号。
6. 切到另一线程不出现上一线程卡片，返回恢复；提交中按钮禁用，响应失败保留内容和重试入口；输入法确认候选字不提交。
7. 凭据恢复开始/结束提示显示，刷新可从 bridge 快照恢复；turn 结束或进程停止清除恢复中状态。恢复结束不代表模型请求成功，实际失败仍显示原 turn 错误。
8. TestChat 发送唯一标记和 Markdown/文件链接，检查 href/title/text；UI 不显示回答绑定标记。截图放在 output/playwright/。
9. 0.2.17 问题回答发送 ID：新回答使用带提交时间的标准发送 ID，失败重试复用浏览器已保存的请求。预先在浏览器保留旧 `question:<thread>:<turn>:<ordinal>` ID 的待确认记录（模拟旧版“无效的发送 ID”），刷新并点击“核对提交”，原回答正常送达并清除待确认状态，不要求停止跟踪或重新填写。再模拟服务器接受后丢失 HTTP 响应，刷新核对仍使用原记录，只有一次原生回合。旧记录按其原提交时间和 ID 确定兼容 ID，内容、账号快照不变；七天过期保护和账号变更保护仍生效，普通发送/确认文件沿用原路径。

性能：能力沿用缓存；凭据恢复快照附在既有 pending 请求响应，不新增轮询；每次显式结构化回答增加一次当前线程核对请求。状态最多 100 个线程，单条提示受限。采集候选首页与真实验收线程 profiler，复核重复请求与错误页。

清理/回退：临时认证容器按名称删除，保留失败线程和报告。仅回退候选应用镜像，不回退认证/撤销状态；旧版本仍可读取回答的普通用户消息。

## 2026-09-11 提问卡片固定在输入框上方

准备：虚构会话含长历史和未回答问题，浅深主题及 1440×1000、375×812、768×1024。

操作：滚动历史到顶部；展开/收起输入框；回答问题；切换会话并刷新。模拟回复失败和已接受但响应丢失，核对重试只提交一次。

预期：历史原位置没有问题卡片；待回答卡片位于输入框上方且不随历史滚动。多问题区域限制高度、内部滚动；选择、自填和暂不回答仍可用。失败保留卡片，成功移除；已答历史消息保留且无协议标记泄漏。卡片按会话/turn/问题序号隔离。

清理：关闭 fixture；无真实模型调用。性能：一次 computed 扫描问题和回答，复用现有消息数据，无新监听、轮询或请求。
