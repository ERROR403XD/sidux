# 0.1.90：持久调度与执行记录

前提：使用隔离的 `CODEX_HOME`，容器内测试目录 `/test-workspace/automation-0190`，时区 `Asia/Shanghai`。不要挂载真实 Vault，也不要复制真实日记。稳定 5900 保持运行。

1. 创建项目任务，使用虚构日记和固定日期范围，输出到同目录的 Markdown 日历；规则设为 `FREQ=MINUTELY;INTERVAL=2`。
2. 点击“立即运行”，连续重复同一个 `requestId` 请求。预期只有一条运行记录，先排队/运行，收到正常完成事件后才显示完成；会话中的文件产物与任务要求一致。
3. 关闭页面，等待下一计划时点。预期服务端仍自动执行，记录显示“定时”；再次执行检查同一个文件，不生成重复产物。
4. 暂停任务，等待当前运行结束，然后重启候选。预期记录、暂停状态和文件保留；已完成的 `runId` 不增加新执行，不重复提交。
5. 使用不存在的 cwd、无效 RRULE、损坏的 TOML、隔离的无效认证分别检查错误。预期有可见诊断；无效定义不会静默消失；不循环重试认证或业务错误。
6. heartbeat 目标正在运行或有普通消息排队时触发任务。预期自动化等待，不中断用户；账号操作期间不派发，自动化排队/执行期间账号切换被空闲检查阻止。
7. 模拟提交响应丢失后重启。预期通过运行标记及 `turnId` 核对已有会话，不重新调用 `turn/start`；无法确认则显示“中断，需检查”。
8. 查看执行历史，切换任务、刷新页面、打开执行会话及更早记录。预期时区明确，失败可检查后重试，多 cwd 的各目标状态独立，分页无重复或遗漏。完成表示模型回合完成，业务结果仍需核对文件。
9. 调用 `POST /codex-api/automation-runtime/drain`，正文 `{"draining":true}`。预期停止领取新计划，现有队列排空；新手动运行被拒绝。调用同一路由并传 `false` 恢复。
10. 在 1440×900、375×812、768×1024 查看浅色/深色界面，确认日志、错误和按钮可读，编辑器可滚动，时区保存后刷新仍保留。

时间规则：分钟和小时规则当前仅接受 INTERVAL，按实际经过时间计算；日/周规则支持 INTERVAL、BYDAY、BYHOUR、BYMINUTE、WKST，使用 IANA 时区。DST 不存在的本地时点跳过，重复时点只采用第一次。其他字段明确报错。首次接管只安排未来时间；停机最多补最近 24 小时内的一个漏跑时点，更多时点合并或标记漏跑。

自动验证：`pnpm run test:unit`；调度测试使用临时目录和可控时钟覆盖去重、恢复、时区、等待、重试与单实例锁。性能脚本 `scripts/profile-automations.ts` 默认运行 10 分钟，检查 1/10/100 个空闲任务不产生上游 RPC。

清理/回退：暂停验收任务并确认 `activeCount=0`、`queuedCount=0`；保留候选 volume 内的验收记录便于查阅。只删除明确创建的测试任务/目录。代码回退使用保留的 0.1.89 镜像；不得把候选认证复制到生产。真实周计划的自然触发验收安排在生产交接之后。

## 0.1.90 封测修订：5 条预览与完整历史

存储：原“每任务 100 条/30 天”只用于保持调度 state.json 较小；移出的终态先原子归档到 codexapp-automations/history，历史长期保留。分页只读取当前页文件，最多并发 8 次；通过创建时间和 runId 的组合游标处理同毫秒记录。自动刷新只更新 5 条预览，不重置弹窗的浏览页。

验证：`pnpm exec vitest run src/server/automationHistory.test.ts src/server/automation.test.ts`。清理仅删除创建的隔离 fixture，不能清理真实历史归档；回退应用时保留归档文件。

## 0.2.19：分段历史、恢复与旧版回退

前置：构建当前包，仅使用自己创建的临时 CODEX_HOME；不要在生产目录注入损坏。旧 history/history-keys 为兼容输入，当前归档写 history-v2。账号、认证、计划及热运行 state.json 格式不变。

操作与预期：

1. 运行 `pnpm exec vitest run src/server/automationHistory.test.ts src/server/automation.test.ts`。验证 207 条同毫秒记录的 100/100/7 分页、45 天跨段分页、热冷重复记录合并及重启后的 requestId 防重。
2. 运行 `node scripts/test-automation-history-recovery.cjs`。在 pending、事实、键副本、时间索引、ID 索引各次原子落盘后 SIGKILL 测试子进程，重启离线维护。五种中断均恢复原 runId，pending 清空，无重复记录，认证哨兵字节不变。
3. 单测分别删除一份永久事实、破坏另一份文件；有有效副本时仍识别旧请求，两份损坏时明确失败。旧键索引存在但正文丢失时禁止当作新请求发送。历史不能被自动清理为防重失效。
4. 在测试 home 运行调度器时执行 `node dist-cli/index.js automation-history --home <测试 home>`，预期拒绝维护；第二实例未取得调度锁时也不得通过历史查询启动写入恢复。
5. 确认目标实例停止后，执行同一命令重建派生索引；准备回退到旧包时，加 `--export-legacy`。预期生成旧格式完整副本，旧读取算法能查回原记录；新格式与旧源文件均保留。**旧应用不能读取 history-v2，必须先导出再回退。**

性能：每天的显示索引按需加载，最多缓存 32 天；页最多 100 条，正文最多并发 8 次。1,000 条/100 天本机测试归档约 1.19 秒，100 条分页中位 7.00ms/p95 7.95ms，键查询中位 0.10ms/p95 0.19ms；该结果不代表 NAS 或百万条历史。旧格式首次迁移需要逐条复制，可能延长自动化初始化，之后只核对目录元数据。

恢复边界：验证的是进程中断与文件损坏，不承诺未经实测的断电持久性；同时丢失全部事实及备份无法凭空恢复。旧源文件和新永久事实不自动删除；建议正常备份整个 CODEX_HOME。清理只移除本脚本拥有的测试子进程和临时目录。
