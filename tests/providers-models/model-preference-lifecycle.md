# 0.2.22 Q03 模型配置、偏好与重试生命周期

前提：使用本轮独立验证容器，或完成空闲 gate 后的 59001 候选。记录原连接、默认模型、推理强度、速度及“记住每个会话”设置。准备两个模型目录不同的测试连接；延迟/失败样本仅使用合成凭据和独立状态，不读取生产认证。

操作与预期：

1. 在已有会话选择模型和推理强度，刷新目录；暂时移除所选模型，查看有效回退，再恢复目录。原保存模型及强度不被回退覆盖，恢复后重新生效；界面不把运行时报告的模型当成新的手动选择。
2. 在空白新会话分别为 Codex 和 provider 选择模型，来回切换连接。每个来源恢复自己的选择；目录只来自该来源。保存的 Web 默认值保持，pending 会话的有效来源随当前连接变化。
3. 将配置读取或模型目录响应延迟，等待期间切账号、切会话或停止/重新启动客户端。释放旧响应后，当前目录、选中模型及错误不受污染；过期配置不追加旧目录请求，过期失败不追加重试。
4. 让当前模型读取失败；3 秒内不重试，3 秒后仅重试一次。再次失败不形成循环；停止后不执行重试，重新启动后的新刷新可立即读取。相同上下文的普通并发刷新共享配置/目录读取，所有调用等待目录完成；失败只安排一个重试，底层 catalog 继续使用原单一缓存。
5. 在支持/不支持相应能力的模型间切换强度与速度，检查模型、provider 隔离；不支持的速度或图片在发送前报原校验错误。浅色/深色显示均沿用原界面。
6. 在独立打包容器验证无认证 Zen fallback、畸形认证 fallback、Zen→OpenRouter 两次切换、无效 Codex 认证。原生认证失败在刷新后仍有一条持久错误行，重复 live 错误层为零；认证样本文件不变。

清理与回滚：恢复最初连接和 Web 默认设置。仅删除本次独立容器和临时 home；不清空 59001 标准卷。源码回退本批独立提交，不回写会话或配置格式。

自动化证据：`threadModelComposition.test.ts` 保留真实 desktop/metadata/model 装配；`threadModelController.test.ts` 覆盖 owner 合同、200 项偏好容量及十次重启；迁移 AST、完整构建、当前 Linux 包矩阵见 `docs/baseline/022/model-controller-20261012/`。模拟合同不等同于真实云成功、浏览器时延或用户人工验收。

## G6：并发模型刷新协调

前提：独立 `threads-201` fixture，当前源码验证服务 `127.0.0.1:4173`；浏览器 Network 保留日志。配置或目录延迟/失败仅使用请求拦截，不改用户账号。

1. 打开首页，同时触发路由选择和后台辅助刷新。配置未结束或目录未结束时，相同账号/会话/生命周期的普通刷新只有一次 `config/read` 和一次目录请求；两个入口均等到目录完成。
2. 等读取全部完成，再手动刷新。重新读取配置，不能沿用已经完成的请求。`includeProviderModels` 兼容提示不同仍按绑定 provider 的实际目录范围合并，不改变目录来源。
3. 在旧读取尚未完成时切换连接，连续两次显式连接切换仍各自读取最新配置。旧成功、旧错误均不覆盖当前目录/选择；旧请求结束后再触发普通刷新，不能误清除新账号的并发请求。
4. 拦截首次 `config/read` 为 503，等待恢复。3 秒后自动重试一次，错误消失并展示当前目录；再次失败不无限重试。停止客户端清掉重试 timer，重启后可立即读取。

预期：没有全局 TTL 或完成结果缓存；账号、会话、停止/重启和显式连接变化仍隔离，所有并发等待者收到同一轮完成结果。首页 profiler 的 `config/read` 为 1，list/skills 各 1，warnings 为空；队列/续跑的重连校准单独审计，不能直接跳过。

清理：关闭拦截页面，保留自有 4173 验证服务；只删除本轮独立容器和临时 home。回滚本批源码提交，不改偏好格式或持久数据。

前置：隔离 4173 验证环境，已有来源为 custom 或 custom_<id> 的历史会话；OAI 账号提供非空模型目录。

1. 在自定义连接中打开会话，再切回 OAI 并打开模型选择器。

4. 浅色与深色各执行一次，回归 Zen/OpenRouter 历史来源目录行为。

预期：自定义连接退出后不出现空白模型菜单；每轮使用单一目录请求，不先请求失效来源再兜底。
清理：关闭测试浏览器上下文，恢复测试连接；回滚本修复提交，不删除账号或会话数据。

## dev.4 全面审计：偏好同步和迟到目录

前置：隔离 4173；两个独立浏览器上下文代表两台设备，连接同一测试服务。使用 `node scripts/verify-022-preferences-drafts.cjs`；网络故障只拦截合成请求。

1. 设备一在 A 选择模型与强度，设备二打开 A，应恢复相同组合；设备二修改后，设备一刷新也应恢复。两设备各自草稿不得交换。
2. 拦截偏好 PUT 失败，手动选择后刷新页面并恢复网络。待同步修改应从本标签页重试记录恢复，服务端及另一设备最终显示新组合。
3. 首次读取远端偏好后离线刷新，本地缓存仍可提供之前读到的模型、强度和记忆开关；失败时有提示，读取/保存每次最多等待 5 秒。
4. 新会话模型请求延迟时手动切模型/强度，释放旧响应，保留新选择。连接切换失败、账号切换后配置失败时，不显示上一个来源的模型选项。
5. 关闭每会话记忆，当前会话临时选择另一组合；另一设备改变默认值，后台刷新不改当前临时组合，重新进入会话才应用新默认值。

性能：手动选择不额外读取配置或模型目录；连续同步写合并，只发送变更条目；远端读取落本地缓存不触发写回循环。草稿仍为浏览器本地存储，不增加逐键网络请求。
清理：关闭合成上下文，恢复测试默认值；不清空测试或生产账号。回滚对应提交，保留既有偏好文件。
