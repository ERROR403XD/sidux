# 0.2.0 动态模型能力、服务档位与兼容信息

前置：当前版本的隔离 4173 或 59001，独立 CODEX_HOME；保留原镜像和候选账号。使用目录夹具定义新模型 low/high/max/ultra、priority（显示 Fast）、文字/图片；第二个模型仅 high/文字，第三方服务仅返回 ID。测试不得写生产业务目录。

1. 在真实会话输入框选择新模型，打开强度：只显示目录项、默认项及已有但未确认的保存值。选择 ultra、通过输入框控制区的 Fast 开关启用快速模式；请求使用 priority，不能写 fast 或硬编码价格。再用 + 菜单的服务档位核对两处状态一致，切换档位不改变推理强度。
2. 切换第二个模型，只显示 high，图片输入有明确阻止提示；回到新模型，ultra/priority 恢复。刷新后模型选择和参数不变，运行时最近返回模型单独展示。
   0.2.10：不支持 Fast 的模型显示禁用状态；Fast 关闭后下一次请求清除覆盖值。375×812、768×1024 和桌面浅深主题下开关、发送按钮均可见且不重叠，排队消息保留入队时的选择。
3. 配置一个未知合法已保存强度。UI 保留并标注；目录明确不支持时阻止提交，草稿不清空；目录缺失时显示未知，不套用其他 provider 的能力。不自动展示未声明的 max/ultra。
4. TestChat 发送唯一标记、加粗文字、本地文件链接和网页链接，拦截并核对 turn/start 的 model、effort、serviceTier 和 collaborationMode.settings。刷新检查 hrefOk/titleOk/textOk。先 priority 后默认，后者必须显式发送 null。
5. 任务执行时排队，随后改变模型。服务器队列应保留入队时 model/effort/serviceTier；执行时使用原快照。旧队列不含参数时仍使用旧默认路径。编辑/排序仍遵循原消息 ID 事务规则。
6. 自动化编辑器选择新强度和服务档位，保存并刷新，TOML/API/UI 保留参数；指定另一个模型且使用默认强度/档位时不能继承原模型的 ultra/priority。运行记录可见已提交参数。
7. 模拟 MCP、动态工具、子任务、网页搜索、压缩和未知工具事件。运行中及刷新后有一致折叠摘要，不泄露原始 arguments 或整个结果；reasoning 的既有历史隐藏行为保持。
8. 打开设置中的“运行版本与能力”，核对应用版本、CLI 版本、schema 标识，以及客户端未接入项目。方法数不是支持率。并发读取只生成一次；检测失败可重试。
9. 账号/provider 切换或目录失效期间制造慢响应，旧返回不能覆盖新上下文；第三方服务目录错误不能借用上一 provider 能力。首页/短线程记录 model/list、provider-models、rateLimits 次数、总 API 字节和耗时。

UI 覆盖 Chromium/WebKit、1440×900、375×812、768×1024、浅深主题，截图保存在 output/playwright。Provider/Auth 工作流另跑打包镜像无认证、畸形认证、失效认证刷新、Zen→OpenRouter；失效错误刷新保留，重复 live overlay=0。

清理：测试线程/自动化限内部夹具；临时容器按精确名称停止，保留候选状态卷。候选回滚前检查空闲，只还原镜像，不覆盖认证、队列、自动化或草稿。生产 5900 另行授权后才切换。

启动去重回归：无认证 Zen 首页首次启动，provider 状态读取只更新设置显示，初始模型目录由统一初始化流程读取。实测 thread/list、skills/list、rateLimits/read、provider-models 各一次；用户后续切换 provider/导入认证仍触发完整失效刷新。

重连回归：保留页面并令隔离运行时重启或在通知夹具中发出第二次 ready；首次 ready 不额外读取目录，后续 ready 清除旧能力快照并刷新模型参数与配额。新目录生效，已有显式选择保留。测试后恢复连接与夹具，不能以重启生产服务制造此场景。
