## dev.4 变更摘要（相对 NAS 基线 0.2.20-dev.1 / b2fa900519fd）

1. 独立协议桥组件 `protocol-bridge/`（Responses ↔ Chat 双向流式转换，70 用例独立测试，9 份文档，demo 测试台）。
2. Chat-only 自定义连接经「协议转换」开关启用 Codex；responses-only 连接开桥后反向服务 `/v1/chat/completions`；开关不参与测试 digest、可免重测保存；关闭活跃连接的桥自动取消激活。
3. 能力 tag 三态：绿=原生、黄=经协议转换（连接卡片 + API 代理面板 key 处一致）。
4. API 代理 izitoast 通知：服务与账号保存、API key 保存配置（无变化静默）、创建/轮转/撤销 key。
5. **生产缺陷修复（新会话无法发送）**：`AccountResourcePool` 分配生命周期重构——每个分配有 45s 总超时与 abandon 机制（超时后链路必结算，后续分配立即重新开始）、候选 worker 空闲检查 5s 上限（单个挂起检查只跳过该候选并记入诊断）、回收等待真实子进程退出但有 15s 硬上限、池满/回收中/检查超时/初始化失败返回结构化 `WorkerPoolAllocationError`（code 可区分四类）；worker 异常退出时由 `onProcessExited` 立即释放池槽位并清理 ownership/pending；新增身份脱敏的 worker 池诊断（`GET /codex-api/worker-pools` + `[worker-pool]` 日志行）。前端：`submitFirstMessageForNewThread` 不再静默吞错（toast + 首页内联错误条，区分「会话运行资源已满，空闲会话正在回收，请稍后重试。」与「当前会话运行资源正在回收或暂时不可用，请稍后重试。」），120s 客户端看门狗保证发送按钮不会永久 pending，失败保留草稿；旧会话发送与 delivery 链路未改。
6. OpenAI 账号反代（CLI Proxy API）零改动；原生 Responses 链路（`unifiedResponsesProxy`）零改动。
