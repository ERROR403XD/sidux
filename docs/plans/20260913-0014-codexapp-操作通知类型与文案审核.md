# 操作通知类型与文案审核

本轮只调整 UI：通知的类型、颜色、图标、文字和显示时长。不为凑齐颜色增加提示，原本安静的操作保持安静。沿用 useOperationToast 与 OperationToastHost，不增加通知总线、模块分层或业务状态机。账号、额度、API 代理、出口、自动化的接口、请求参数、调度、防重、阻塞及放行规则均未修改。

## 用户确认的修改边界

- 这次颜色扩展只调整显示，不改变任何业务功能或代码结构；已有移除/清除确认属于此前单独批准的 UI 需求。
- 四类是供已有提示选择的语义，不要求每个功能都产生四种提示，也不要求为了展示黄色或灰色而增加新的触发点。
- 有明确操作结果的提示应准确细分；原本无需提示的操作继续保持安静，不增加例行成功提醒。
- 改色不改变请求次数、参数、重试、确认和关闭流程，更不能改变账号、额度、API、出口、调度及阻塞放行规则。

## 1. 四类操作通知

| 类型 | 显示 | 适用情况 | 示例 | 默认时长 |
| --- | --- | --- | --- | --- |
| success 成功 | 绿色勾 | 用户操作已确认完成 | 已保存、自动化任务已移除、连接已切换 | 3 秒 |
| error 失败 | 红色感叹号 | 请求失败或操作无法完成 | 保存失败、连接测试失败 | 6 秒 |
| warning 注意 | 黄色三角 | 已完成但存在后续问题，或结果/可用性需要核对 | 自动化任务已移除，但列表刷新失败；结果未确认，请刷新账号核对 | 6 秒 |
| info 普通信息 | 灰色信息图标 | 正常阶段状态、无需处理的空结果或已完成状态说明 | 自动化已加入队列、已打开授权页面、没有匹配技能 | 3 秒 |

颜色仅作用于边线、图标和倒计时，正文保持主题文字色。深色主题独立提供绿色/黄色 token；图标与辅助技术类型标签同时区分含义，不要求只靠颜色识别。保持最多 3 条、按文案/类型/会话作用域去重、悬停/聚焦暂停、离开后继续剩余时间以及 × 关闭。

移除前的确认按钮使用危险样式；移除完成仍属于操作成功，不能因为动作名包含“删除”就改成黄色。已入队只说明提交阶段，不表示模型处理或任务执行成功。黄色不代表额外放行，更不能据此自动重试不确定请求。此语义参考 [Carbon 通知规范](https://carbondesignsystem.com/components/notification/usage/)，信息色选择本应用的灰色 token，保持界面轻。

## 2. 现有通知逐类整理

| 功能/结果 | 本轮类型与文案 | 处置 |
| --- | --- | --- |
| 自动化移除 | 成功：自动化任务已移除 | 替换上层“自动化已更新”；列表、编辑器及普通项目联动移除一致 |
| 自动化启用/暂停 | 成功：自动化任务已启用 / 自动化任务已暂停 | 分开表达，不再共用“已更新” |
| 自动化写入完成但列表刷新失败 | 注意：对应完成结果 + 但列表刷新失败 | 只显示一条结果通知，保留行内刷新问题，不报成写入失败 |
| 自动化保存 | 成功：自动化已保存 | 保留专属结果 |
| 自动化编辑器立即运行受理 | 信息：自动化已加入队列 | 只将原有绿色提示改灰色；执行仍走原接口 |
| 自动化详情立即运行 / 历史显式重试受理 | 不新增短时通知 | 保持原有安静行为；请求失败仍显示原错误，不影响运行记录更新 |
| 目标保存/暂停/继续/清除 | 成功：目标已保存 / 已暂停 / 已继续 / 已清除 | 已有细分，不改为通用保存；目标冲突与失败继续红色 |
| 自定义连接测试/保存/切换/移除 | 成功：连接测试成功 / 连接已保存 / 连接已切换 / 连接已移除 | 切换不再误称“账号已切换” |
| GPT 账号新增/认证刷新/切换/移除 | 对应成功提示；失败仍红色 | 原有结果已区分；本轮不改账号操作 |
| 重置额度 reset | 成功：额度已重置 | 保留成功 |
| 重置额度 alreadyRedeemed / nothingToReset | 信息：该次重置已完成 / 当前没有可重置的额度窗口 | 正常结果不当失败，不触发额外请求 |
| 重置额度 noCredit / 无法识别的成功回执 | 注意：此重置机会已不可用 / 结果未确认，请刷新账号核对 | 仅改显示；未知回执继续保留原确认框，不能据此认定已重置 |
| 重置额度请求失败 | 失败：保留原错误 | 不用文案关键字猜测上游是否成功 |
| MCP 打开授权页 | 信息：已打开授权页面 | 不声称授权或连接已经完成 |
| MCP 重载、插件设置、技能安装/卸载/设置 | 对应成功结果 | 保持已有细分；实际失败仍红色 |
| 技能搜索无匹配 | 信息：没有匹配技能 | 正常空结果使用中性提示 |
| 通知设置保存/测试 | 成功：已保存 / 通知已发送；回执无结果时为注意 | 明确失败仍红色；不调整外部通知发送行为 |
| 分支创建 | 成功：分支已创建 | 保持目标会话作用域 |
| 普通偏好保存 | 成功：已保存 | 保持轻量，不强调本机 |

默认 notifyOperation 的类型仍为 error，既有异常 catch 不会因扩展类型而被静默降级。UI 根据明确返回字段选择类型；不全局替换用户内容，不根据错误字符串关键词自动改业务结论。

## 3. 与其他提示的边界

- 会话蓝/红/黄圆点分别承载未读、非手动中断、额度问题；阅读、忽略及活跃筛选暂留规则保持不变。它们不是短时操作通知。
- 会话错误、排队状态、目标限制、账号保护、运行历史等持久提示仍由原业务状态决定；不因 toast 消失而清除问题。
- PWA/浏览器系统通知、Telegram/Apprise 等外发内容、通知渠道和免打扰计划不在本次改色范围。
- 二次确认只增加操作前的 UI 确认。确认后的删除/清除仍调用原接口；取消不提交，忙碌时防重，不改变后台任务出口。

## 4. 验证与维护

单元测试覆盖四类生命周期、上限、去重和作用域；浏览器检查三档视口的浅深主题、辅助标签、暂停/关闭，以及真实组件的额度回执分类和自动化入队显示。受控请求断言沿用原 storageId、creditId、confirmed、idempotencyKey、automationId、target、kind、requestId，未增加业务请求。

最终构建、发布包、截图、prepare 路径及测试结果见 [[20260913-0012-codexapp-封版漏项补查与0.2.19交接]] 的本轮追加部分。后续只在明确的新通知场景选择四类之一；本轮没有增加持续告警系统或改变核心调度结构。
