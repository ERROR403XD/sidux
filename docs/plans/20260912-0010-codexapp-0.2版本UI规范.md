# CodexApp 0.2 版本 UI 规范

## 目标与适用原则

保持已接受的 0.2 视觉风格，让当前工作、状态和操作清楚，减少无用说明。沿用[公共组件约定](20260906-0016-codexapp-UI组件与代码风格约定.md)与[中英文术语](20260910-0013-codexapp-中英文术语约定.md)，加入 0.2.18 已确认的时间控件、可关闭功能提示、轻保存文案和自动化列表规则。

新页面和改动区域遵守本规范；历史组件按修改机会迁移，不能把规范整理扩大为未经确认的全站重设计。0.3 工作台仍在草案选择阶段，本文不预先决定其布局。

## 信息结构与文案

0.2.19 命令搜索只在草稿字符 0 开始的 `/` 生效；正文和空白后不唤起。空结果统一“无匹配命令”/“No matching commands”，删除继续输入和按原方式发送的提示。已有键盘操作提示与发送规则保留，不增加新解释层。

- 一级显示用户正在做的事；状态紧邻对象；次要细节进入详情。列表不堆提示词、实现名称和健康服务状态。
- “会话/conversation”用于用户界面，“thread”仅用于协议/内部标识；使用“回合/turn”“额度/quota”“额度重置/quota reset”“推理强度/reasoning effort”。
- “已保存”轻量表达草稿保存成功，不增加“本机”等解释，不使用成功弹窗打断输入。保存失败保留内容并提供复制/重试等有效动作。
- 不展示“工作树 codexapp”“调度器：运行中”；健康是默认状态，初始化、异常和 drain 状态仍需可见。
- 账号空状态保留必要入口，不在卡片和设置中反复添加“尚无账号，请从此面板添加”。无账号时不显示 fallback 模型加“已保存偏好不变”的说明串。
- 动作用具体动词：添加时间、移除、保存、重试、打开会话。错误说明失败对象与可执行下一步，避免把所有失败都写成“网络错误”。
- 不展示调试端口、存储实现、RPC 方法等信息，除非诊断界面需要。文案不得暗示通过换账号绕过额度或服务限制。

## 控件选择

| 场景 | 统一组件 | 约束 |
| --- | --- | --- |
| 模态流程 | `AppDialog` | 调用方控制 open/busy/error/save；正文滚动，footer 固定 |
| 锚点菜单 | `AppPopover` | body 下定位、视口约束、焦点/监听由 primitive 负责 |
| 普通单选 | `AppSelect` | 模型、账号、分支、语言、目录等禁用原生 select |
| 多选/技能实时建议 | 现有业务菜单 + AppPopover | 保留描述、多选与输入焦点语义，不套普通单选 |
| 描边动作 | `AppButton` | 默认 button；忙碌禁用；破坏性操作用 danger |
| 开关 | `AppSwitch` | 有可读标签与 switch 语义；避免只靠颜色表示 |
| 每日时刻 | `AppTimeInput` | 原生 `type=time`、一个字段、时钟入口；这是已确认的原生控件例外 |
| 可收起功能提示 | `DismissibleNotice` | 红字/alert + `×`，关闭按钮有“关闭提示”可访问名称 |
| 普通输入 | 原生 input/textarea + `app-input` | 具备 label；不为每个 HTML 元素额外建立包装层 |

`ComposerDropdown` 是兼容适配，新普通选择框直接使用 AppSelect。公共控件不请求接口或保存偏好，业务组件处理请求与错误。

## 颜色、字体、圆角与层级

颜色取自 `src/style.css` 的 token。以下为 0.2.18 基线；未来改 token 时同时验证所有共享页面。

| token | 浅色 | 深色 |
| --- | --- | --- |
| `--ui-surface` | `#fff` | `#18181b` |
| `--ui-text` | `#27272a` | `#e4e4e7` |
| `--ui-border` | `#d4d4d8` | `#52525b` |
| `--ui-divider` | `#e4e4e7` | `#3f3f46` |
| `--ui-field` | `#fff` | `#27272a` |
| `--ui-muted` | `#71717a` | `#a1a1aa` |
| `--ui-hover` | `#f4f4f5` | `#27272a` |
| `--ui-danger` | `#be123c` | `#fda4af` |
| `--ui-danger-border` | `#fda4af` | `#9f1239` |
| `--ui-focus` | `#6366f1` | 沿用共享 focus |

共享圆角：dialog 16px、popover 12px、control 8px。共享层级：dialog 16000、popover 16010；业务页面不要另起任意 z-index。焦点轮廓不能仅移除 outline。

设置/管理页面字号使用 section 16px、subsection 14px、control 13px、meta 12px；普通字段高度 36px，紧凑列表动作 32px。会话正文保留其阅读字号，不按控制面板字号全局缩小。标题一般 600 字重，普通按钮描边，不靠强填充增加层级。

大页面和共享路由的决定性深色样式写入 style.css，避免懒加载 scoped CSS 把深色字段改回白色。原生时间字段在深色下设置 `color-scheme: dark`；页面深色而字段浅色属于缺陷。

## 时间控件与时间列表

自动化每天运行、账号定时激活、POST/Telegram 免打扰统一使用 AppTimeInput。界面是**单个时间字段**，不使用两个小时/分钟输入框夹冒号。浏览器内部可能分段选择数字，但应用不拆成两个独立字段。

支持 `09:00`、`09：00`、`９：００` 等粘贴归一化；底层值为 HH:mm。有效范围 00:00–23:59；无效、空白和不完整输入应阻止业务保存，保留待修正输入或旧保存值。不能通过浏览器显示格式判断存储格式；不同地区可能显示 AM/PM。

基线几何：时间列表字段宽 104px；免打扰字段宽 96px、高 32px。免打扰标签与 switch 间距 12px，switch 分组与时段分组列间距 20px、换行行间距 10px。保留“至”连接两个时间，窄屏允许分组换行，不能挤压 switch 或让时间字段占满整行。

每天运行和定时激活都采用标题 + “添加时间”，每行一个时间字段和右侧“移除”，最多 24 项；添加按钮达到上限时禁用，保存时去重排序。列表内字段左对齐、移除按钮位置稳定，不因单条文案长度跳动。

![每天运行多时间的 0.2.18 已验收控件](assets/0.2.18/0218-multitime-candidate-detail.png)

高级 RRULE 保留 textarea，以容纳多行精确每日规则；不能转成列表的高级约束不可静默丢弃。界面时间列表必须对应真实持久化与刷新结果。

## 提示、错误与轻状态

| 类型 | 表现 | 关闭语义 |
| --- | --- | --- |
| 草稿成功 | 低强调“已保存”，靠近输入框 | 无需额外关闭；不抢焦点、不弹 toast |
| 临时功能错误 | 对应操作附近，红字 + `×` | 仅隐藏本条；新消息可再显示 |
| 字段校验 | 字段附近文字/边框与 aria-invalid | 用户修正后清除，不能隐藏后保存无效值 |
| 持久失败回合 | 保留在会话历史，可刷新核对 | 关闭上方 notice 不删除历史 |
| 问题/审批 | 输入区域附近清晰可操作卡片 | 不能用关闭错误的方式自动回答或批准 |
| 保存/请求忙碌 | 相应按钮 busy，必要时“保存中…” | 防双击；失败保留表单，不假装保存成功 |

当前 DismissibleNotice 按 message 变化重置关闭状态；同一字符串如果只是重复赋值不会产生新的提示实例，需要调用方明确区分新事件。不要靠全局清空所有错误恢复界面。

“已保存”当前基线为 11px、低强调；失败时提高可见性并保留复制退路。不得增加额外磁盘写入/轮询来驱动这个文字。

## 自动化列表与详情

列表主信息为名称、计划及必要状态，长名称省略，完整内容在详情查看。使用直接开关控制启停，不再并列重复的编辑/暂停说明和提示词预览。列表切换后保持当前排序至刷新，避免用户刚点击的行移动。

详情承担提示词、执行会话、错误与历史。立即运行与启用计划是两个动作；操作完成后更新对应任务，失败保留旧状态并显示错误。正常调度器不占用额外状态栏，异常仍需定位到任务或调度器。

筛选/搜索工具栏允许搜索框伸缩，刷新按钮保留可点击宽度；不把按钮压成图标残片，也不人为拉大按钮之间空白。

## 弹窗、浮层、响应式与可访问性

- AppDialog 默认宽度上限 760px，compact 460px；手机边缘至少 8px。正文可滚动，标题和底部动作稳定。
- Esc 按层级处理：搜索词清空、浮层关闭、弹窗关闭；忙碌时按组件规则禁关。Tab 在模态范围循环，关闭回到触发器。
- 只接受完整背景点击关闭；拖选文本、从面板拖到背景、右键不误关。复用现有 backdrop 指令，不新写一套 document listener。
- Popover 使用 fixed 视口坐标，ResizeObserver/scroll/resize 通过 RAF 合并；关闭/卸载移除监听并取消迟到测量。
- 账号弹出区避开固定账号卡片；内部滚动，不遮住用户再次点击的入口。手机软键盘出现时保持输入和待回答卡片可操作。
- 图标按钮有 aria-label，开关有文本标签，时间列表每项有序号或可区分名称；禁用、错误、忙碌不只通过颜色表达。
- 中文/英文长文案均允许合理换行；检查控件宽度，不按某一个语言的短词硬编码整个表单。

## 验收标准

针对真实改动界面检查，不用侧栏预览或基础首页代替表单。纯文档更新不重跑 UI；真正改动时按仓库规则执行：

| 检查 | 必须确认 |
| --- | --- |
| 浅深主题 | 表面、字段、浮层、禁用、错误均一致，无白块 |
| 桌面 1440×1000 | 表单对齐、按钮间距、列表截断、焦点顺序 |
| 平板 768×1024 | 容器缩放、弹窗与账号弹出区不越界 |
| 手机 375×812 | 时间分组换行、无横向溢出、软键盘和待答区域 |
| 双语言 | 标签与状态翻译完整，英文长文本不挤压控件 |
| 交互 | 点击/Enter/Esc/Tab、开关、添加/移除、上限、无效输入 |
| 保存 | 请求次数符合操作；成功刷新保留；失败保留旧值与草稿 |
| 状态 | 已保存不等于已发送；关闭提示不等于取消任务或审批 |
| 性能 | 不增加重复请求、全局监听或高频布局循环；构建体积可解释 |

优先 Browser Use；需要拦截、故障注入、storage 修改时使用 Playwright CJS。测试 URL、视口、断言、绝对截图路径和内联图片写入验收记录。截图前等待 2–3 秒稳定；断言失败先修复再报告。测试目录见 `tests/theme-layout-terminal/` 及相关功能域。

本规范引用的多时间截图源于之前已完成的 0.2.18 UI 验收；0.2.19 已单独验证命令菜单的浅深主题与三种视口，未声称再次验收全部 UI。[开发记录](20260912-0003-codexapp-0.2.18修复与59001开发验收.md)保存其完整证据。

## 0.2.19：状态筛选与圆点

活跃筛选按一次开启周期保留观察到的运行会话，完成或停止后待用户查看并切走再清理；重新开启只取当前运行项。蓝点仍表示未读，阅读清除。红点表示尚未忽略的普通异常，黄点表示尚未忽略的额度异常；阅读、刷新和后续成功不清除问题。存在多项问题时黄色优先，三种点沿用相同约 6.67px 圆形。运行与审批图标继续使用原优先级。

最终错误正文复用“忽略/已忽略”操作，会话菜单提供“忽略全部问题”，保存失败不伪装成功。中断筛选包含红黄问题，当前选中行仍保留到切走。不得把筛选、阅读或忽略直接映射为取消执行、修改额度续跑、账号切换或重新投递。
