本次只整理边界和规约，不覆盖或改动源码。现场核对结果如下：

## 2. 目录职责

| 目录 | 职责 | 约束 |
| --- | --- | --- |
| `/mnt/NAS02-Code/Sidux` | 唯一源码树、Git 分支、开发、测试和提交 | 先确认 NFS 挂载；不与另一系统同时写入；不从旧树覆盖 |
| `/home/Code/codexapp` | 迁移前旧树、历史对照和恢复参考 | 不作为开发入口；不直接复制其未审查改动或 `.git` |

本机辅助目录当前预留 `deployment/`、`prepare/` 和 `output/`，分别用于非敏感部署说明、临时 prepare 材料和验证输出。它们可以清空重建，不应反向同步为源码。

## 3. Windows 与 Ubuntu 交替开发

两种系统都操作同一个 NFS 源码路径，不建立“Windows 一份源码、Ubuntu 一份源码、最后手工拷贝”的双主模式。

每次切换系统时按以下顺序交接：

1. 当前系统停止开发服务器和测试写入，检查 `git status --short --branch`，提交应提交的代码和文档，或明确记录尚未提交的文件。
2. 下一个系统先确认 NFS 可访问，再检查分支、HEAD、工作树和 `package.json` 版本；发现未预期改动时先停下核对，不执行 `reset --hard`、批量覆盖或清理。
3. 只在 NFS 工作树执行 Git 操作。若确实需要从旧目录取回内容，先做逐文件 diff 和目标清单，再由用户确认后处理。
4. 交接记录使用提交号、版本号、测试命令和结果，不以“文件已经复制”作为完成依据。

`node_modules/`、`dist/`、`dist-cli/`、`output/` 以及 `node-pty` 等原生依赖带有系统/架构属性，不属于跨系统源码交接。Windows 和 Ubuntu 切换后，必须在当前系统按锁文件重新安装或重建目标依赖；不能把 Windows 的 `node_modules` 当作 Linux 部署依赖。必要的临时缓存和验证输出放在 `/home/Code/Sidux`，不要把它们混入源码提交。

## 4. 本机最终部署

Windows 可以完成开发验证、文档和交接，但不替代 Ubuntu 本机的最终部署验收。最终部署必须满足：

- 在 Ubuntu 本机使用与目标平台匹配的 Node.js、依赖和发布产物完成 `prepare`；
- 发布目录具有 `.codexapp-release-ready`，并通过精确目录的 `check`；
- 从独立终端完成真实空闲检查后，才可在获得明确授权时执行 `activate`；
- 激活后检查 systemd 实际引用的发布目录、5900 服务和真实页面/API 行为；
- 不从 Windows 工作目录复制认证、账号、会话或 `CODEX_HOME`，也不因迁移改动本机持久状态。

Linux 侧的典型交接形态如下，`<release>` 必须替换为本次命令输出的精确绝对路径：

```bash
cd /mnt/NAS02-Code/Sidux
git status --short --branch
git log -1 --oneline --decorate

sudo env \
  CODEXAPP_SOURCE_DIR=/mnt/NAS02-Code/Sidux \
  bash /mnt/NAS02-Code/Sidux/scripts/codexapp-release-switch.sh prepare

sudo env \
  CODEXAPP_SOURCE_DIR=/mnt/NAS02-Code/Sidux \
  bash /mnt/NAS02-Code/Sidux/scripts/codexapp-release-switch.sh check <release>
```

`prepare` 只生成并检查候选发布物，不自动授权生产切换。激活、回退、5900/59001 维护和发布目录清理继续遵守 [NAS 源码与版本轮换部署约定](20260918-0001-codexapp-NAS源码与版本轮换部署约定.md) 及 release-switch 脚本的现场门禁。

## 5. 禁止事项

- 不把 `/home/Code/codexapp`、Windows 临时拷贝或 `/home/Code/Sidux` 当作第二个权威源码树。
- 不在 NFS 未挂载、工作树状态不明或存在未审查差异时进行覆盖、prepare、activate 或清理。
- 不把平台依赖、构建输出、日志、测试截图和本机部署状态当作源码迁移成功的证据。
- 不把凭据、令牌、账号池、会话数据库或私密日志写入本项目或本机辅助目录。
- 不因本次目录迁移修改生产认证、服务持久状态或现有 5900/59001 运行边界。
