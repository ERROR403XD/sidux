## 追加：侧边栏状态标签筛选

用户继续开发 0.2.18，新增项目/会话区顶部的“活跃中、未读、中断”标签。采用能力认证 tag 类似的紧凑外观，单选，再次点击取消；选中标签白字、白边框。无“全部”标签、无常驻说明文字。

筛选仅隐藏会话和无匹配会话的项目，保留项目归属、固定区、会话区、当前排序与折叠状态，不创建独立结果列表。内部始终保留完整 groups 和 pin 数据，避免被隐藏的固定会话遭清理。

- 活跃中：复用现有 inProgress 标志，不按账号占用或历史活动推断。
- 未读：直接复用蓝点。点击前记录暂留 ID，蓝点正常确认已读；当前会话继续显示，切到另一会话才移除。状态放在 App 层，手机收起侧栏导致组件卸载后仍有效。取消筛选清除暂留，刷新默认不筛选。
- 中断：只判定最后一回合的 failed/interrupted 与额度错误；成功、进行中、普通手动停止和认证错误不匹配。不使用自动续跑标记推断，不扫描历史中的任意错误。读取未知时展示可重试错误，不当作确定中断。

### 实现与调度边界

新增只读 `POST /codex-api/sidebar-thread-status`，每批最多 100 个 ID。服务端读取原生 `thread/turns/list`，`limit=1`、倒序、`itemsView=notLoaded`；没有全文、工具输出或图片内容。只对已结束的失败/中断回合补充同一回合的流错误，不能把已经成功的回合重新标成额度中断。

## 自定义连接会话恢复修复（POE）

### 问题与实现

自定义连接会话在 rollout 中保存 `custom_<storageId>`。切回普通账号后，会话 worker 按当前出口重新创建；原恢复请求却继承历史 provider，而当前 worker 没有该定义，导致 thread/resume 返回 502 / Model provider not found。

恢复和分支请求现在显式传入当前 worker 的 provider；发送前自动恢复也使用同一路径。自定义 worker 直接使用自己的连接 ID，普通 worker 通过原生 config/read 获取实际 provider。保留已有模型参数，不注册其他账号的 provider，不写认证，不更改账号选择、调度准入或全局阻塞规则。

## 账号切换后的会话恢复与 Terra 偏好污染

### 原因与修复

前次修复处理后端 provider 注册问题，但页面仍保留旧身份下的已恢复缓存、加载失败短期缓存及在途请求；切换成功后 refreshAll 可以直接复用旧状态。另一个独立问题是普通会话在当前账号不提供 Astra 时，把回退 Terra 写回会话选择，导致切回 A/刷新仍为 Terra。
