# CodexApp 现有功能说明

本文描述 0.2.19 封测版本已具备的能力。实际会话、文件与工具运行在服务主机，浏览器是操作界面。原生 Codex、账号类型及连接的能力不同，具体可用模型、工具、压缩和历史操作以界面能力判断为准。

追加复审的四项确定问题已修复，当前候选及 823 项回归结果见 [[20260913-0011-codexapp-0.2封测复审问题修复与回归]]。保留的安全、长期运行与客户端验证边界仍适用。

## 1. 入口总览

| 入口 | 能力 |
| --- | --- |
| 首页与侧栏 | 创建/导入项目、打开目录、创建会话、项目归组、搜索与状态筛选 |
| 会话页 | 流式消息、附件、Markdown、工具结果、计划、问题、审批、队列、引导、历史和分支 |
| 会话/项目菜单 | 改名、置顶、归档、导出、项目关联、自动化等；受具体对象与能力约束 |
| 自动化页 | 任务列表、搜索、启停、详情、编辑、立即运行、执行历史 |
| 账号卡片与设置 | 账号、额度、连接、模型偏好、定时激活、通知、语言、外观和反馈 |
| API 出口 | API 配置、key、模型、活动、用量、账号和连接出口 |
| 扩展入口 | 技能、插件、应用与 MCP 能力发现、状态和按需详情 |
| 文件/变更/终端 | 文件浏览与编辑、Git 变更、交互 PTY、后台终端和 Hook 过程观察 |

0.3 项目主导工作台仍是设计阶段，现有应用继续采用侧栏项目/会话管理。两份新设计稿不表示其中所有界面已经实现。

## 2. 项目与会话组织

新建项目可填写名称和目录，也可以只提供名称。仅名称项目同样显示在侧栏，使用抽象组织层级的开/关图标，操作待遇与普通项目一致。

仅名称项目由 CodexApp 保存展示关系。创建、改名、归组、排序或移除这种组织，不创建一个对应项目文件夹，不改变已有会话 cwd、文件、账号、权限、AGENTS 或实际工作方式。新会话使用原有无项目会话工作目录分配方式，然后显示在所选项目下面。组织自身没有伪造的 Git 根或共享工作区。

可以把已有无项目会话归入项目；同 cwd 的相关分支沿用相应展示归属。移除组织后会话回到无项目列表，已有文件和会话仍在。关联自动化也保留，继续按原账号、执行条件和普通无项目目录分配方式运行；如需删除任务，在自动化页显式操作。显式导入、导出则按既有规则读取或创建副本，这与创建展示组织是不同操作。

有目录项目继续支持已有主目录、附加目录、文件浏览、Git/worktree、克隆与 ZIP 导入导出。项目多目录上下文使用 AGENTS.md 受管区域，保留用户其他内容。目录路径对应服务主机，不能把浏览器本机路径当作主机目录。

## 3. 输入与消息

支持普通文字、Markdown、代码、图片/文件引用、技能、模型与推理强度选择，以及原生能力允许的协作模式。消息流式显示，工具和计划按类型展示，文件和浏览链接可打开对应目标。

草稿在现有保存机制成功后轻量显示“已保存”，清空后消失。保存失败保留内容并提供复制方式；复制正文不等于备份附件二进制。

从空草稿开始输入 `/` 可搜索命令；输入正文后再打 `/`、移动光标回开头、粘贴或恢复 `/plan` 不会自动弹出搜索。无结果显示“无匹配命令”。开启后可继续查询、键盘选择，Esc 关闭。扩大输入框后菜单位于输入区中部稍靠下，窗口缩放时位置随之更新，草稿及选区保留。

会话忙碌时支持排队和引导。队列可按当前状态编辑、调整、移除或引导；最终能否发送仍由服务端执行与审批门禁决定。点击引导后，内容在正文立即出现并标明提交/等待/处理/待确认等真实状态；切换、刷新、接口短暂失败仍保留显示。原生回显到达后按身份替换显示记录，避免重复，不能仅因为文字相同就合并两次输入。

浏览器持久存储写满时，已受理引导的显示记录降级保存在当前标签页，仍支持切换会话和刷新；原生回显后清除。关闭该标签页，或持久存储与标签页存储同时不可写时，不保证这份显示副本仍在；这不改变实际发送结果。

“待确认”表示实际发送结果尚未核实，不表示发送失败。不要把刷新、关闭显示或暂时没看到回复当作可以安全重发的证据。

## 4. 问题、审批、长任务与历史

工具审批和阻塞问题需要明确处理，关闭临时提示不会代替批准。异步问题支持选择和自由回答，回答失败保留已输入内容；提问卡片、回答投递与原生阻塞状态各自按真实结果更新。

原生支持时可使用目标/预算、暂停与继续、上下文压缩，以及父子任务导航、引用和摘录。预算与压缩语义由原生能力决定，界面不把不支持的状态伪装成可执行。

会话历史分批加载，侧栏搜索支持标题与有界正文检索，结果范围会受已加载/可读历史影响。可以按可用能力复制、导出或分支；某些正在进行的会话不能直接复制时，需要使用分支等允许的操作。功能性临时错误有 × 可关闭，再次发生仍会显示。

## 5. 活跃、未读与中断

| 筛选/标记 | 当前行为 |
| --- | --- |
| 活跃初次开启 | 只纳入当时符合活跃标准的会话，旧未读蓝点不单独纳入 |
| 活跃开启期间 | 期间观察到的活跃会话完成、额度/网络中断或手动停止后暂留 |
| 阅读并切走 | 已结束的暂留会话从本次活跃结果中移除 |
| 关闭再开启/刷新 | 重新按当前活跃计算，旧暂留集合清空 |
| 蓝点 | 已完成未读，阅读后取消 |
| 红点 | 尚未忽略的普通最终异常，阅读后仍保留 |
| 黄点 | 尚未忽略的额度异常，阅读后仍保留；存在多类问题时优先显示 |
| 中断筛选 | 包含尚未忽略的异常；对尚未发现的旧会话按需读取最终回合 |

普通异常与额度异常均可在错误正文忽略/撤销忽略，会话菜单可忽略当前已有的全部问题。保存失败保留原圆点；新发生的问题不被旧忽略覆盖。后续成功回合不会自动清除尚未处理的问题。

阅读、问题忽略和活跃暂留互相独立。忽略不关闭额度续跑、不恢复额度、不换账号、不取消任务，也不会触发重发。手动停止本身不新增红黄问题。

问题忽略保存成功后即可继续处理其他会话；摘要读取卡住不会持续锁住按钮。请求超过 10 秒会结束界面等待并保留必要错误，未确认成功的问题不自动清除，也不自动重试写入。

## 6. 自动化

支持推进指定会话的自动化，以及基于项目执行目录创建会话的定时任务。可保存计划、提示词、模型、默认或固定账号/出口、启停状态；服务端在页面关闭时继续调度。仅名称项目的自动化仍创建普通无项目工作目录的会话，并登记展示归属。

每天运行支持多个时间，最多 24 个，排序去重；例如 08:15 与 18:45 只对应这两个时点，不交叉产生 08:45/18:15。仍是同一任务与执行历史。单时间和旧高级规则保留兼容，无法完整表示的高级规则不强行转换为简单每日列表。

立即运行与启用计划是两个动作。任务同时受账号、额度、会话忙碌、审批与全局资源边界约束；被阻止不代表任务消失。取消准备会先反馈，但共享原生操作若无法取消，其资源和占用仍要等真实结束，不能用超时绕过阻塞。

多个漏跑按现有合并规则处理，不建立无界补跑队列。历史按任务分页读取，长期运行记录和防重事实保留。历史损坏或调度器无法取得所有权时停止不安全的执行；维护与回退步骤见 [[20260913-0008-codexapp-0.2封测验收与运行维护]]。

## 7. 账号、连接、模型与额度

账号卡片和设置展示账号、认证与额度；支持已有的登录/添加/切换/移除、额度刷新与模型偏好。默认偏好与当前会话实际模型分开，已有固定账号执行不因切换界面选中账号而漂移。

原生 Codex 账号、自定义连接、OpenCode Zen/OpenRouter 等路径沿用各自能力与协议适配。模型、推理强度、Fast、输入类型等按当前连接能力显示，不把所有提供方假设成完全一致。

额度保护与额度恢复续跑保持既有规则。续跑要经过实际额度、账号与目标忙碌检查，稳定投递 ID 防止重复提交。账号移除、凭据刷新及正在执行的任务之间仍受资源归属与互斥约束。

## 8. 定时激活与通知

账号定时激活可选择账号和多个每日时刻，默认关闭。它使用最小 API 请求，不创建普通会话，启动时不补跑过去时点。账号正在使用、凭据变更、缺少最新额度、没有适用五小时窗口或窗口不满足条件时跳过；发送前再次检查。显示请求已发送不等同已经观察到额度窗口启动。

POST 和 Telegram 等通知渠道具有各自配置、测试和结果；支持免打扰。所有时间统一为带时钟的单一输入控件，支持中英文冒号/全角数字粘贴归一化。网络结果不明时并非精确一次送达承诺，不能以重复通知尝试影响执行链。

## 9. API 出口与开发辅助

API 出口提供现有 key、模型访问、Responses、流式/SSE、WebSocket、用量与活动管理，以及固定账号和连接出口。管理页登录与 API key 是不同权限入口；未携带有效 key 的 API 请求仍需拒绝。长连接和正在处理的请求继续计入活动，供账号协调和发布交接检查。

扩展目录提供原生支持的技能、插件、应用与 MCP 信息和按需详情。旧的整站连接器目录、Composio 专用界面与 GitHub 技能自动同步已不属于当前产品入口，不等于删除所有原生扩展能力。

文件浏览、HTML/SVG 预览、文本编辑、Git 变更、交互终端和原生后台终端仍可使用。手动主动内容预览保留当前同源风险；普通文件链接和终端权限并未因此改变。后台 processId 不等于操作系统 PID，不能拿界面 ID 直接 kill。

## 10. 外观、PWA、反馈与适用边界

支持中英文、浅深主题、侧栏与输入布局偏好及现有品牌外观。设置隐藏无帮助的正常状态文案，异常与必要决策仍保留。

PWA manifest 已声明 focus-existing。支持该浏览器能力时，重复启动使用已有窗口；不存在时创建新窗口。本轮没有增加跨窗口抢焦点代码，也没有承诺不支持该 manifest 字段的浏览器具有相同行为。

反馈入口生成可预览、编辑和复制的最小诊断报告，不自动发送给别人。报告不采集会话正文、账号凭据、路径或完整错误原文。

本轮确认的是封测代码、隔离候选和相应测试。真实云账号正常消费、自然额度重置、多日连续调度及真实设备软键盘不等于本地自动化测试；其验证边界和已知保留项在封测验收页明确列出。


## 封版漏项补查（2026-09-13）

空目录项目和仅名称项目收起后均只保留标题行，不显示“没有会话”；展开空项目仍保留原空状态。鼠标、Enter、空格和刷新后的状态一致。 详见 [[20260913-0012-codexapp-封版漏项补查与0.2.19交接]]。
