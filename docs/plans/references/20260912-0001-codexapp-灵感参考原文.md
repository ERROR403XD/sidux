**Codex WebUI 功能规划说明**

基于 CodexApp 0.2.14 当前能力的后续功能建议

文档日期：2026-09-10

# 1. 文档目的

本文档用于说明 Codex WebUI 在现有功能基础上可继续增加的功能模块。内容以功能定义、可执行操作和实际用途为主，不讨论产品定位、宣传表述或视觉风格。

现有版本已经具备项目与会话管理、模型与推理设置、历史搜索与分支、Goal、子任务、Git/worktree、终端与后台进程、Hooks、账号池、API 出口、自动化、插件/技能/MCP 等能力。以下内容主要描述这些基础能力之上的新增管理、编排、观测和安全功能。

# 2. 当前能力基线

| **领域**   | **现有能力概述**                                                                              |
|------------|-----------------------------------------------------------------------------------------------|
| 会话与项目 | 实时回复、历史分页、搜索、分支、Goal、压缩、异步问题、审批、项目与项目外会话。                |
| 账号       | 多账号隔离、登录与重新认证、账号切换、额度窗口、恢复通知、定时激活、账号移除。                |
| API        | Responses、Chat Completions、HTTP/SSE/WebSocket、模型目录、Key 管理、固定账号绑定、用量统计。 |
| 自动化     | 持久定义、手动/定时执行、账号与模型选择、运行历史、失败/取消状态、有界并发。                  |
| 扩展       | 插件安装/卸载/启停、授权链接、项目技能、MCP 状态与详情、重载与 OAuth。                        |
| 项目工具   | Git/worktree、应用终端、原生后台终端、Hooks 观察、导入导出。                                  |

# 3. 项目工作区与信息组织

| **功能**               | **主要能力**                                                                                                            | **典型操作**                                                         | **用途**                                                         |
|------------------------|-------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------|------------------------------------------------------------------|
| Project Workspace 首页 | 为每个项目提供统一首页，汇总分支、worktree、未提交改动、活动会话、运行中 Goal、后台进程、自动化、待审批事项和最近错误。 | 进入项目后直接查看当前状态；从首页跳转到对应会话、进程或任务。       | 减少在会话、终端、Git 和自动化页面之间切换；提供项目级状态入口。 |
| Thread 树与分类        | 以父子关系、分支关系和任务关系组织会话；支持标签、收藏、归档和状态分类。                                                | 查看主任务及其子任务；按“设计、开发、测试、Review、废弃”等标签筛选。 | 解决大量 thread 仅按时间排列时难以理解任务关系的问题。           |
| 项目对象关联           | 将 thread、Goal、自动化、worktree、commit、后台进程和产物挂接到项目。                                                   | 从任一对象反查所属项目和相关对象。                                   | 建立统一的项目级资源模型，方便导航与检索。                       |
| 项目模板               | 保存项目启动时需要的默认账号、模型、推理强度、技能、MCP、权限和常用命令。                                               | 新建项目时选择模板；已有项目应用或更新模板。                         | 减少重复配置，并确保同类项目使用一致环境。                       |

# 4. 上下文与项目记忆

| **功能**                  | **主要能力**                                                                                                          | **典型操作**                                                                     | **用途**                                               |
|---------------------------|-----------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------|--------------------------------------------------------|
| Context Inspector         | 显示当前请求实际包含的系统指令、AGENTS.md、技能、MCP、引用历史、压缩摘要、文件上下文、Goal 和 Git diff 等上下文来源。 | 发送前或运行中查看“本轮实际使用了什么”；定位未加载的文件或配置。                 | 帮助判断模型回答是否因上下文缺失、错误注入或压缩造成。 |
| Working Set / Context Pin | 允许将文件、目录、文档或上下文片段固定为某个 thread 的持续工作集。                                                    | 固定关键源码；临时移除；查看被模型建议加入或移除的上下文。                       | 避免长会话中关键材料因上下文变化而丢失。               |
| Project Memory            | 维护项目级长期知识，例如架构约定、部署方式、关键决策、禁止方案、常用命令和已知问题。                                  | 从历史会话提取候选记忆；人工确认；编辑、禁用或锁定；新 thread 自动加载相关内容。 | 跨 thread 保留稳定项目知识，减少重复解释。             |
| 记忆来源追踪              | 每条项目记忆保存来源 thread、消息、commit 或文档位置。                                                                | 点击记忆查看形成依据；发现错误时回溯并修订。                                     | 提高长期记忆的可审计性。                               |
| 上下文占用分析            | 按系统指令、历史消息、工具输出、代码、文件、压缩摘要等类别显示 token 占用。                                           | 查看当前上下文组成；定位占用过大的日志或文件。                                   | 用于控制上下文大小和排查压缩行为。                     |

# 5. 代码变更、版本和回滚

| **功能**              | **主要能力**                                              | **典型操作**                                                          | **用途**                                   |
|-----------------------|-----------------------------------------------------------|-----------------------------------------------------------------------|--------------------------------------------|
| Change Set 面板       | 按回合、Goal 或任务集中展示新增、修改、删除文件及 diff。  | 查看逐文件 diff；接受、撤销单个文件或整组改动；跳转到产生改动的消息。 | 将代码修改从聊天文本中独立出来，便于审核。 |
| Checkpoint / Snapshot | 在重要执行前保存 Git 状态、相关配置、工作目录和任务状态。 | 手动建立检查点；Goal 开始时自动建立；失败后回滚。                     | 为长任务提供明确恢复点。                   |
| 会话与 Commit 关联    | 记录 commit 与 thread、Goal、变更回合之间的双向关系。     | 从 commit 查看产生原因；从 thread 查看最终进入哪些 commit。           | 便于后续追踪代码来源。                     |
| Commit 分组与生成     | 根据 Change Set 建议合理的 commit 拆分，并生成提交说明。  | 按功能拆分修改；预览 commit 内容；用户确认后提交。                    | 避免多个不相关修改混入同一 commit。        |
| Release Center        | 统一展示生产版本、候选版本、commit、验收结果和部署记录。  | 部署候选版本；切换生产；查看版本差异；执行回滚。                      | 适合维护 WebUI 自身或其他可部署项目。      |

# 6. 任务、Goal 与多 Agent 编排

| **功能**                         | **主要能力**                                                                            | **典型操作**                                                           | **用途**                                   |
|----------------------------------|-----------------------------------------------------------------------------------------|------------------------------------------------------------------------|--------------------------------------------|
| Task Board                       | 将开发任务作为独立对象管理，并可关联 Goal、thread、agent、branch、worktree 和验收条件。 | 创建任务；设置状态、负责人、依赖和优先级；从任务启动新 thread。        | 在会话之外维护项目级工作列表。             |
| Agent DAG                        | 使用有向依赖图表示并行和串行子任务。                                                    | A/B 并行完成后触发 C；测试失败后生成修复节点；查看每个节点状态。       | 支持复杂任务的结构化并发执行。             |
| Agent 角色模板                   | 为架构、实现、测试、Review、调研等角色配置模型、推理强度、工具权限和默认提示。          | 选择角色启动子任务；限制 Reviewer 只读；测试角色允许执行测试但不提交。 | 减少重复配置，并控制不同代理的权限边界。   |
| Handoff                          | 把一个 thread 的成果结构化移交给另一个 thread。                                         | 生成目标、已确认事实、关键文件、决策、未解决问题和验收条件摘要。       | 避免新 thread 依赖完整旧聊天记录。         |
| 结构化验收条件                   | 将验收项、测试命令、预期结果和证据保存为任务对象。                                      | 逐项执行；记录通过/失败；关联日志、截图、commit 和文件。               | 用于版本验收、回归测试和自动生成验收报告。 |
| Plan / Execute / Review 工作状态 | 在同一任务中区分只分析、实际执行和结果审核三个阶段。                                    | Plan 阶段禁止写文件；Execute 允许执行；Review 汇总 diff、测试和风险。  | 控制任务阶段的工具权限和输出形式。         |

# 7. 运行环境与后台进程

| **功能**               | **主要能力**                                                         | **典型操作**                                                                 | **用途**                              |
|------------------------|----------------------------------------------------------------------|------------------------------------------------------------------------------|---------------------------------------|
| Environment Hub        | 统一展示应用终端、原生后台终端、服务进程、端口和最近活动。           | 查看 PID、命令、所属 thread、端口、启动时间、日志；停止或重启。              | 统一管理 Codex 启动和遗留的后台服务。 |
| 进程归属追踪           | 每个后台进程记录启动它的账号、thread、Goal、automation 或 API 请求。 | 从进程跳回来源任务；从任务查看仍存活的进程。                                 | 用于判断进程是否仍需要保留。          |
| Port / Preview Manager | 自动识别 HTTP 服务和端口，并提供预览入口。                           | 将 4173、5900、59001 等端口命名；iframe 预览；外部打开；生成移动端访问入口。 | 管理多个开发预览和候选环境。          |
| 资源使用观察           | 记录长时间运行进程的 CPU、内存、运行时长、最后输出和退出码。         | 定位异常占用或长期无输出进程。                                               | 帮助管理无头服务器上的长期运行任务。  |
| 命令历史与复用         | 保存项目常用终端命令并标记执行结果。                                 | 从历史重新运行测试、构建和启动命令；保存为项目命令。                         | 减少重复输入并保留执行记录。          |

# 8. 可观测性与故障诊断

| **功能**              | **主要能力**                                                                 | **典型操作**                                                                      | **用途**                               |
|-----------------------|------------------------------------------------------------------------------|-----------------------------------------------------------------------------------|----------------------------------------|
| Activity Timeline     | 按时间统一记录消息、工具调用、文件读取、终端命令、子任务、自动化和后台事件。 | 按 thread、Goal、账号或时间筛选；定位任务停在哪一步。                             | 提供跨模块的执行时间线。               |
| 全局 Active Runs 页面 | 展示当前所有活动会话、自动化、API 请求、后台终端和执行租约。                 | 查看正在运行的对象及账号占用；跳转、停止或取消。                                  | 提供系统当前负载和活动状态。           |
| Request Inspector     | 展示标准化后的请求参数和生命周期信息，同时脱敏认证信息。                     | 查看账号、模型、reasoning、Fast、cwd、request id、状态、首 token 时间和结束原因。 | 用于排查请求参数、路由和上游错误。     |
| Debug Bundle          | 收集版本、CLI 版本、OS、错误日志、请求 ID、进程状态和匿名化配置。            | 一键生成 Markdown/ZIP 诊断包。                                                    | 方便提交 issue 或交给 Codex 自己分析。 |
| 错误聚合              | 对重复出现的认证、额度、SSE、网络、插件和终端错误进行归类。                  | 查看最近发生次数、受影响账号和首次/最后发生时间。                                 | 避免同类错误散落在多个 thread 中。     |
| 性能指标              | 记录请求延迟、工具耗时、首 token 时间、模型目录刷新耗时和自动化执行耗时。    | 按账号、模型、版本查看统计。                                                      | 用于定位 UI、服务端或上游性能变化。    |

# 9. 账号、额度与路由管理

| **功能**       | **主要能力**                                                                     | **典型操作**                                                               | **用途**                                 |
|----------------|----------------------------------------------------------------------------------|----------------------------------------------------------------------------|------------------------------------------|
| 账号健康页     | 集中显示认证状态、上次刷新、模型目录刷新、最近错误、最近成功请求和当前执行租约。 | 快速判断某账号是否可正常执行。                                             | 替代在多个页面分别检查账号状态。         |
| 额度与窗口预测 | 在已有额度数据基础上显示当前窗口、恢复时间和近期消耗趋势。                       | 估算当前任务是否可能跨窗口；在启动长任务前给出提示。                       | 用于计划账号使用，不自动替用户切换账号。 |
| 显式路由策略   | 允许项目、API Key、自动化或任务绑定明确账号策略。                                | 项目 A 固定账号 1；Automation 固定账号 2；额度低于阈值时暂停新任务并提示。 | 在保持账号选择透明的前提下减少手动选择。 |
| 账号使用审计   | 记录账号被哪些 thread、自动化、API Key 和时间段使用。                            | 查看最近一天或一周的账号执行来源。                                         | 用于排查额度消耗来源。                   |

# 10. API Gateway 与开发调试

| **功能**       | **主要能力**                                                             | **典型操作**                                                | **用途**                                           |
|----------------|--------------------------------------------------------------------------|-------------------------------------------------------------|----------------------------------------------------|
| API Playground | 在 WebUI 内直接构造 Responses、Chat Completions、SSE 或 WebSocket 请求。 | 选择 Key、账号、模型和参数；查看原始请求、响应及 SSE 事件。 | 用于测试 WebUI 自身 API 出口和第三方客户端兼容性。 |
| API 请求日志   | 记录脱敏后的请求元数据、状态码、耗时和绑定账号。                         | 按 Key、账号、模型、端点、状态筛选。                        | 用于查看出口使用情况和失败模式。                   |
| Clone & Replay | 复制历史请求并修改参数后重新发送。                                       | 复现 401、500、SSE 中断等问题；对比不同模型或参数。         | 降低 API 故障复现成本。                            |
| Key 权限策略   | 为不同 API Key 配置模型、端点、账号、来源和限额。                        | 限制 Key 只能访问指定模型或账号；设置日请求数/token 上限。  | 使 WebUI 可作为可控的个人/局域网 API Gateway。     |
| 兼容性测试套件 | 保存常用客户端的标准测试请求并自动执行。                                 | 版本升级后测试 Responses、Chat、SSE、WS 和模型目录。        | 用于检测 app-server 或 CLI 升级造成的兼容回归。    |

# 11. 自动化与工作流

| **功能**               | **主要能力**                                                     | **典型操作**                                                          | **用途**                                     |
|------------------------|------------------------------------------------------------------|-----------------------------------------------------------------------|----------------------------------------------|
| 事件触发自动化         | 除定时任务外支持 webhook、文件变化、Git 事件、测试结果等触发源。 | 收到 webhook 后启动 Goal；目录出现文件后运行处理流程。                | 支持事件驱动任务。                           |
| 自动化流水线           | 允许多个自动化节点按依赖顺序执行，并传递产物。                   | 录音转录→分类→写入笔记→归档；构建→测试→部署。                         | 把多个独立任务组合为可观察的工作流。         |
| Human-in-the-loop 节点 | 工作流在需要人工确认时暂停并生成待处理项。                       | 确认覆盖文件、提交 Git、发送外部内容或继续高风险命令。                | 在自动化中保留明确的人为控制点。             |
| Dry Run                | 保存自动化前使用当前配置模拟执行路径。                           | 显示账号、模型、cwd、权限、可能读写目录和预计步骤。                   | 检查配置错误和潜在副作用。                   |
| 自然语言配置生成       | 用自然语言生成结构化自动化定义，再由用户确认。                   | 输入“每天凌晨处理昨天录音”，生成对应 schedule、账号、模型和任务步骤。 | 降低复杂自动化配置成本，同时保留结构化定义。 |
| 工作流重试与补偿       | 为不同节点设置重试、超时、失败分支和清理动作。                   | 上传失败重试；后续节点不执行；失败后移动临时文件或恢复状态。          | 提高长流水线可靠性。                         |

# 12. 扩展、权限与安全

| **功能**                | **主要能力**                                                       | **典型操作**                                                         | **用途**                             |
|-------------------------|--------------------------------------------------------------------|----------------------------------------------------------------------|--------------------------------------|
| Secrets Vault           | 集中保存插件、MCP、API 和项目运行需要的敏感凭据，并按 scope 分配。 | 设置全局、账号、项目、自动化级 secret；仅允许替换，不回显完整值。    | 降低凭据散落在配置文件中的风险。     |
| Permission Profile      | 定义文件、Shell、网络、插件和 MCP 的可用范围。                     | 项目只读项目外目录；Reviewer 禁止写文件；Automation 只能写指定目录。 | 把工具权限从提示词约定变成系统约束。 |
| Filesystem Sandbox 视图 | 在 UI 中显示当前任务可访问的根目录和读写权限。                     | 查看 NAS、NFS、项目目录是否为只读或可写。                            | 避免对文件访问范围的误判。           |
| 插件/MCP 权限追踪       | 记录工具未调用或调用失败的具体原因。                               | 显示未安装、未授权、scope 未启用、能力不支持或运行报错。             | 便于排查扩展不可用问题。             |
| 扩展使用统计            | 统计 skill、插件和 MCP 的调用次数、失败率和平均耗时。              | 识别长期未使用或经常失败的扩展。                                     | 用于扩展清理和性能分析。             |
| Skill Test Harness      | 提供技能测试输入、注入内容和调用结果视图。                         | 修改 skill 后运行固定测试用例并比较结果。                            | 用于 skill 开发和回归测试。          |

# 13. 搜索、导航与操作效率

|-----------------|-----------------------------------------------------------------------------------------|------------------------------------------------------------|----------------------------------|

| Saved Views     | 保存常用筛选条件。                                                                      | 例如“今日失败自动化”“项目 X 未完成任务”“账号 2 最近执行”。 | 重复查看同类状态时减少筛选操作。 |

# 14. 移动端、通知与共享

| **功能**      | **主要能力**                                                                 | **典型操作**                                        | **用途**                     |
|---------------|------------------------------------------------------------------------------|-----------------------------------------------------|------------------------------|
| 移动监督模式  | 移动端重点提供任务状态、审批、问题回答、diff 摘要、服务停止/重启和账号状态。 | 手机上处理等待确认项，不承担复杂代码编辑。          | 适合无头服务器远程监督。     |
| 统一通知中心  | 集中处理 Goal 完成、自动化失败、额度恢复、等待审批和服务异常。               | 网页、PWA 或外部通知渠道均跳回具体对象。            | 避免通知与实际任务状态分离。 |
| Shareable Run | 生成经过脱敏的只读执行记录。                                                 | 分享任务摘要、diff、测试结果和日志，不包含 secret。 | 用于协作、问题复现和审阅。   |
| 多用户权限    | 为未来多用户环境预留 Admin、Developer、Viewer 等角色。                       | 限制用户访问的项目、账号、Key 和敏感操作。          | 支持局域网或小团队共享部署。 |

# 15. WebUI 自身维护与升级

| **功能**                 | **主要能力**                                             | **典型操作**                                                     | **用途**                       |
|--------------------------|----------------------------------------------------------|------------------------------------------------------------------|--------------------------------|
| Self-update 检查         | 检测 WebUI、Codex CLI、app-server 协议和依赖版本变化。   | 显示可升级版本及变更范围。                                       | 减少手动检查版本。             |
| Schema / Capability Diff | 比较升级前后的 experimental schema、模型能力和接口字段。 | 标记字段新增、删除、类型变化和当前代码受影响位置。               | 在升级 CLI 前识别兼容性风险。  |
| 候选环境验证             | 升级先部署到候选端口或实例并运行固定验收套件。           | 测试账号登录、模型目录、Responses、SSE、WS、自动化、插件和终端。 | 避免直接替换生产实例。         |

# 16. 建议实施优先级

如果后续开发以“提高长期使用效率和可管理性”为目标，可以按以下顺序实施。该排序主要考虑功能之间的依赖关系，不代表必须一次完成。

| **优先级** | **主要功能**                                                                 | **实施依据**                                                                           |
|------------|------------------------------------------------------------------------------|----------------------------------------------------------------------------------------|
| P0         | Project Workspace 首页、Environment Hub、全局 Active Runs、Activity Timeline | 这些功能直接复用现有项目、会话、进程、自动化和账号状态，主要工作是统一数据模型和展示。 |
| P1         | Thread 树、Context Inspector、Working Set、Change Set、Checkpoint            | 形成项目管理、上下文管理和代码变更审核的基础。                                         |
| P2         | Project Memory、Task Board、结构化验收、Handoff、会话-Commit 关联            | 建立跨会话的长期项目知识和任务生命周期。                                               |
| P3         | Agent DAG、角色模板、自动化流水线、事件触发、Human-in-the-loop               | 在已有子任务和自动化执行能力上增加编排层。                                             |
| P4         | API Playground、请求日志、Key 权限策略、Secrets Vault、Permission Profile    | 完善 API Gateway、权限和安全管理。                                                     |
| P5         | Release Center、升级验证、Schema Diff、多用户与共享                          | 适用于项目成熟后继续增加部署、升级和协作能力。                                         |

# 17. 总结

后续功能可以归纳为五类：项目级信息组织、上下文与记忆、任务与执行编排、可观测性与故障诊断、权限与运行环境管理。现有 0.2.14 已经提供会话、账号、API、自动化、扩展和终端等执行基础，因此后续重点可以放在统一对象关系、状态可视化、跨会话持久信息和工作流管理，而不需要重复实现底层执行能力。
