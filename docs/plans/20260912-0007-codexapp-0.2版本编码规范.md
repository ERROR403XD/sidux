# CodexApp 0.2 版本编码规范

## 适用范围与执行方式

适用于 0.2.18 及后续 0.2 维护版本。以仓库 `AGENTS.md`、[术语约定](20260910-0013-codexapp-中英文术语约定.md)、[UI 规范](20260912-0010-codexapp-0.2版本UI规范.md)为依据，补充服务端状态机、调度、持久化和依赖规范。适用于新增或正在修改的代码，不授权全仓重排格式。

本文写的是应遵守的要求；已有不符合项在[审阅报告](20260912-0006-codexapp-0.2系统代码审阅.md)跟踪，不代表当前代码已全部符合。每个改动应能回答：谁拥有状态、哪个入口触发、如何取消、失败后能否重试、持久化是否完成、怎样验证不重复执行。

## 分层与接口

| 层 | 可以承担 | 不应承担 |
| --- | --- | --- |
| `components/common` | typed props/emits、焦点、几何、基础外观 | RPC、路由、账号选择、保存业务数据 |
| 业务 Vue 组件 | 展示、表单草稿、用户操作、错误/忙碌状态 | 创建常驻后端调度器、读取主机文件 |
| composables | 复用的前端状态、订阅生命周期、界面适配 | 混入无关领域的全局状态或服务端凭据 |
| `api/codexGateway` 与 RPC client | 请求协议、错误归一化、DTO → UI 映射 | 猜测用户意图、自动批准操作、绕过服务端台账 |
| `server/*Runtime` 与 bridge | 协议适配、执行归属、能力检测 | 在传输适配器里另写一套任务状态机 |
| engine/service/store | 调度和投递语义、串行写入、校验 | 拼装 Vue 文案和复制 UI 控件逻辑 |
| 纯领域模块 | RRULE、时间、额度、标记、数据校验 | 隐式访问 global/window、RPC、磁盘 |

一个持久状态文件只能有明确写入者。共享类型表达领域事实，不把协议字段改成中文。跨边界输入从 `unknown` 校验；已有 `any` 可在修改路径收紧，但不为静态整洁重写无关协议层。

公共接口使用显式类型和返回值。新增状态需要定义转换、刷新恢复和失败语义；避免靠多个 bool 组合出无法解释的隐式状态。返回给前端的数据使用快照，避免外部修改内部 Map、数组和 run 对象。

## TypeScript / Vue 写法

- 新增共享代码两空格缩进，显式导入，Vue 使用 `script setup lang="ts"`；props/events 均具名、类型化。
- 处理函数描述动作，例如 `saveAutomation`、`releaseAccountLease`；不用同一 `handle()` 承担多个领域。
- 一条语句完成一个状态转换；复杂 async、catch、finally 展开为块。异常路径应与正常路径一样易读。
- 使用纯函数表达验证、时间转换、指纹计算；相同格式只保留一个实现来源，例如 `timeInput.ts`、`automationDailyTimes.ts`。
- `catch {}` 仅用于明确可忽略的观察、清理或兼容失败，注释说明理由；不能吞掉发送/写入失败后继续显示成功。
- 命名空间清晰：`threadId` 是协议标识；用户文案为“会话/conversation”；回合为 turn，额度为 quota。
- 不引入只服务一个用例的万能表单、规则执行器或插件框架。抽象应有明确责任和现实复用点。

## 并发、调度与生命周期

1. 串行段只保护共享状态读取、领取与提交；网络探测、历史读取、子进程启动不应长期占用全局控制队列。以 revision/runId/lease token 检查迟到结果。
2. 所有跨网络、RPC、进程的等待都有端到端 deadline 和取消责任。超时只代表调用者停止等待；若底层仍可能完成，必须清理迟到资源并禁止迟到提交。
3. 并发上限和公平性同时设计：自动化当前为 4，会话 worker 池 16，API component 池 8；按批扫描应轮转，不能永久只访问数组头部。
4. 定时器可合并 tick，不能无界排队；新建 interval、监听器、订阅、AbortController、RAF 和 Observer 时同时实现释放路径。浏览器组件关闭后不能保留失效监听。
5. dispose/close 能阻止新准入，等待或取消自己的工作，释放租约；不得批量停止其他实例进程。若无法确认清理，应返回可观察的未完成状态。
6. 发布 drain 的边界包含用户回合、队列、审批、自动化、API、账号定时激活和后台终端。先冻结新准入再读活动；未知、读取失败、分页截断都不能当作空闲。
7. 显式区分 drain 与暂停任务。当前 automation drain 拒绝新手动/定时领取，但会继续处理既有 queued 记录；改变这个语义须同步交接脚本与测试。
8. 不用自动换账号、改路由或扩大并发绕过额度、安全拒绝或服务限制。额度与认证问题反馈当前事实和可用恢复操作。

0.2.19 已实现 SCH-01 激活发布门禁、SCH-02 定期 inspect 隔离与迟到结果防护、SCH-04 续跑轮转。SCH-03 已贯通 90 秒准备期限、取消与 adapter 所有权：新建资源核对真实退出，共享且不可取消的已发操作继续保留租约至返回。发布活动计数必须追踪底层尚未结束的准备/发送/清理，不能只数 Promise.race 外层。详见[0.2.19 收口验收](20260912-0014-codexapp-0.2.19稳定性收口与验收.md)。

## 发送、重试与持久化

发送前必须生成稳定请求标识并持久领取。网络返回丢失时保留 `unknown`，通过原生 turnId/clientId/运行标记核对；不能以“暂时没看到结果”判断可重发。只有确认没有发送，或用户检查后明确重试，才进入新的提交路径。

| 场景 | 要求 |
| --- | --- |
| 双击或页面重试 | 复用 requestId/deliveryId，指纹相同返回既有结果；不同内容冲突要拒绝 |
| 编辑、移除与发送竞争 | revision 校验；过期编辑不能覆盖已发送状态 |
| 写入失败 | 保留原数据与草稿；停止需要持久保证的执行，反馈失败 |
| 原子更新 | 同目录唯一临时文件 + rename；写前验证所有权；finally 清理临时文件 |
| 断电保障 | rename 不自动等于 fsync；若承诺断电耐久，另行设计并验证文件和目录刷盘 |
| 状态损坏 | 校验 version、必需字段、状态枚举；fail closed，不静默清空重建导致重放 |
| 数据迁移 | 可恢复、可重复执行、稳定幂等键；保留未知 TOML 扩展字段 |
| 历史归档 | 先归档再从 hot state 移除；分页有界；保留去重所需索引/tombstone |
| 时间 | 绝对时刻使用毫秒明确命名；外部秒值在边界转换，禁止混用 |

自动化、消息投递和通知的语义不同。通知当前选择“结果不明不自动重发”，可能丢失，不能宣传精确一次送达。冷历史清理必须和幂等保证一起设计。

## 账号、凭据与执行安全

- 账号凭据由 AccountAuthCoordinator/Store 管理；执行连接领取固定身份 lease，凭据 revision 变化需要重新确认。不要让 UI、任务记录或组件缓存持有 refresh token。
- 用户会话、自动化、API、定时激活均登记资源归属；账号移除必须关闭该账号连接并取消迟到提交，不影响无关账号。
- 认证文件和私有状态使用受限权限；诊断记录分类、状态码、操作阶段，禁止原样写 Authorization、Cookie、完整上游错误体、个人会话或截图进公开包。
- 执行外部命令优先 `spawn/execFile` 的参数数组，不拼 shell 字符串；git 路径与选项边界明确。实际终端是用户明确授权的 shell 入口，与后台命令拼接分开审阅。
- HTTP/WebSocket 必须在同一认证模型下工作；API key 和管理登录分别处理。`/v1` 的独立 key 校验不能被管理页本地信任替代。
- 仓库 HTML/SVG 属于主动内容。0.2.19 为保持现有手动预览/编辑兼容，明确保留同源主动内容风险；新增自动或内嵌预览必须先实现独立来源与能力边界。链接编码、HTML 转义、脚本来源隔离是不同责任，不可相互替代。
- `v-html` 只能接收经明确转义/白名单处理的生成结果；用户文本与 URL 协议验证分开进行。反馈报告必须允许用户预览后再分享。

## 性能要求

每项行为改动至少提交一种证据：请求数量、代码路径和复杂度、构建体积、耗时、trace 或 profiler。文档本身不需要性能测试。对 startup/thread/routing/API/filesystem/git/loading 改动检查：重复请求、阻塞、并发上限、大载荷、缓存失效。

- 前端复用通知传输与请求 in-flight；无关数据分别加载/失败/重试，不能一个 `Promise.all` 失败隐藏全部内容。
- 列表先摘要，详情按需；历史按页，昂贵数据有大小和并发边界。长列表不要每次渲染读取主机目录。
- 本地缓存必须有身份、配置或 revision 维度；账号/模型切换后旧响应不能覆盖新状态。
- 不为了“轻”另加轮询、复制已保存草稿或上传反馈；沿用现有保存成功结果显示“已保存”。
- 记录对比环境和数据规模。开发服务器一次首页 21.4 KiB 不代表生产大历史也只需要这么多；warnings 为空仍需看完整 apiSummary。

## 测试与完成条件

| 改动 | 必须覆盖 |
| --- | --- |
| 调度/队列 | 时间边界、重复领取、崩溃恢复、超时/晚到、取消、并发上限、公平性 |
| 状态/文件 | 损坏文件、写失败、旧版本迁移、revision 冲突、原子更新失败恢复 |
| 账号/provider/chat 错误 | 仓库规定的隔离 Docker 打包矩阵；不以真实账号默认发请求 |
| UI | 真实改动界面、浅深主题；响应式变更覆盖 375×812、768×1024；持久化变更刷新后验证 |
| 聊天解析/文件链接 | TestChat 唯一标记，验证 href/title/text，保存截图 |
| 包/runtime/module | 先 build，再 CLI 和公共 CJS 依赖入口；终端涉及真实 PTY，不止 `require` |
| 文档 | 路径/链接存在、内容与实现一致；Obsidian 挂载和字节一致性 |

使用现有测试框架，给已确认 bug 增加能阻止回归的断言；不为简单可逆样式改动堆砌镜像实现测试。手工用例放在 `tests/<domain>/`，写前提、精确操作、期望、清理；`tests.md` 只做索引。

常用验证：`pnpm run test:unit`、`pnpm run build`、`git diff --check`。未用检查目前有 69 处历史诊断，作为清理清单；新增/修改文件不应增加新的未用声明，不为“过检查”整体关闭 strict 或扩大 suppress。

## 运行依赖与复装

0.2.19 将直接运行/可选依赖固定到已验证的原版本，不顺带升级。prepare 必须保留该安装目录生成的 package-lock.json；从该锁文件执行 npm ci --omit=dev，复核实际运行依赖和真实 PTY。锁文件记录该次准备结果，不代表不同日期的 prepare 自动得到相同间接版本。最低 Node 版本需单独验证；本次仅在 Node v24.19.0 验收。

## 提交与发布

每个可独立审阅子任务单独提交，说明具体触发、行为变化和验证结果。先检查 live git/worktree/合并状态；不覆盖别人的改动。存在 GitHub PR 路径时遵守仓库合并流程；对外评论和发布必须有对应授权。

59001 使用独立 CODEX_HOME；5900 `/root/.codex` 是生产边界。prepare、check、activate 三者分开；prepare 验证实际包、缓存、PTY，核对并清理本次验证进程。发布路径固定，依赖解析结果可追溯。公共快照、内部 Obsidian 文档、个人状态不得混入同一发布产物。

结束报告分别说明：已改、已验证、已知问题、未验证范围、部署是否生效。不得用“单测通过”替代浏览器实测或真实云端验收，也不得把 `skipped-busy` 写为空闲。


## 0.2 长期维护约束

UI 展示组织、未处理问题和消息回执投影不能改写原生 cwd、任务状态或账号租约。阅读确认与问题忽略分别建模；超时与真实资源释放分别确认。自动化永久请求事实不得随分页缓存淘汰；迁移与派生索引恢复须持有调度锁。回退旧格式应用前先离线导出兼容副本，保留新旧事实。常规准备/查询不能顺手重构账号切换、API 出口或调度互斥链。
