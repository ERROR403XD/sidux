# CodexApp 项目版本功能演进与当前能力

本文依据当前仓库的 Git 历史、各版本实施/验收文档和 0.2.14 源码整理。版本表示代码能力，不等于该版本已发布 npm 或已切换生产 5900。0.2.14 的独立候选运行于 59001，运行证据见[本版开发验收](20260910-0001-codexapp-0.2.14账号执行架构与开发验收.md)。

## 项目主线

项目从 Codex app-server 的浏览器界面，逐步扩展为包含项目/会话管理、工具交互、账号池、API 出口和自动化调度的本地应用。0.2.0—0.2.9 主要完善会话协议和可靠性；0.2.10—0.2.13 根据日常使用反馈修复出口、额度和界面；0.2.14 把账号执行隔离提升为共享架构，并收敛扩展管理入口。

## 0.2.14 当前能力与边界

| 领域 | 当前能力 | 需要区分的边界 |
| --- | --- | --- |
| 会话 | 实时回复、Markdown/文件/图片、模型与推理、Fast、队列/引导、异步问题、审批、历史分页、搜索、分支、Goal 与压缩 | 发送确认、回合完成、目标完成是不同状态；未知结果先核对 |
| 账号 | 多账号隔离存储、本地别名、链接/Device 登录、重新认证、切换、按实际窗口预留额度、恢复/重置机会通知、定时激活、移除 | 没有随机轮询或偷偷换账号；移除切断该账号连接，历史保留 |
| API | 默认出口和 Key 固定绑定、HTTP/SSE/WS、压缩、目录、Key 用量与生命周期 | 固定绑定不随主账号漂移；所选账号的模型权限、认证和额度仍由上游决定 |
| 自动化 | 持久定义/运行记录、手动/定时、模型与账号选择、失败/取消终态、有界并发 | 会话池最多 16 个进程、自动化并发最多 4 个，同一目标避免重叠；未知提交不自动重发 |
| 扩展 | 设置中的原版插件安装/卸载/启停/授权链接；双分类布局、本地搜索筛选、项目技能；MCP 状态、按需详情、重载与 OAuth | 原版接口能力检测；插件/服务可能需要各自权限或授权，新会话采用最新配置 |
| 项目与工具 | 本地项目与项目外会话、导入/导出、Git/worktree、应用终端、原生后台终端与 Hooks 观察 | 暂存/准备部署不等于生产激活；后台命令与 HTTP 流有独立生命周期 |

账号设置、分项通知、无 5h 窗口保护与双分类页面的追加验收见 [账号设置与扩展页面复核](20260910-0004-codexapp-0.2.14账号设置保护值与扩展页面复核.md)。

## 已移除或替代的能力

- 内建隧道与启动强制登录：本机维护阶段移除，沿用既有可信内网访问方式。
- GitHub 技能仓库同步：0.2.14 移除页面、登录和后台自动同步/推送。普通技能安装、搜索及原版插件市场不因此移除；历史技能文件保留。
- Apps 全量目录页：0.2.14 移除。该页访问上游连接器目录，403 不能推断所有已安装插件不可用。插件需要的服务授权链接在插件详情中显示。
- 应用内 Composio：0.2.14 移除页面、安装/登录/连接接口和 `@composio/client` 依赖；GitHub 登录专用 Firebase 依赖一并移除。生产全局技能、凭据和其他应用不属于此项删除范围。
- 全局单一自动化执行账号：由按账号独立的原生运行资源替代；API 与自动化共用选择/所有权/撤销规则。
- 两行模型选择器：0.2.14 改为单行“模型名 + 推理强度”，弹层同时提供模型搜索与强度选择。
