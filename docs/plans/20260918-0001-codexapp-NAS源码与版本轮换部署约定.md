## 2. prepare 产物位置

源码树与发布产物分离：

```text
/mnt/NAS02-Code/Sidux          # 外部开发、测试和提交
/mnt/NAS02-Code/Sidux-release  # prepare 发布产物交换区
```

每次 `prepare` 必须把完整发布目录写入：

```text
/mnt/NAS02-Code/Sidux-release/codexapp-<version>-<commit>-<YYYYMMDD-HHMMSS>/
```

发布目录中的 `.codexapp-release-ready` 是可切换门槛。已生成的发布目录视为不可变版本：不要在其内直接改文件、不要复用目录名；需要修复时从新的提交重新 `prepare`。至少保留当前运行版本和上一个可回退版本，确认没有服务或切换事务引用后再清理更旧目录。

`latest-prepared` 位于执行 `prepare` 的主机本地状态目录，不在 NAS 交换区中同步。因此本机激活和回退都必须使用 NAS 上的精确绝对路径，不依赖 `latest`。

## 3. 外部开发和 prepare

在 NAS 副本上开发时，先确认路径、分支和工作树；不要未经检查执行 `reset --hard` 或覆盖未提交内容：

```bash
cd /mnt/NAS02-Code/Sidux
git status --short --branch
git log -1 --oneline --decorate
```

完成代码提交、测试和版本确认后，在具备 Node.js、pnpm、npm 且可执行 root 命令的环境中运行：

```bash
sudo env \
  CODEXAPP_SOURCE_DIR=/mnt/NAS02-Code/Sidux \
  CODEXAPP_RELEASE_ROOT=/mnt/NAS02-Code/Sidux-release \
  bash /mnt/NAS02-Code/Sidux/scripts/codexapp-release-switch.sh prepare
```

以命令输出的具体发布目录作为交接值，并在交接时检查：

```bash
findmnt -T /mnt/NAS02-Code/Sidux-release
test -f /mnt/NAS02-Code/Sidux-release/codexapp-<version>-<commit>-<timestamp>/.codexapp-release-ready
```

GitHub 尚未发布 `0.2.20-dev.1` 的专用标签或分支；这不影响本地 NAS 基线。若之后需要多人从远端协作，再由维护者从该基线创建并推送明确命名的分支或标签，不在本约定中自动公开实验版本。

## 4. 本机从 NAS 轮换到新版本

本机生产服务仍使用本机既有运行状态和认证目录；切换只改变服务代码目录。每次操作都显式指定 NAS 交换区和精确发布目录：

```bash
RELEASE_ROOT=/mnt/NAS02-Code/Sidux-release
RELEASE="$RELEASE_ROOT/codexapp-<version>-<commit>-<timestamp>"

sudo env CODEXAPP_RELEASE_ROOT="$RELEASE_ROOT" \
  bash /home/Code/codexapp/scripts/codexapp-release-switch.sh check "$RELEASE"

sudo env CODEXAPP_RELEASE_ROOT="$RELEASE_ROOT" \
  bash /home/Code/codexapp/scripts/codexapp-release-switch.sh activate "$RELEASE" --confirm-idle
```

`check` 报告仍有活动回合、页面或其他运行任务时，先结束任务并关闭 CodexApp 页面，再从独立终端重试；不能用 `--confirm-idle` 绕过实际空闲门禁。`activate` 成功后，systemd drop-in 会直接引用 NAS 发布目录。

## 5. 回退

正常回退使用最近一次成功激活事务记录的上一版本，不手动复制认证文件或删除状态目录：

```bash
RELEASE_ROOT=/mnt/NAS02-Code/Sidux-release
sudo env CODEXAPP_RELEASE_ROOT="$RELEASE_ROOT" \
  bash /home/Code/codexapp/scripts/codexapp-release-switch.sh rollback --confirm-idle
```

如果要切换到指定的历史发布目录，应先检查该目录仍存在且 ready 标记有效，再按第 4 节对该绝对路径执行 `check` 和 `activate`。回退前同样需要真实空闲；回退不会删除 NAS 发布目录。

## 6. 运行边界和清理

- 操作前确认 `/mnt/NAS02-Code` 仍由 NAS02 NFS 挂载；未挂载时不执行 `activate`、`rollback` 或发布目录清理。
- NAS 交换区是生产代码依赖路径。NAS 短暂不可用时不要通过手工改 systemd 路径解决；先恢复挂载，再按切换脚本的健康检查和事务记录处理。
- 2026-09-18 建立副本时未执行生产 `prepare`、`activate`、`rollback`，也没有修改生产认证和会话状态；后续各次激活以对应的 prepare 交接文档为准。
- 删除发布目录前，先用 `status`、systemd drop-in 和切换事务确认它不是 active、previous 或待回退版本。
