## 0.2.1 实施设计

复用现有 pending request 状态与卡片，通过公共提问适配器区分 isBlocking=false；旧请求缺省保持阻塞语义。所有答案在问题卡片提交，绑定 request/question/item/turn，删除普通输入猜答案路径。结构化 agentMessage 保留 questions/delivery，实时和持久数据共用归一化，验证真实协议的回答方式后接入。审批优先显示，异步问题不遮挡审批或关闭普通输入；默认选项不自动提交。认证恢复使用原生通知与有界状态，不承诺登录一定成功。

API 入口使用独立蓝色图标；创建/轮换 key 弹窗名称和持续时间分行，空白表示无限，正整数为天数，提交时转换为明确到期时间，拒绝无效数字。使用 AppDialog 和全局主题 token，让 Teleport 后布局仍生效。保留旧 key 轮换 24 小时过渡规则。

## 新增 UI 修复：全局显示时区

用户追加要求：在侧边栏设置中指定全局显示时区，避免每个位置重复说明。纳入 0.2.8 的全局 UI 范围：复用统一时间格式化入口，设置保存后立即生效并跨刷新保持；去除列表、运行状态等表面的重复“显示时区”文字。当前定位到 AutomationsPanel、AutomationRunHistory、AutomationRunList、ThreadConversation、ThreadComposer，实施时继续核对全局日期显示与设置入口。

显示时区与定时任务的调度时区是不同设置；本次只统一显示偏好，任务执行规则保持原语义。验收覆盖浅深主题、不同 IANA 时区、跨日时间、刷新恢复，以及页面是否仍有冗余时区说明。此项尚未实现，不计入 0.2.1 已交付范围。
