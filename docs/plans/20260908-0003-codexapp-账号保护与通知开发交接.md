# 最终功能与语义

## 账号卡与重置

周额度在全局时区的今天/明天/后天重置时显示对应日期，否则显示周几；不显示月日。5h行对应日期对齐。当前账号描边、两行限额、用量分档颜色、独立可见刷新时间沿用前批成果。已用部分为斜线纹理，不与背景混同。

重置机会按到期时间升序显示，最多3个图标，超出显示“+N次重置”；悬停查看到期时间。未知明细不可操作，过期机会不算可用。点击后AppDialog二次确认，取消不请求消费。消费使用CLI的`account/rateLimitResetCredit/consume`，含指定creditId和稳定幂等ID；随后全量读取更新次数。重试同一确认保持同一幂等ID。不确定结果需先刷新核对，不能通过另一机会盲目重试。

手动额度刷新会更新可用的上游planType，后台全量快照也更新等级；非活跃账号5分钟兜底读取身份及额度。未执行真实重置消费。

## 账号共享预留与任务调度

保护百分比属于账号；Key只有固定/全局账号选择及受保护开关。**跟随全局账号的Key也可受保护**，旧限制已撤销。多个受保护Key和自动化共享同一账号预留，不累加。普通请求在周剩余≤P或5h剩余≤min(100,2P)时拒绝；受保护任务可进入预留区。未知额度时普通流量保守拒绝。

API按账号隔离代理实例，固定账号实例最多8个，闲置淘汰。HTTP在准备前后检查，WS在握手及后续帧检查；Key策略变更会断开旧连接。观察到额度触及预留时，终止非保护API连接及原生运行回合，不仅检查新请求。

自动化编辑器可选账号和受保护。原生执行采用单任务账号租用：等待活动回合、队列和后台终端结束，在安全边界初始化任务账号；忙时任务排队，UI先响应。外部token登录仅作用于当前子进程，不切换全局auth.json。任务结束后恢复常规执行通道。API各账号实例可独立并行；没有引入另一套通用中间池。自定义provider的普通任务保持既有provider路径。

保护是本应用的准入与观察后中止机制，不能撤销已经发送给上游的消耗。上游通知/读取存在延迟，观察前可能越过阈值；不承诺精确硬配额。独立CLI、其他应用及生产5900不受59001策略控制。

## 线程额度恢复续跑

线程菜单可切换循环播放图标标记，与目标图标共存，刷新后保留，可取消。遇到额度或保护中断后等待激活账号各窗口可用且超过预留，再通过原有消息投递账本继续一次。正在执行、排队或用户已继续完成的工作不会重复续跑。

状态持久化为armed/waiting/submitted/unknown；提交意图先落盘，重启遇到不确定结果不自动重放。明确未发送的本地额度拒绝可回到等待。取消标记同时取消尚未发送的自动继续消息；已经运行的回合须用停止按钮中止。

## POST恢复通知

设置提供URL、多行JSON请求体和全局时区免打扰。例：`{"channel":"固定外围配置","message":"{{message}}"}`。请求体可替换`{{message}}`和`{{account_id}}`；按JSON字符串值替换，消息中的引号和换行不能注入外围字段。Content-Type为application/json。

账号分别配置5h/周通知开关和消息模板。模板支持`{{account}}`、`{{account_id}}`、`{{window}}`、`{{remaining}}`、`{{reset_at}}`。首次观察只建基线；同窗口resetAt推进且已用比例下降才判定恢复。免打扰跨午夜有效，结束后发送暂存消息。

队列最多256条、保留7天，单次最多16条串行POST，每条超时10秒。发送前持久移出队列，不确定结果不重试，因此可能漏发但避免重启重复。默认关闭，未向真实外部服务发送测试通知。

# 实时额度实现与官方依据

核对官方资料：

- [App-server文档](https://learn.chatgpt.com/docs/app-server)：`account/rateLimits/updated`是滚动稀疏通知；缺失/null字段不能清空旧窗口。重置机会由全量快照提供。
- [官方终端分档策略](https://github.com/openai/codex/blob/main/codex-rs/tui/src/chatwidget/rate_limits.rs)：2026-09-08检索版本第190–215行确认75/90/99阈值以及60/30/15/5秒。
- [官方终端刷新协调](https://github.com/openai/codex/blob/main/codex-rs/tui/src/app/rate_limit_refresh.rs)：账号generation、单飞、完成后安排下一轮。研究快照保存在`output/account-features/upstream-*.rs`。

本应用优先处理原生通知，保留未推送窗口/重置机会，并立即经`codexapp/accountQuota/updated`通知账号卡；前端不因每次推送额外GET。较晚返回的旧全量响应不会覆盖新通知。完整读取`account/rateLimits/read`负责兜底和重置机会刷新。

当前账号及运行中账号取5h/周最大已用比例：<75%为60秒、≥75%为30秒、≥90%为15秒、≥99%为5秒；非活跃账号5分钟。后台每5秒检查到期时间，不代表每5秒调用上游；队列串行，网络耗时可延长名义间隔。以完整读取的验证时间计时，滚动通知不会无限推迟全量读取。

启动、重新登录和恢复连接立即读。当前原生账号复用已初始化的app-server；并发读取合并，2秒短缓存避免启动重复请求，收到通知立即失效。单次等待25秒但不取消共享请求，不叠加无限未完成调用。其他账号通过短生命周期隔离app-server探针读取，未实现长期探针池。

429保留RPC错误data，优先解析Retry-After秒数/HTTP日期；未提供则指数退避，上限5分钟。较旧成功不能清除较新失败的退避状态。退避中手动/后台读取不继续请求。未直接高频调用内部wham usage接口。
