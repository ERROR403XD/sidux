## 2. dev.6 改动内容（三项，均按任务单提交）

### 2.1 API key 账号下拉框固定宽度溢出（`f4487eb`）

- 现象：账号下拉框在一定窗口宽度范围内固定 260px，特定宽度（约 806px）下溢出行容器。
- 根因：`src/style.css` 的 `.api-proxy-inline-policy .app-select.api-proxy-key-account` 带 `min-width: 260px` 硬下限；key 行双列网格的左列被右列操作区（或更宽的按钮文案、或容器查询不生效的环境）压到 260px 以下时，下拉框钉在 260px 溢出。Playwright 强制双列复现：溢出最高 260px。
- 修复：`min-width: min(260px, 100%)`——有空间时保持 260px 稳定宽度（原设计意图），不足时随列收缩。
- 验证：中英文、375–1280 全宽度、菜单展开态、明暗主题、强制双列模拟，均无溢出；806px 明暗截图 `output/playwright/dev6-select-fixed-806-*.png`。

### 2.2 等待区消息自动发送后残留（`2ac626f`）

- 根因：`codexapp/queue/changed` 推送不带令牌且断线不重放；SSE/WS 重连的 `ready` 分支不刷新队列状态，浏览器离开期间发生的自动发送无法反映到页面，残留排队行点击「删除」命中服务端 409（`该消息已发送或已移除`）。
- 修复：客户端 `ready`（重）连接分支补 `refreshQueueState()`（`useDesktopState.ts`）；服务端 `BackendQueueProcessor.mutate` 对已结算行的 `remove`/`abandon` 改为幂等成功（返回最新状态 + `delivered` 回执），其余操作维持报错；`reconcile`/`steer` 行为不变。
- 验证：两个新回归测试（ready 重同步；排空后幂等删除）+ 全量单测；行为手册见 `tests/chat-composer-rendering/persisted-idle-queue-recovery.md` dev.6 节。

### 2.3 自定义连接推理强度（`404b91c`，后改为全自动逐档探测）

- 背景：自定义连接的模型目录通常不带 `supportedReasoningEfforts`，`efforts` 恒为空 → 选择器 N/A、请求链路剥离 reasoning 参数；DeepSeek 等 OpenAI 兼容上游实际支持 `reasoning_effort`。
- 行为（应用户要求从手动声明改为全自动）：连接测试时在解析出的 wire 上对 5 个档位逐一发 16-token 探针；档位被上游点名拒绝即从选择器剔除，静默忽略与无关失败一律保留（创建即默认全支持）。表单无任何推理强度控件；结果只在重新测试连接时刷新，免复测保存保留原判定。探测结果写入 `reasoningEfforts`，读取时合并进模型能力，下游链路（选择器、turn/start、运行时/API 出口 sanitize、协议桥互转）全部复用既有逻辑。
- 演进记录：初版为「手动勾选声明 + 整体拒绝兜底」（`reasoningEffortSupport` 三态），按用户要求移除手动声明与三态字段，改为逐档探测自动结果；`reasoningEfforts` 字段名保持不变，旧状态文件规范化加载，无迁移负担。
- 验证：store 测试覆盖值级拒绝（仅 xhigh 剔除）、全接受、不确定保留、免复测保留；HTTP 透传集成测试（有档位透传 reasoning、无档位剥离）；Playwright 三条上游（全接受/全拒绝/仅 xhigh）9/9 断言，含模型/协议转换各占一半与 375 无溢出。

### 2.4 附件-only 新会话标题与侧栏可见性（bug 修复）

- 根因（实验证实）：Codex app-server 的 `thread/list` 会剔除 `first_user_message` 为空的线程；纯附件发送（无文字）的回合文本为空 → 线程不被列出（刷新/重载后侧栏不可见），且客户端 `requestThreadTitleGeneration` 对空 prompt 直接跳过 → 标题缓存也永远不会生成。文件附件发送虽非空，但标题是 `# Files mentioned by the user:` 脚手架首行，无辨识度。
- 修复：发送链路对附件-only 回合合成非空占位文本（`[Image]` / `[Attachment]`，与既有文件脚手架同存，模型可见但语义中性，队列路径同样处理）；客户端在空 prompt 时用附件派生标题（`[Image]` / 首个文件名 / 组合）写入标题缓存并 `persistThreadTitle` 持久化，刷新与重载后保持。
- 验证：gateway 层 3 条占位断言（本地图/文件/远程图）、useDesktopState 层乐观标题与持久化断言；手册 `tests/chat-composer-rendering/attachment-only-new-thread-title-and-sidebar-visibility.md`。
