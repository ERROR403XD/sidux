# codexapp 0.2.20-dev.4 协议转换开关、黄色能力tag与API代理通知

## 范围与边界

- **OpenAI 账号反代（CLI Proxy API，`resources/api-proxy`）完全不触碰**：其 key 路由、受保护语义、WebSocket 适配保持原样；本版所有改动只作用于自定义连接与前端面板。
- 协议桥从「chat 连接自动启用」改为**按连接 opt-in**：账号设置弹窗中的「协议转换」开关（AppSwitch），仅对缺少 chat 或 responses 端点的连接显示。

## 交付内容

### 协议转换开关

- `CustomConnection.protocolBridge: boolean`（存量配置迁移默认 false）；`CustomConnectionDraft` 增加同名可选字段。
- `customConnectionStore.save()`：`protocolBridge` 不参与测试 digest；**凭据未变时仅切换开关可免重测保存**（revision+1、runtimeToken 轮换）；带合法 proof 的保存照旧走探测路径；关闭活跃连接的桥会自动取消激活（对齐旧版「保存为 chat 取消激活」语义）。
- 门控：`select()`/`customRuntimeConfig()`/运行时路由/自动化准入对「chat 且未开桥」给出可行动错误「该连接仅支持 Chat Completions，可在账号设置中开启协议转换」。

### 反方向转换接入（responses-only + 桥）

- glue 新增 `handleChatViaProtocolBridge`：Chat 请求 → `chatRequestToResponsesRequest` → 上游 `/responses` → `ResponsesToChatStreamTranslator` 还原 chat 流（含 `[DONE]`、usage 尾块）；非流式上游经 `responsesResponseToChatResponse` 直接回 JSON。
- `forwardCustomConnection`：responses 连接开桥后 `/v1/chat/completions` 走反桥；chat 连接的 chat 直通保持不变。

### 黄色能力 tag

- `customConnectionEndpoints/NativeEndpoints/BridgedEndpoints` 三助手：native（探测确认）、bridged（桥转换成立）、unsupported。
- `ConnectionEndpoints.vue` 接收 `endpoints` + `bridged`，新增 `is-bridged` 黄色态（浅色 #fefce8/#854d0e，深色 #33270a/#fde68a，style.css 决定性覆盖）。
- 连接卡片与 API 代理面板（key 行、创建/账号弹窗）统一使用该组件；gateway `/status` 账号行新增 `bridgedEndpoints`。
