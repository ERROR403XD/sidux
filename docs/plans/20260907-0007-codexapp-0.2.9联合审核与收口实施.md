# CodexApp 0.2.9 联合审核与收口实施

## 基线与授权

按 0028 连续开发授权，在已验收 0.2.8 / 9a7bd98 上收口。59001 当前为 0.2.8 镜像 67313902090f，生产 5900 仍为 0.2.0 / PID 3456650。仅本地分支和候选，不推送/合并、不 prepare/activate、不改 5173 或生产认证。

## 审核和修复顺序

1. 审查 0.2.0 以来真实源码变化及其测试：问题/审批、历史分页/搜索、发送/队列、Goal/压缩、子任务/引用、扩展目录、Hooks/后台终端、时区/输入/复制；把现有证据与新联合回归分开记录。
2. 先修复已复现的开发重启问题。已检查本机 Vite restartServer：先构造新服务器，再关闭旧服务器；两份 middleware 复用共享运行态，旧 close 无条件 dispose 使新发送服务失效。用明确的持有计数与幂等释放保护共享运行态，旧实例释放自己的订阅，最后持有者才关闭；新代初始化等待旧代写入租约释放。验证实际配置重启后队列、调度器和通知可用，不通过定时睡眠猜测完成。
3. 合并同时发生的 /prompts 读取，不缓存已完成响应；创建/删除成功使在途读取失效，调用方防止迟到结果覆盖。保持按需更新与账号边界，不增加轮询。
4. 候选空闲检查补入原生已加载会话的后台终端；按能力探测，仅做有界元数据读取，遇到未知/失败不冒充空闲，发现后台任务就阻止替换。保留旧 CLI 的明确能力边界；不自动停止任何进程。
5. 针对审核发现修正实质问题，收敛冗余说明和无效控件/代码，不做大范围风格改写。同步完整使用说明和最终开发报告；实验能力与实测限制清楚说明。

## 联合验收

运行相关和全量单测、类型/构建、CJS/native PTY、最终 59001 产物一致性；真实页面性能与长会话/请求数/流式渲染、各主题与响应式组合；复用前版交互脚本进行跨功能回归。真实打包升级/回退、认证失败刷新及 API key 蓝色入口和持续时间布局重新核对。跨账号使用隔离假凭据做边界检查，不冒充真实第二账号成功登录；物理手机、自然令牌到期、外部 OAuth 等不具备条件的项目单列限制。

最终保留 0.2.8 回退镜像与原独立卷，交付准确候选版本、命令、报告和已验证/待实测范围。可选清理只涉及明确小于 0.1.90 的无引用候选，不删除认证、会话、卷、已验收回退或共用原生依赖基础镜像。
