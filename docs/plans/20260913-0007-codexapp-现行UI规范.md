# CodexApp 现行 UI 规范

适用于 0.2.19 的长期维护。0.3 两份 UI 设计稿是下一阶段设计材料，不覆盖这里记录的现行交互。新增控件遵守本规范，已有控件只在触及对应需求时整理。

## 1. 信息与文案

操作入口轻，状态准确。普通保存只显示“已保存”，不强调本机、不增加流程；草稿保存、投递提交、模型处理和任务完成各自表达，不借相同成功提示合并含义。

| 用语 | 约定 |
| --- | --- |
| 会话 / conversation | 用户可见的对话单位；代码与协议 thread 保持原标识 |
| 回合 / turn | 一次输入及对应原生执行结果 |
| 额度 / quota | 用量窗口与可用额度；恢复时点用“额度重置 / quota reset” |
| 推理强度 / reasoning effort | 不混写成模型速度或计算预算 |
| 无匹配命令 | 命令搜索的空结果；保留用户已输入内容 |
| 项目 | 有目录和仅名称项目均使用普通项目待遇，不加“虚拟”等解释标签 |

已经去除：设置与账号弹出区重复的无账号提示、无账号时的当前模型/保存偏好差异说明、关于页工作树、正常自动化调度器“运行中”。真实故障、初始化和交接状态仍可见。审核 CSV 的明确意见是本轮文案依据；不能替换用户内容、协议错误码或模板变量。

## 2. 公共组件与主题

| 场景 | 组件/约束 |
| --- | --- |
| 模态对话框 | `AppDialog.vue`；默认最大 760px，compact 460px，窄屏有边距 |
| 锚定浮层 | `AppPopover.vue`；复用视口定位、滚动/尺寸更新和生命周期 |
| 普通单选 | `AppSelect.vue`；不用原生 select 实现账号、模型、语言等应用菜单 |
| 描边操作 | `AppButton.vue`；危险操作使用 variant=danger |
| 开关 | 现有公共 Switch；标签和控件有独立可点击/可读空间 |
| 时间 | `AppTimeInput.vue` 原生 type=time，保留时钟入口；这是时间控件，不是原生下拉菜单例外扩张 |
| 兼容层 | ComposerDropdown 只包装公共单选；不维护另一套定位/主题实现 |

共享颜色、圆角、focus 和层级使用 `src/style.css` 的 `--ui-*` tokens。业务布局留在业务组件；共享页面和大功能区的关键深色覆盖放在 style.css，不能仅依赖 scoped 内的全局选择器。浅深主题均检查字段、菜单、错误、禁用和空状态，深色页不能出现意外白面。

公共组件使用 typed props/emits/slots，不拥有 RPC、账号状态、存储或保存规则。不要为一个表单建立通用 schema 框架，也不要复制弹窗焦点管理或 window 监听。

## 3. 页面与响应式

现有页面组织仍是侧栏项目/会话 + 主内容区，设置、自动化、API 出口和扩展通过既有入口进入。紧凑列表显示必要摘要，长文本详情按需展开。只读正常状态不应挤占主要操作。

自动化页面随窗口收窄仍保留两侧至少 12px 距离；表单、详情和列表内部可收缩，工具栏按钮保持完整可点击。AppDialog 手机边缘至少 8px，长正文内部滚动，标题/底部动作稳定。中英文都允许合理换行，不以中文短标签宽度锁死整行。

输入框扩大后，占据当前会话内容区、避开标题与操作区。窗口宽高改变、切换横竖向和收起再展开都重新计算位置。桌面缩小窗口不得被当作软键盘；触屏键盘场景保留可操作输入和发送控件。尺寸改变保留文字及选区。

## 4. 输入、命令与引导

### 命令搜索

- 必须从**空草稿**新输入 `/` 才开启。正文、空格、换行已存在时输入 `/` 不开启；把光标移回开头也不重新激活。
- 开启后继续输入命令查询；Esc 关闭。粘贴、恢复草稿或程序填入 `/plan` 不算新按下 `/`。
- 草稿中一旦出现命令以外的正文，菜单关闭；匹配不能只看光标前缀而忽略后文。
- 普通输入框沿用锚点上下布局；扩大时菜单水平居中，位于输入区中部略靠下，避开第一行输入，并受视口限制。
- 使用有限可见行、键盘选择和活动项滚动；resize/scroll/Observer 测量合并到 RAF，关闭后释放所有监听与待执行测量。

### 保存与发送

草稿沿用现有保存触发，不为显示“已保存”新增写入或请求。保存失败保留内容及复制入口；附件引用和二进制能力按既有规则，不把复制正文当作完整附件备份。

引导提交后，正文立即显示该内容及真实状态：提交中、等待引导、引导中、待确认、发送前失败等。切换会话、刷新、队列/历史读取失败不能仅因暂时缺少原生回显就抹掉已确认存在的显示记录。按原生 ID 或确认的回合/序号合并，不能仅凭文字相同去重。成功/失败回来后更新并重排；显示不制造第二次发送。持久存储写满时可用标签页显示缓存降级，不将 ACK 改成失败；标签页关闭或两种存储均不可写不在刷新恢复保证内。

## 5. 侧栏、项目和圆点

有目录项目用文件夹开/关图标；仅名称项目使用同尺寸的抽象组织层级开/关图标，仍拥有普通项目的操作和样式。不要加入额外风险说明、虚拟目录标签、特殊横幅或劝导文本。实际目录相关操作基于会话真实目录，不造出一个文件夹身份。移除组织不连带删除自动化；自动化页仍可管理原任务，已移除组织的目标显示“—”，不暴露内部 virtual ID 或额外增加解释横幅。

| 状态 | 视觉/行为 |
| --- | --- |
| 正在运行/审批 | 保留现有优先级和图标，不由下面的圆点覆盖运行门禁 |
| 已完成未读 | 蓝点，阅读后清除 |
| 未忽略的非手动普通异常 | 红点；阅读、刷新、后续成功均不清除 |
| 未忽略的额度异常 | 黄点；存在多类问题时黄点优先；阅读不清除 |
| 手动停止 | 不凭手动停止新增红黄问题；活跃筛选期间仍暂留 |

三种圆点沿用同样的小圆形尺寸（约 6.67px），不改成长标签或警告图标。错误正文提供“忽略/已忽略”，会话菜单提供“忽略全部问题”。忽略按当时已有回合问题生效且可撤销，保存失败不能先移除圆点；新发生的问题不受旧忽略操作影响。忽略已得到成功响应时立即释放对应控件，独立刷新摘要；读取或写入超时不无限锁住后续操作，也不能把未确认写入显示成成功。

“活跃”是一次开启周期：先纳入当前活跃项，期间看见的活跃会话结束或停止后暂留，查看并切到其他会话后再移除。关闭再开启或刷新重新以当前活跃计算，旧蓝点/红黄点不会单独纳入。阅读、问题忽略和筛选暂留是三个独立维度；“中断”筛选响应未忽略的异常，不修改服务端任务状态。

## 6. 时间控件与自动化

各处统一带时钟的单一时间控件，不再使用两个数字框和独立冒号。浏览器显示格式可能随地区变化，保存格式统一 HH:mm。粘贴支持中文冒号、英文冒号和全角数字归一化；非法值提示并保留已有有效值，不能自动改成 00:00。

免打扰时间框当前 96px，每日激活约 104px；免打扰标签与 toggle 间距 12px，开关与时间组间距 20px，窄屏自然换行。不能让标签、开关和时间控件互相挤压。

自动化“每天运行”和账号“每日激活”均可添加/移除多个时间。自动化最多 24 个，每次保存排序去重，拒绝空/非法/超限；高级日历规则不能被简单编辑器悄悄丢弃约束。详情显示真实选择的时间，列表不堆叠重复解释。

## 7. 反馈、可关闭提示与可访问性

功能性临时错误复用 × 关闭，只关闭本次提示；再次发生仍能显示。关闭不等于忽略持久回合错误、不等于确认审批，也不取消后台任务。需要用户决策的内容保留原操作入口。

反馈报告由用户预览、编辑、复制或自行分享；不自动采集会话正文、路径、账号、凭据或原始上游响应。正常轻操作反馈不遮住标题和当前输入。

图标按钮具备 aria-label，开关有标签，每个时间项可以区分。Tab 焦点在模态范围内，关闭返回触发器；Esc 按当前最上层处理。背景关闭只接受完整背景点击，拖选文字后拖到背景、右键不误关。状态不能只依赖颜色表达，问题正文和操作仍可访问。

## 8. PWA 与验收

静态和动态 manifest 均声明 `launch_handler.client_mode=focus-existing`，支持该能力的浏览器再次启动时聚焦已有 PWA 上下文，无上下文才新建。应用不增加心跳、跨窗口选主或抢焦点脚本。操作系统快捷方式与浏览器支持决定实际效果，本轮按用户要求只做 manifest/HTTP 轻量验证。[浏览器能力定义](https://developer.chrome.com/docs/web-platform/launch-handler/)。

改 UI 要看真实改动页面，至少浅深主题、1440×1000、768×1024、375×812；窗口 resize 追加窄高与短高变化，不能只各截一次静态图。验证键盘、焦点、菜单边界、刷新恢复、保存失败和实际请求次数。截图等待 2–3 秒，报告保存 URL、视口、断言、绝对路径和内联图。故障注入采用 Playwright CJS；模拟接口与真实运行时证据分别列明。

## 封版漏项补查（2026-09-13）

项目的闭合图标与实际内容区必须同步。空项目折叠时隐藏整条空状态行，只保留项目标题；展开时才显示“没有会话”。验收不能仅断言图标，须检查可见行、实际高度与刷新恢复，普通目录/组织项目采用同一规则。 详见 [[20260913-0012-codexapp-封版漏项补查与0.2.19交接]]。
