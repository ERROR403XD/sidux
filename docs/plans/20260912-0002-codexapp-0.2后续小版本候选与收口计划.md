# CodexApp 0.2 后续小版本候选与收口计划

0.2.17 之后建议用 **1—3 个小版本**完成反馈收集与体验收口。优先修复真实复现的问题，每版只加入少数可以独立验收、低耦合的小功能。到期允许未选需求进入 0.3 候选，不以清空此清单作为结束条件。

本文把新增候选、已有功能、代码查证项和回归观察项分别说明，方便后续直接挑选。编号用于跟踪讨论，不表示已决定实施。配套的 [0.3 开发展望与方向选择](20260912-0001-codexapp-0.3开发展望与方向选择.md)负责较大方向与架构取舍。

## 2026-09-12 实施更新

R01、R02 已在 0.2.18 修复，S05 按用户意见采用轻量“已保存”；新增 S13：会话中功能性错误提示提供 × 关闭。候选已运行在 59001，未发布或切换生产。详细范围、边界与测试见 [0.2.18 修复与开发验收](20260912-0003-codexapp-0.2.18修复与59001开发验收.md)。以下未选中条目继续作为候选，原始查证段落保留用于说明问题来源。

小版本候选应满足：

1. 一个清楚的用户操作问题，能够在现有页面或组件中解决。
2. 复用现有数据和业务动作，最多增加少量可回退的偏好/元数据。
3. 不以引入新运行时、通用任务模型、全局事件仓库、数据库迁移或新调度语义为前提。
4. 有准确的预期结果，失败时能回退对应改动，不覆盖会话、认证或其他用户数据。
5. 性能影响能通过请求数、数据量、代码路径或实际 profile 说明。

规模定义：S 为局部 UI/文案/偏好，M 为现有多个模块联动，L 为新持久化语义或新的运行链路。0.2 主要选 S，每版最多考虑一个边界明确的 M；拆完仍是 L 的需求进入 0.3。规模不是天数承诺。

## 3. 两个优先核对的现有问题

### R01 反馈入口与当前维护渠道、采集范围不一致

**已查证事实**：`src/composables/useFeedbackDiagnostics.ts` 保留固定的上游邮件收件人；`buildFeedbackMailto()` 构造内容时包含页面可见文字、当前 URL、浏览器存储摘要与诊断。`src/App.vue` 在错误位置使用该反馈入口。生成 mailto 不等于已发送邮件，本次没有打开或发送。

这会影响 0.2 收集反馈：用户可能把问题发到旧维护渠道，且错误页可能同时显示私人会话内容。它是具体的数据流与渠道问题，不需要因此建设完整诊断平台。

建议把它收敛为候选 S01：本地生成、预览和复制最小问题报告，并由用户自行决定是否提交到当前项目。待浏览器复现后确定修改范围。

### R02 自动化额度错误提示与 README 的边界不一致

**已查证事实**：`src/server/automationEngine.ts` 的 `automationError()` 在额度/429 分类下含“可改选账号后重试”的建议；当前 README 明确不允许通过切换等方式绕过额度与速率限制。

建议只修正此类错误文案及相关翻译为“查看实际额度和恢复时间；恢复后再试”，保留失败状态与现有错误码，不改变执行路由、不触发自动重试。需要检查同义文案的实际使用位置和测试，不能全局替换用户内容或把“连接故障”和“额度耗尽”混为一类。规模 S。

**验收**：合成额度耗尽/429 场景显示可理解的等待/核对建议；认证失败仍引导处理认证；不额外发送请求、不切换账号。这里确认的是代码文案不一致，本次没有用真实账号制造限流。

### 4.1 S01：用于反馈收集的最小问题报告

默认采集结构化允许字段；不收集完整页面文字、localStorage/sessionStorage 内容、提示词、回复、文件正文、凭据或带查询参数的 URL。若用户选择加入一段错误文字，先展示内容供检查。截屏由用户选择，不能因为开始生成报告就自动上传。

用户填写“操作步骤、预期结果、实际结果”，生成 Markdown 或复制到剪贴板。链接打开当前项目的反馈渠道，但提交由用户完成。当前内存诊断已有数量上限，应复用；不增加常驻全量请求日志。

**验收**：在合成会话正文、模拟敏感存储和带参数 URL 的页面生成报告，默认输出不包含这些值；确实包含版本与重现条件。复制/下载有明确成功或失败状态；生成时网络发送次数为零；不会自动打开旧收件人。

**回退**：移除新报告 UI 或对应能力开关，保留已有错误显示；如旧邮件入口已确认不适用，不应为了回退新功能重新恢复该旧目标。

### 4.2 S02/S03：检索与快捷入口的范围

S02 只查设置定义及可见标签，用已有表单分区定位。它不更改设置值、不自动展开凭据内容，搜索结果应支持中英文关键词。若保存动作仍在进行，定位不得卸载表单丢失状态。

S03 优先复用现有斜杠命令与导航动作，第一版只做跳转和打开面板。现有会话内命令仍保留。删除项目、切换实际执行账号、停止进程等操作沿用原入口与确认语义，不在快捷结果里直接执行。

**验收**：键盘、鼠标与触摸可进入同一个目标；Esc/焦点符合共享浮层约定；中文输入法组合输入不触发动作；输入草稿不变。基于本地数组检索时网络请求为零，远端正文搜索不混入此版本。

S02 与 S03 不必一起做。若用户主要通过手机使用，先选设置定位和侧栏体验；若没有实际检索困难，两项都可不进入 0.2。

### 4.3 S04/S05：列表筛选与草稿信心

S04 的第一版只提供“全部/运行中/未查看完成”等已经有可靠数据源的条件。筛选只影响展示，不批量改状态。未完整加载列表时说明范围；不能把“未加载”误算成不存在。更复杂的跨对象保存视图留给 0.3。

**验收**：切换筛选不触发逐会话正文读取，不清除蓝点，不把选中会话误归档；运行状态到达后正确更新。当前打开会话不满足筛选时，正文仍可继续工作。

S05 已按用户反馈在 0.2.18 实现：正常只显示轻量“已保存”，不强调“本机”。复用现有草稿持久化结果，写入失败不能显示成功；不额外增加保存动作。技术上仍是当前浏览器草稿，不新增跨设备同步。

**验收**：切换会话、刷新恢复、存储失败、附加文件引用失效均有明确结果；不会把 A 会话草稿写进 B 会话，不会自动发送。默认常规保存可用轻提示，只有失败时持续提示。

### 4.4 S06/S07：自动化配置效率

S06 复制标题、提示词、调度、目录和配置选项，但不复制运行历史、回执 ID、租约或认证内容。源账号/连接已移除、模型不可用时需要重新选择；新草稿和新定义默认暂停，取消窗口不创建任何任务。

**验收**：复制并取消后定义数量不变；保存产生新 ID；没有实际执行；源定义不变；页面刷新后仍是暂停；重新打开能看到保存的配置。配置变化走既有验证路径。

S07 已有下次时间，应只补“接下来三次 + 时区”的按需详情。若需要另造一套调度解析器或依赖，延期。它显示计划触发点，不承诺忙碌、暂停、离线或失败时一定在该时间执行。

**验收**：同一规则的预览与调度器一致；跨日、暂停、无效规则及适用时区的夏令时场景正确；改变显示时区不修改实际 schedule；展开预览不启动任务。

### 4.5 S08—S12：按真实缺口补细节

这组不适合一次全站改造。每个问题保留准确页面、元素、设备和步骤，再修对应组件。

| 候选 | 关键验收 | 0.2 的停止边界 |
| --- | --- | --- |
| S08 长文本 | 手机不依赖 hover 才能看全；复制值与原值一致；长名称不挤掉主要动作 | 不为了 tooltip 重写全站布局 |
| S09 连接说明 | 使用既有同步时间；断线时草稿保留；重连后核对状态，不自动重发未知投递 | 若需跨端新同步协议，转入 0.3 C |
| S10 扩展说明 | 展示真实检查结果和时间；授权、重载、不可用区分；重复点击共用在途请求 | 不新建扩展调用统计平台，不后台遍历全部 MCP 工具 |
| S11 附件反馈 | 上传失败、取消、移除和重复文件有准确状态；独立发送图片不误去重 | 不扩展成多模态编辑器或持久成果系统 |
| S12 目录提示 | 提示与实际 cwd 一致；项目外可正常开始；附加目录不暗示挂载/强制权限 | 不顺带迁移项目存储或建设多根工作区 |

每项的清理方式是恢复本次局部 UI/偏好变更；如涉及保存数据，仅迁移本功能新加字段，不清空原项目/会话状态。

## 6. 1—3 个小版本如何分配

### 6.1 推荐的三段式上限

| 迭代 | 核心目标 | 可选范围 | 不应带入 |
| --- | --- | --- | --- |
| 第一版，暂称 0.2.18 | 把反馈收得准、修最影响使用的问题 | R01/S01、R02，若干已复现 UI bug；容量有余才加一个 S 级体验项 | 全局新导航、数据迁移、自动化新执行逻辑 |
| 第二版，暂称 0.2.19 | 根据反馈改善高频操作 | S02/S04/S05/S08/S11 中挑 2—3 项；S03 或 S06 如进入则占本版主要功能额度 | 同时改聊天同步、账号链路与自动化执行 |
| 第三版，暂称 0.2.20 | 冻结 0.2，形成 0.3 的证据 | 剩余明确回归、必要的小修、兼容/使用说明、方向样本总结 | 为凑第三版加入新功能；继续延长愿望清单 |

第一版若需要 M 级 S01，先围绕它与 R02、相关修复收口；不是要求把所有“优先”项塞进同一版。UI 问题按影响排序，存在阻断使用的问题时可以替换任何可选功能。

### 6.2 只做一版或两版也可以

- **只做一版**：处理 R01/R02、实际阻断与高频 UI 问题，补一个最有价值的小功能，冻结基线并进入 0.3 方向验证。
- **做两版**：第一版完成收集反馈的必要改进，第二版消化反馈并完成冻结。
- **做三版**：只有仍有值得独立发布的真实修复时才需要第三版；不为了版本数量刻意拆分。

每次立项确定本版清单后，新建议默认进入下一版或 0.3，除非属于本版改动引入的回归。最终选择以用户反馈和剩余风险为准。

## 8. 验证、性能与发布边界

### 8.1 按改动类型验证

| 改动类型 | 所需验证 |
| --- | --- |
| 文案/纯样式 | 核对实际页面、中英文与浅深色；必要的类型/构建检查；说明不增加请求/监听 |
| 筛选/快捷入口 | 键盘、触摸、焦点、IME、正确目标；基于本地列表的筛选不应增加 API 请求 |
| 草稿/偏好持久化 | 保存失败、刷新恢复、切换对象、跨标签页语义；只验证实际支持的同步范围 |
| 自动化复制/时间预览 | 新 ID、默认暂停、零误运行；复用调度结果；合成配置验证，不启用真实业务自动化 |
| 连接/诊断 | 合成断网、失败及敏感内容；请求合并、恢复去重、诊断预览范围 |
| 解析/文件链接变动 | 依仓库规则执行 TestChat，核对 `hrefOk`、`titleOk`、`textOk` |
| 包/启动/模块加载 | 依仓库规则构建后执行公开 CJS 入口与必要的 PTY/安装验证 |
| Provider/认证链路 | 触发项目专门隔离测试流程；不要为了 UI 提示顺带重构该链路 |

有 UI 改动时检查 375×812、768×1024 及桌面尺寸，保存真实改动页面的浅深色截图。只有需要请求拦截、存储或页面状态注入等情况才选择合适的 Playwright 路径，按仓库规则使用已核对 cwd 的验证服务。

### 8.2 每个功能的性能预算

- 本地筛选、设置检索与快捷导航：默认新增后台 API 请求数为 0；不要为了导航读取所有会话正文。
- 新增状态提示：复用已有状态和事件，不另开固定周期的全站轮询。
- 草稿反馈：沿用现有节流/保存链，不增加每键一次写入；存储失败不能无限重试。
- 调度时间预览：按需、有限次数；不能为每个列表行高频重算复杂规则。
- 诊断报告：保留有界记录，用户触发时生成；不采集完整媒体或无限日志。
- 数据链发生变化时，用现有 profiler 查看 `duplicateCounts`、`warnings`、`totalApiKB`、慢请求和实际页面；纯文档修改不运行性能审计。

历史 0.2.17 发布说明记录入口 JS 815.25 kB、gzip 258.55 kB 与大分块提示，不是本次测量。后续小版本如增加依赖，应重新比较实际首页加载内容；不要仅凭“功能很小”免除性能判断。

### 8.3 版本收口条件

1. 本版新增或修复的功能有准确验收结果，无已知会话丢失、重复发送、无法回答/审批等阻断缺陷。
2. 相关真实 UI 已按主题/语言/尺寸检查，历史已修项目没有被本版重新破坏。
3. 新增偏好/数据的保留和回退边界已写清；没有改变旧投递、账号或自动化定义的含义。
4. 报告区分“本次实测通过”“沿用历史证据”“尚未验证”；不把测试启动或 HTTP 200 当作功能通过。
5. 按任务独立提交，更新相关手工测试与版本说明，形成可审阅产物。

开发验收、打包、prepare 和生产切换是不同步骤。小版本沿用独立候选与状态目录、既有空闲门禁和发布流程，具体运行目标在实施时重新核对。本次文档工作不执行这些操作。

## 9. 用 0.2 反馈为 0.3 做选择

每个反馈保留以下字段，项目名、路径和内容可用用户选择的匿名标签：

| 字段 | 例子/用途 |
| --- | --- |
| 反馈 ID / 版本 | F-001、0.2.18；区分是否为本版引入 |
| 页面 / 设备 / 主题语言 | 设置页、手机、深色、中文 |
| 任务类别 | 开发、文档、维护、自动化、手机回访 |
| 最短复现步骤 | 从哪个入口开始，在哪一步出现困难 |
| 预期 / 实际 | 希望定位原会话，实际只能重新搜索 |
| 频率 / 影响 | 偶发/反复；阻断/明显变慢/轻微不便 |
| 现有替代路径 | 是否能用命令、搜索、现有面板完成；代价是多少 |
| 判定与证据 | 已复现 bug、已有能力缺少入口、候选新需求、暂不处理 |
| 可能对应的 0.3 方向 | A 阅读导航、B 交付、C 监督、D 自动化、E 知识、F 多引擎 |

优先记录实际摩擦，不要求常驻行为跟踪或上传私人会话。0.2 收口时整理约 10—15 个代表性任务，比较“会话优先”与“项目/待处理优先”的流程，再决定 0.3 主线。

## 10. 实施前的最小交接

开始某个小版本时，重新检查实际代码版本、工作树、已有修复和候选是否重复；从本文选择本版条目，补复现步骤、数据范围与验收，才进入实施。R01/R02 是当前静态查证项；其余多为候选或回归观察项。

初稿阶段只形成两份规划文档并保存参考原文；未选择最终版本范围，未开发候选，未修改测试索引、运行配置、认证、会话或发布状态。后续更新保留文件名，以新核对结果修订候选状态。
